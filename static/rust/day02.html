1. i32：赋值时 Copy

可运行示例：

fn main() {
    let x = 10;
    let y = x;

    println!("x = {}", x);
    println!("y = {}", y);
}

输出：

x = 10
y = 10

这里 let y = x; 会把 x 的值复制一份给 y。

原因是 i32 实现了 Copy。对于 i32、bool、char、浮点数等简单类型，复制成本低，Rust 允许自动复制。

关键点：

let y = x;

不是修改 x，而是用 x 初始化一个新变量 y。

2. String：赋值时 Move

错误实验：

fn main() {
    let s = String::from("hello");
    let t = s;

    println!("s = {}", s);
    println!("t = {}", t);
}

编译错误核心：

error[E0382]: borrow of moved value: `s`

move occurs because `s` has type `String`, which does not implement the `Copy` trait
value moved here
value borrowed here after move

解释：

#![allow(unused)]
fn main() {
let t = s;
}

这句会把 s 的所有权移动给 t。之后：

t 有效
s 失效

所以后面再打印 s 会报错。

可以运行的 move 版本：

fn main() {
    let s = String::from("hello");
    let t = s;

    println!("t = {}", t);
}

这里没有再使用 s，所以没有问题。

3. 为什么 String 不默认 Copy？

String 管理堆内存。可以粗略理解成：

String {
    ptr,
    len,
    capacity,
}

如果 Rust 默认复制这三个字段，就可能出现两个 String 指向同一块堆内存。离开作用域时，两者都想释放同一块内存，可能造成 double free。

Rust 的选择是：

默认 move 所有权，不默认深拷贝堆数据。

这也是 Rust 的性能哲学：

便宜的复制可以自动发生。
昂贵的复制必须显式写出来。

4. clone()：显式深拷贝

如果确实希望 s 和 t 都拥有一份字符串内容，可以使用 clone()。

可运行示例：

fn main() {
    let s = String::from("hello");
    let t = s.clone();

    println!("s = {}", s);
    println!("t = {}", t);
}

含义：

s 保留原字符串
t 得到一份新的字符串拷贝

代价：

额外分配内存
复制字符串内容

看到 .clone() 时，要逐渐养成一个习惯：

这里真的需要复制吗？能不能改成借用？

初学阶段不必害怕 clone()，但要知道它不是免费的。

5. 函数传参也可能 Move

错误实验：

fn take_ownership(s: String) {
    println!("inside function: {}", s);
}

fn main() {
    let s = String::from("hello");

    take_ownership(s);

    println!("after function: {}", s);
}

这里：

#![allow(unused)]
fn main() {
take_ownership(s);
}

会把 main 里的 s 移动到函数参数 s。

可以理解成：

main::s -> take_ownership::s

函数结束时，函数参数 s 离开作用域，字符串被释放。回到 main 后，原来的 s 已经失效。

6. 只读借用：&str

如果函数只是读字符串，不需要拿走所有权，应该使用借用。

可运行示例：

fn read_string(s: &str) {
    println!("inside function: {}", s);
}

fn main() {
    let s = String::from("hello");

    read_string(&s);

    println!("after function: {}", s);
}

输出：

inside function: hello
after function: hello

这里 read_string(&s) 只是借用 s，不拿走所有权，所以函数调用后 s 仍然可用。

为什么用 &str 而不是 &String？

&String 可以用，但 &str 更通用。

#![allow(unused)]
fn main() {
fn read_string(s: &str)
}

既可以接收：

#![allow(unused)]
fn main() {
let s = String::from("hello");
read_string(&s);
}

也可以接收：

#![allow(unused)]
fn main() {
read_string("hello");
}

所以只读字符串时，优先考虑 &str。

7. 可变借用：&mut String

如果函数要修改原字符串，需要可变借用。

可运行示例：

fn add_suffix(s: &mut String) {
    s.push_str(" world");
}

fn main() {
    let mut s = String::from("hello");

    add_suffix(&mut s);

    println!("s = {}", s);
}

输出：

s = hello world

这里有三处要对应：

#![allow(unused)]
fn main() {
let mut s = String::from("hello"); // 变量本身允许被修改
fn add_suffix(s: &mut String)       // 函数接收可变引用
add_suffix(&mut s);                 // 调用时传可变借用
}

如果变量没有声明为 mut：

#![allow(unused)]
fn main() {
let s = String::from("hello");
add_suffix(&mut s);
}

会报错，核心意思是：

cannot borrow `s` as mutable, as it is not declared as mutable

8. 可变借用是独占的

错误实验：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    println!("s = {}", s);
    println!("r = {}", r);
}

这里不允许，因为 r 是对 s 的可变借用，而且后面还要继续使用 r。

核心规则：

可变借用存在期间，不能同时通过原变量或其他引用访问同一份数据。

更口语化：

借给 r 改的时候，就别同时从 s 这边插手。
等 r 用完了，再回到 s。

可运行修复版本：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;
    r.push_str(" world");
    println!("r = {}", r);

    println!("s = {}", s);
}

这里 r 最后一次使用在：

#![allow(unused)]
fn main() {
println!("r = {}", r);
}

之后借用结束，所以可以继续使用 s。

也可以用作用域明确结束借用：

fn main() {
    let mut s = String::from("hello");

    {
        let r = &mut s;
        r.push_str(" world");
        println!("r = {}", r);
    }

    println!("s = {}", s);
}

9. 所有权地图：传值、借用、可变借用

Rust 里函数参数设计可以先用这张地图理解：

函数想做什么参数类型调用方式数据归属
拿走整数等 Copy 值i32f(x)复制一份，原值还可用
拿走堆数据Stringf(s)move 所有权，原变量失效
只读字符串&strf(&s) 或 f("hi")借用，不拿走
修改原字符串&mut Stringf(&mut s)可变借用，独占修改
只读数组/Vec 内容&[T]f(&nums)借用一段连续数据

今天先记住三个最核心的：

传 String：把所有权交出去。
传 &str：借给函数看一下。
传 &mut String：借给函数改一下。

参数选择的初步原则

如果你在写一个函数，可以先问：

1. 函数是否需要拥有这个值？
   - 需要：传 `T`，例如 `String`。
   - 不需要：传引用。

2. 函数是否需要修改调用者的数据？
   - 需要：传 `&mut T`。
   - 不需要：传 `&T`、`&str` 或 `&[T]`。

3. 这个参数是不是字符串？
   - 只读字符串优先用 `&str`。

4. 这个参数是不是数组/Vec？
   - 只读一段连续数据优先用 `&[T]`。

这不是最终完整规则，但足够支撑第一轮 Rust 学习。

10. Copy、Move、Clone、Borrow 的关系

可以把今天学的四个词放在一起：

词含义典型例子
Copy便宜复制，赋值后原变量还能用i32, bool, char, f64
Move所有权转移，原变量失效String, Vec<T>
Clone显式深拷贝或自定义复制s.clone()
Borrow借用，不拿走所有权&s, &mut s

它们解决的是同一个问题：

数据到底怎么在程序中流动？

Rust 不希望昂贵复制偷偷发生，所以：

小值可以 Copy。
堆数据默认 Move。
真的要复制就 Clone。
只是用一下就 Borrow。

11. 和 C++ 的关键区别

C++ 中：

void f(std::string s);

调用：

std::string name = "hello";
f(name);

通常是拷贝一份，name 还能用。

Rust 中：

#![allow(unused)]
fn main() {
fn f(s: String) {}

let name = String::from("hello");
f(name);
}

默认是 move，name 之后不能再用。

如果 Rust 想复制，要显式写：

#![allow(unused)]
fn main() {
f(name.clone());
}

如果只是读，要写：

#![allow(unused)]
fn main() {
f(&name);
}

今日总结

Day 2 的核心模型：

  1. i32 等简单类型赋值时 Copy。
  2. String 赋值或传参时默认 Move。
  3. clone() 表示显式深拷贝，可能有性能成本。
  4. 函数只读字符串时，优先用 &str。
  5. 函数要修改字符串时，用 &mut String。
  6. 可变借用是独占的，不能和原变量访问穿插使用。

更高层的理解：

Rust 学习的主线之一，就是不断训练函数签名设计：
T、&T、&mut T、&str、&[T] 到底该选哪个？

这条主线会贯穿后续：

String / Vec / struct / enum / Result / iterator / 文件读取 / 并发
