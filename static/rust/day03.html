1. 借用规则的核心模型

Day 2 已经学过：

#![allow(unused)]
fn main() {
let r = &mut s;
}

可以理解为：

r 是指向 s 的可变引用。
s 仍然拥有数据。
r 临时、独占地借用 s，并可以通过 r 修改 s。

Rust 的借用规则可以先记成一句话：

同一份数据：可以有多个只读引用，或者有一个可变引用，但二者不能重叠。

也就是常说的：

many readers OR one writer
多个读者，或者一个写者

2. 多个只读引用可以共存

完整示例：

fn main() {
    let s = String::from("hello");

    let r1 = &s;
    let r2 = &s;

    println!("r1 = {}", r1);
    println!("r2 = {}", r2);
    println!("s = {}", s);
}

这段代码可以正常通过。

原因是：

r1 和 r2 都只是读，不会修改数据。
多个只读引用同时存在是安全的。

可以类比成：

很多人同时看同一本书：可以。

3. 可变引用可以修改原数据

完整示例：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    r.push_str(" world");

    println!("r = {}", r);
}

这里有两处要区分：

#![allow(unused)]
fn main() {
let mut s = String::from("hello");
}

表示变量 s 绑定的值允许被修改。

#![allow(unused)]
fn main() {
let r = &mut s;
}

表示创建一个对 s 的可变引用。

r 不是 owner，s 才是 owner；但是在借用期间，r 可以修改 s 拥有的那份字符串。

4. 可变引用存在时不能同时使用原变量

错误示例：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    println!("s = {}", s);
    println!("r = {}", r);
}

典型错误信息类似：

cannot borrow `s` as immutable because it is also borrowed as mutable
mutable borrow occurs here
immutable borrow occurs here
mutable borrow later used here

原因是：

r 还要继续使用，所以 r 对 s 的可变借用还没有结束。
在这段时间里，不能再通过 s 访问同一份数据。

可以类比成：

书已经被一个人拿去修改批注了，在他还没还之前，别人不能同时拿这本书读。

5. 引用通常活到最后一次使用

下面这个版本可以通过：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;
    r.push_str(" world");
    println!("r = {}", r);

    println!("s = {}", s);
}

原因是：

#![allow(unused)]
fn main() {
println!("r = {}", r);
}

是 r 的最后一次使用。之后可变借用结束，所以可以重新使用 s。

现代 Rust 的引用作用域通常不是简单地持续到代码块结尾，而是到最后一次使用为止。这叫：

NLL: Non-Lexical Lifetimes
非词法生命周期

初学阶段不需要深入生命周期语法，只需要记住：

引用通常活到最后一次使用。
最后一次使用之后，原变量可以重新被使用。

6. 只读引用和可变引用不能重叠

可以先只读，再可变，只要只读引用后面不再使用：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    println!("r1 = {}", r1);

    let r2 = &mut s;
    r2.push_str(" world");

    println!("r2 = {}", r2);
}

但如果只读引用和可变引用重叠，就会失败：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &mut s;

    println!("r1 = {}", r1);
    println!("r2 = {}", r2);
}

因为 r1 在创建 r2 之后还要继续使用，所以只读借用和可变借用的作用范围重叠了。

7. &[T]：借用一段数组或 Vec

如果函数只是读一段连续元素，参数优先写成 &[T]。

完整示例：

fn print_slice(nums: &[i32]) {
    println!("slice = {:?}", nums);
    println!("len = {}", nums.len());

    if !nums.is_empty() {
        println!("first = {}", nums[0]);
    }
}

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    print_slice(&nums);
    print_slice(&nums[1..4]);
    print_slice(&nums[..2]);
    print_slice(&nums[2..]);
    print_slice(&nums[..]);
}

这里：

#![allow(unused)]
fn main() {
nums: &[i32]
}

表示：

借用一段连续的 i32。

它既可以接收整个 Vec，也可以接收 Vec 的一部分。

8. slice 范围语法

对于：

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    println!("{:?}", &nums[1..4]);
    println!("{:?}", &nums[..2]);
    println!("{:?}", &nums[2..]);
    println!("{:?}", &nums[..]);
}

含义是：

&nums[1..4]  -> [20, 30, 40]
&nums[..2]   -> [10, 20]
&nums[2..]   -> [30, 40, 50]
&nums[..]    -> [10, 20, 30, 40, 50]

Rust 的范围通常是左闭右开：

[start, end)

所以 1..4 包含索引 1、2、3，不包含索引 4。

9. 为什么优先用 &[T] 而不是 &Vec<T>

求和函数可以写成：

fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for &x in nums {
        total += x;
    }

    total
}

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    let total = sum_slice(&nums[1..4]);

    println!("sum = {}", total);
    println!("nums after borrowing = {:?}", nums);
}

&[i32] 比 &Vec<i32> 更通用：

&Vec<i32>  = 我必须借一个 Vec
&[i32]     = 我只需要借一段 i32

所以函数只读 Vec 内容时，优先使用：

#![allow(unused)]
fn main() {
fn f(xs: &[T])
}

而不是：

#![allow(unused)]
fn main() {
fn f(xs: &Vec<T>)
}

10. for &x in nums 的含义

在这个函数里：

#![allow(unused)]
fn main() {
fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for &x in nums {
        total += x;
    }

    total
}
}

nums 的类型是：

#![allow(unused)]
fn main() {
&[i32]
}

遍历 nums 时，每个元素的类型是：

#![allow(unused)]
fn main() {
&i32
}

所以：

#![allow(unused)]
fn main() {
for &x in nums
}

表示把 &i32 解开，得到 i32。

等价写法是：

#![allow(unused)]
fn main() {
fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for x in nums {
        total += *x;
    }

    total
}
}

因为 i32 是 Copy，所以复制一个整数很便宜。

11. &str：字符串 slice

&str 表示一段 UTF-8 字符串的只读视图。

完整示例：

fn print_text(text: &str) {
    println!("text = {}", text);
    println!("len in bytes = {}", text.len());
}

fn main() {
    let s = String::from("hello rust");

    let first = &s[..5];
    let second = &s[6..];

    print_text(&s);
    print_text(first);
    print_text(second);
    print_text("literal string");
}

这里 print_text 可以接收：

#![allow(unused)]
fn main() {
print_text(&s);               // String 的全部内容
print_text(&s[..5]);          // String 的一部分
print_text("literal string"); // 字符串字面量
}

所以只读字符串时，优先使用：

#![allow(unused)]
fn main() {
fn f(s: &str)
}

而不是：

#![allow(unused)]
fn main() {
fn f(s: &String)
}

12. String、&String、&str 的关系

可以先这样理解：

类型含义
String拥有字符串数据
&String借用整个 String 对象
&str借用字符串内容的一段

一般函数只读文本时，优先写：

#![allow(unused)]
fn main() {
fn print_text(text: &str)
}

因为 &str 能接收更多来源。

13. 字符串长度是字节数，不是字符数

Rust 字符串是 UTF-8 编码。str.len() 返回的是字节数，不是字符数。

完整示例：

fn main() {
    let en = String::from("hello");
    let zh = String::from("你好");

    println!("en len = {}", en.len());
    println!("zh len = {}", zh.len());
}

输出中，zh.len() 是 6，不是 2，因为中文字符通常每个占 3 个字节。

字符串 slice 必须切在合法 UTF-8 边界上。下面这个程序会在运行时 panic：

fn main() {
    let s = String::from("你好");
    let part = &s[..1];

    println!("{}", part);
}

典型错误信息：

byte index 1 is not a char boundary

说明 Rust 允许用字节范围切 &str，但运行时会检查这个范围是不是合法字符边界。

14. 函数返回 &str

函数可以接收一个引用，并返回这个引用里面的一部分。

完整示例：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let sentence = String::from("hello rust world");

    let word = first_word(&sentence);

    println!("first word = {}", word);
}

这个函数的意思是：

给我一段字符串 text。
我不拥有它，只借来看。
我返回其中第一个单词那一段。

word 不是新的字符串，不拥有数据，它只是指向 sentence 内部一段内容的视图。

15. char_indices() 的作用

在函数中：

#![allow(unused)]
fn main() {
for (index, ch) in text.char_indices() {
    if ch == ' ' {
        return &text[..index];
    }
}
}

char_indices() 会遍历字符串里的字符，同时给出每个字符的字节位置。

对于：

hello rust

可以粗略理解为：

index = 0, ch = 'h'
index = 1, ch = 'e'
index = 2, ch = 'l'
index = 3, ch = 'l'
index = 4, ch = 'o'
index = 5, ch = ' '

遇到空格时：

#![allow(unused)]
fn main() {
return &text[..index];
}

就返回开头到空格之前的字符串 slice。

16. 返回引用时，不能比原数据活得更久

下面这段可以通过：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let mut sentence = String::from("hello rust world");

    let word = first_word(&sentence);
    println!("first word = {}", word);

    sentence.clear();
    sentence.push_str("borrow checker");
    println!("sentence = {}", sentence);
}

因为：

#![allow(unused)]
fn main() {
println!("first word = {}", word);
}

是 word 的最后一次使用。之后 word 不再使用，对 sentence 的只读借用结束，所以可以修改 sentence。

但下面这段会失败：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let mut sentence = String::from("hello rust world");

    let word = first_word(&sentence);

    sentence.clear();

    println!("word after clear = {}", word);
}

典型错误信息类似：

cannot borrow `sentence` as mutable because it is also borrowed as immutable

原因是：

word 借用了 sentence 里面的一段。
如果后面还要使用 word，那么这段借用必须继续有效。
sentence.clear() 会可变修改原字符串，所以 Rust 禁止它和 word 的后续使用重叠。

17. 函数返回 &[T]

同样的逻辑也适用于数组或 Vec slice。

完整示例：

fn first_two(nums: &[i32]) -> &[i32] {
    if nums.len() >= 2 {
        &nums[..2]
    } else {
        nums
    }
}

fn main() {
    let nums = vec![10, 20, 30, 40];

    let head = first_two(&nums);

    println!("first two = {:?}", head);
    println!("nums still usable = {:?}", nums);
}

这里：

nums 拥有 Vec。
head 是借用 nums 前两个元素的 &[i32]。

如果在 head 后续还要使用时修改 nums，就会失败：

fn first_two(nums: &[i32]) -> &[i32] {
    if nums.len() >= 2 {
        &nums[..2]
    } else {
        nums
    }
}

fn main() {
    let mut nums = vec![10, 20, 30, 40];

    let head = first_two(&nums);

    nums.push(50);

    println!("first two = {:?}", head);
}

原因是：

head 借用了 nums 的内部元素。
nums.push(50) 可能导致 Vec 重新分配内存。
如果允许 push 之后继续使用 head，head 可能指向旧内存。

Rust 在编译期禁止这种情况。

18. 返回 String 还是返回 &str

如果返回值来自输入数据的一部分，可以返回 &str：

#![allow(unused)]
fn main() {
fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}
}

这不会分配新内存，只是返回原字符串的一段视图。

如果函数内部创建了新的字符串，就返回 String：

fn make_greeting(name: &str) -> String {
    format!("hello, {}", name)
}

fn main() {
    let msg = make_greeting("rust");
    println!("{}", msg);
}

这里不能返回 &str，因为 format! 创建的是函数内部的新字符串。函数结束后，必须把这个新字符串的所有权交给调用者，所以返回 String。

19. 函数参数选择决策表

想做什么参数类型例子含义
函数要拿走这个值Tfn consume(s: String)所有权 move 进函数
函数只读一个普通对象&Tfn print_user(user: &User)借来看，不修改
函数要修改调用者的数据&mut Tfn normalize(v: &mut Vec<f64>)借来改，独占
函数只读一段数组或 Vec&[T]fn sum(xs: &[i32])借用一段连续元素
函数只读字符串&strfn count_words(s: &str)借用一段文本
函数需要返回新字符串Stringfn join_name(...) -> String创建并返回拥有所有权的新数据
函数需要返回新 VecVec<T>fn filter(...) -> Vec<T>创建并返回新集合

可以用这个流程判断参数类型：

1. 函数是否需要拥有这个值？
   - 是：用 T，例如 String、Vec<T>
   - 否：继续

2. 函数是否需要修改调用者的数据？
   - 是：用 &mut T
   - 否：继续

3. 参数是不是字符串？
   - 是：优先用 &str
   - 否：继续

4. 参数是不是 Vec 或数组内容？
   - 是：优先用 &[T]
   - 否：用 &T

返回值可以这样判断：

1. 返回值是不是函数新创建的数据？
   - 是：返回 String、Vec<T>、T

2. 返回值是不是输入数据的一部分？
   - 是：返回 &str、&[T]、&T

今日总结

Day 3 的核心概念：

形式含义
&T只读借用
&mut T可变借用，独占
&[T]借用一段连续元素
&str借用一段 UTF-8 字符串

核心规则：

  1. 多个只读引用可以共存。
  2. 一个可变引用存在时，不能同时有其他引用访问同一份数据。
  3. 引用通常活到最后一次使用。
  4. slice 是对原数据的一段借用，不拥有数据。
  5. 返回 slice 时，返回值不能比输入数据活得更久。
  6. 只读 Vec 内容时，函数参数优先用 &[T]。
  7. 只读字符串时，函数参数优先用 &str。

一句话压缩 Day 3：

Rust 不是不让你共享数据，而是要求你明确：谁拥有，谁只读借用，谁独占修改，借用能活多久。
