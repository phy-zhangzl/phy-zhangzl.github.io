1. 函数返回值：最后一个表达式

在 Rust 里，函数体最后一个没有分号的表达式就是返回值。

#![allow(unused)]
fn main() {
fn add(a: i32, b: i32) -> i32 {
    a + b
}
}

等价于：

#![allow(unused)]
fn main() {
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}
}

但 Rust 更常写前一种风格。

如果加了分号：

fn add(a: i32, b: i32) -> i32 {
    a + b;
}

编译器会报错：

expected `i32`, found `()`
help: remove this semicolon

2. 语句 vs 表达式

这个区别在 Rust 中非常重要：

语句 statement表达式 expression
做什么执行动作计算并产生值
有没有值没有可用的值（返回 ()）有值
例子let x = 3;a + b，if ... else ...

函数体最后用表达式作为返回值，是 Rust 常见的风格。

3. if 也是表达式

#![allow(unused)]
fn main() {
fn describe_number(x: i32) -> &'static str {
    if x < 0 {
        "negative"
    } else if x == 0 {
        "zero"
    } else if x % 2 == 0 {
        "positive even"
    } else {
        "positive odd"
    }
}
}

这里整个 if ... else ... 是函数最后一个表达式，它的结果就是函数返回值。

if 作为表达式时，所有分支必须返回同一种类型。比如这个不行：

let value = if x > 0 {
    1
} else {
    "negative"
};

因为 Rust 需要在编译时确定 value 的类型，但两个分支类型不一样。

4. match：强大的分支表达式

#![allow(unused)]
fn main() {
fn grade(score: i32) -> &'static str {
    match score {
        90..=100 => "A",
        80..=89 => "B",
        70..=79 => "C",
        60..=69 => "D",
        0..=59 => "F",
        _ => "invalid",
    }
}
}

关键语法点：

90..=100    包含两端的范围，等价于 [90, 100]
_           兜底，匹配其他所有情况
match 必须穷尽所有可能性，所以 _ 很常用

用 | 匹配多个值

#![allow(unused)]
fn main() {
match x {
    1 | 2 => println!("one or two"),
    3 | 4 => println!("three or four"),
    5..=10 => println!("five to ten"),
    _ => println!("something else"),
}
}

| 表示“或“，..= 表示包含两端的范围。

5. 三种循环

for

#![allow(unused)]
fn main() {
for score in [95, 82, 61, 40, 120] {
    println!("score {} -> grade {}", score, grade(score));
}
}

for 也支持 range 语法：

#![allow(unused)]
fn main() {
for i in 0..5 { ... }    // 0, 1, 2, 3, 4
for i in 0..=5 { ... }   // 0, 1, 2, 3, 4, 5
}

while

#![allow(unused)]
fn main() {
let mut count = 3;
while count > 0 {
    println!("count = {}", count);
    count -= 1;
}
}

loop

无限循环，但可以用 break 返回值：

#![allow(unused)]
fn main() {
let mut n = 0;
let result = loop {
    n += 1;
    if n == 5 {
        break n * 10;
    }
};
// result = 50
}

这里 loop 作为表达式产生值 50。

6. Option<T>

Option<T> 是 Rust 标准库里非常常用的枚举，表示“可能有值，也可能没有值“：

#![allow(unused)]
fn main() {
fn find_first_even(nums: &[i32]) -> Option<i32> {
    for &x in nums {
        if x % 2 == 0 {
            return Some(x);
        }
    }

    None
}
}

两种可能：

Some(value)   -> 有值，value 是具体内容
None          -> 没有值

用 match 处理：

#![allow(unused)]
fn main() {
match first_even {
    Some(value) => println!("first even = {}", value),
    None => println!("no even number"),
}
}

7. if let：简化单模式匹配

如果只关心其中一种模式：

#![allow(unused)]
fn main() {
if let Some(value) = find_first_even(&[1, 3, 8, 9]) {
    println!("found even = {}", value);
}
}

等价于：

#![allow(unused)]
fn main() {
match find_first_even(&[1, 3, 8, 9]) {
    Some(value) => println!("found even = {}", value),
    _ => {}
}
}

带 else 的版本：

#![allow(unused)]
fn main() {
if let Some(value) = find_first_even(&[1, 3, 7]) {
    println!("found even = {}", value);
} else {
    println!("no even number");
}
}

为什么必须写 let？

#![allow(unused)]
fn main() {
if let Some(value) = expr { ... }
}

不能省略 let，写成：

if Some(value) = expr { ... }

因为普通 if 期望条件是 bool，而 Some(value) = expr 是模式匹配赋值，不是 bool。let 关键字告诉编译器“这一行是模式匹配，不是 bool 判断“。

8. while let：持续匹配直到失败

#![allow(unused)]
fn main() {
let mut nums = vec![1, 2, 3, 4, 5];

while let Some(top) = nums.pop() {
    println!("popped = {}", top);
}
}

逻辑：

nums.pop() 返回 Some(5)，匹配成功，执行循环体
nums.pop() 返回 Some(4)，匹配成功
...
nums.pop() 返回 None，匹配失败，退出循环

9. let else：简化 Option 的提前返回

#![allow(unused)]
fn main() {
fn try_parse(s: &str) -> Option<i32> {
    let result: i32 = s.parse().ok()?;
    Some(result)
}

fn process(s: &str) {
    let Some(value) = try_parse(s) else {
        println!("parse failed: {}", s);
        return;
    };

    println!("parsed value = {}", value);
    println!("value + 10 = {}", value + 10);
}
}

含义：

如果 try_parse(s) 返回 Some(value)，取出 value。
否则执行 else 块，然后 return。

let else 的 else 块必须以 return、break、continue 或 panic! 结尾。

10. 元组解构

let 可以直接解构元组：

#![allow(unused)]
fn main() {
let pair = (100, 200);
let (a, b) = pair;
// a = 100, b = 200

let (first, _, third) = (1, 2, 3);
// _ 表示忽略这个位置的值
}

match 也可以解构元组，并根据内容做不同分支：

#![allow(unused)]
fn main() {
let point = (3, 0);

match point {
    (0, 0) => println!("origin"),
    (0, y) => println!("on y-axis, y = {}", y),
    (x, 0) => println!("on x-axis, x = {}", x),
    (x, y) => println!("x = {}, y = {}", x, y),
}
}

Rust 从上往下匹配，第一个匹配到的分支会被执行。

11. match guard

match 分支可以附加条件：

#![allow(unused)]
fn main() {
let pair = (10, 20);

match pair {
    (x, y) if x > y => println!("(larger, smaller)"),
    (x, y) if x < y => println!("(smaller, larger)"),
    (x, _) => println!("(equal, value = {})", x),
}
}

if x > y 就是 match guard：模式匹配成功后再额外检查条件。

12. enumerate()

遍历集合时同时获取索引：

#![allow(unused)]
fn main() {
let colors = vec!["red", "green", "blue"];

for (index, color) in colors.iter().enumerate() {
    println!("color[{}] = {}", index, color);
}
}

输出：

color[0] = red
color[1] = green
color[2] = blue

13. 循环标签 'label

嵌套循环时，可以用标签指定 break 和 continue 的作用范围。

#![allow(unused)]
fn main() {
'outer: for i in 0..3 {
    for j in 0..3 {
        if i == 1 && j == 1 {
            break 'outer;           // 跳出两层循环
        }
        if j == 1 {
            continue 'outer;        // 跳到外层下一次迭代
        }
    }
}
}

语法：标签以单引号 ' 开头，放在循环关键字之前。

没有标签时，break 和 continue 只影响最内层循环。

14. panic!：程序紧急停止

#![allow(unused)]
fn main() {
panic!("something went wrong");
}

效果：

1. 打印 panic 信息（文件名、行号、自定义消息）
2. 程序立即停止
3. 后面的代码不会执行
4. 退出码 101

运行 stack backtrace

RUST_BACKTRACE=1 cargo run

会打印调用栈，帮助定位问题来源。

常见的自动 panic 场景

let arr = [1, 2, 3];
arr[10];           // index out of bounds

let x: Option<i32> = None;
x.unwrap();        // called `Option::unwrap()` on a `None` value

Rust 对 panic! 的哲学

panic! 用于"程序无法继续运行"的情况。
不用于"预期可能出错"的情况。

常见用法：

数组越界 -> panic
assert 检查失败 -> panic
程序配置不合法，无法启动 -> panic
用户输入非法 -> 不用 panic，用 Result
文件不存在 -> 不用 panic，用 Result

初学阶段有时为了方便会调用 unwrap()，潜台词是“这里应该不会出问题，如果出问题就 panic 给我看“。
