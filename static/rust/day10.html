1. HashMap 和 HashSet 在 Rust 全貌中的位置

前面已经学过：

Vec<T>       -> 顺序存储
String       -> 可增长字符串
Iterator     -> 数据流处理
Result       -> 可恢复错误

今天的两个容器是：

HashMap<K,V> -> 按 key 查 value
HashSet<T>   -> 只关心某个值是否出现过

Python 类比：

Rust HashMap<K, V> ≈ Python dict
Rust HashSet<T>    ≈ Python set

C++ 类比：

Rust HashMap<K, V> ≈ C++ unordered_map
Rust HashSet<T>    ≈ C++ unordered_set

使用前需要导入：

#![allow(unused)]
fn main() {
use std::collections::{HashMap, HashSet};
}

HashMap 和 HashSet 不在 Rust prelude 中，因此不像 Vec、String、Option 那样默认可用。

2. HashMap 基础：insert 与 get

完整示例：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    println!("scores = {:?}", scores);

    match scores.get("Alice") {
        Some(score) => println!("Alice's score = {score}"),
        None => println!("Alice not found"),
    }

    match scores.get("David") {
        Some(score) => println!("David's score = {score}"),
        None => println!("David not found"),
    }
}

scores 的类型由插入的数据推断出来：

#![allow(unused)]
fn main() {
HashMap<String, i32>
}

含义：

key 是 String
value 是 i32

get 返回：

#![allow(unused)]
fn main() {
Option<&i32>
}

原因有两个：

1. key 可能不存在，所以外层是 Option。
2. value 归 HashMap 所有，所以 get 只借用，返回 &i32。

所以：

#![allow(unused)]
fn main() {
scores.get("Alice")
}

可能是：

#![allow(unused)]
fn main() {
Some(&95)
}

也可能是：

#![allow(unused)]
fn main() {
None
}

这和 Day 7 的 Option 直接连接起来。

3. insert 会覆盖旧值

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Bob"), 72);

    println!("scores = {:?}", scores);
}

结果中 Bob 的分数是 72。

insert 的语义：

如果 key 不存在，插入新 key-value。
如果 key 已存在，覆盖旧 value。

HashMap 中每个 key 只能对应一个 value。

4. entry(...).or_insert(...)

有时我们不想覆盖已有值，而是希望：

如果 key 存在，就保留原值。
如果 key 不存在，就插入默认值。

可以使用：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    scores.entry(String::from("Alice")).or_insert(100);
    scores.entry(String::from("David")).or_insert(81);

    println!("scores = {:?}", scores);
}

结果：

Alice 仍然是 95
David 被插入为 81

含义：

#![allow(unused)]
fn main() {
scores.entry(key).or_insert(default_value)
}

可以读作：

找到 key 对应的 entry。
如果 key 不存在，就插入 default_value。
无论原来存在还是刚插入，都返回这个 value 的可变引用。

最后一点非常重要：

#![allow(unused)]
fn main() {
or_insert(...)
}

返回的是：

#![allow(unused)]
fn main() {
&mut V
}

不是 V 本身。

5. 词频统计：entry 的经典用法

use std::collections::HashMap;

fn main() {
    let text = "rust rust ai infra rust ai";
    let mut word_counts = HashMap::new();

    for word in text.split_whitespace() {
        let count = word_counts.entry(word).or_insert(0);
        *count += 1;
    }

    println!("word_counts = {:?}", word_counts);
}

这里 word_counts 的类型是：

#![allow(unused)]
fn main() {
HashMap<&str, i32>
}

因为：

#![allow(unused)]
fn main() {
text.split_whitespace()
}

产生的是 &str。

这一句：

#![allow(unused)]
fn main() {
let count = word_counts.entry(word).or_insert(0);
}

中，count 的类型是：

#![allow(unused)]
fn main() {
&mut i32
}

也就是说，count 不是一个独立的 i32 副本，而是指向 word_counts 内部某个 value 的可变引用。

因此：

#![allow(unused)]
fn main() {
*count += 1;
}

修改的是 HashMap 里面的 value 本身。

5.1 为什么不需要把 count 放回 word_counts

这是今天很关键的理解点。

假设第一次遇到 "rust"：

word_counts = {}

执行：

#![allow(unused)]
fn main() {
let count = word_counts.entry("rust").or_insert(0);
}

因为 "rust" 不存在，所以 map 变成：

word_counts = { "rust": 0 }

然后 or_insert(0) 返回 map 内部这个 0 的可变引用：

count ---> word_counts["rust"]

执行：

#![allow(unused)]
fn main() {
*count += 1;
}

就会把 map 内部的值改成：

word_counts = { "rust": 1 }

第二次遇到 "rust" 时，entry("rust") 找到已有 value，or_insert(0) 不会插入新值，而是返回已有计数的可变引用。再次执行 *count += 1，就变成 2。

所以这里不是：

取出 count -> 修改 count -> 忘了放回 map

而是：

借到 map 内部 value 的可变引用 -> 直接修改 map 内部 value

这和 Day 9 的 iter_mut() 本质一样：

fn main() {
    let mut scores = vec![58, 76, 90];

    for score in scores.iter_mut() {
        *score += 5;
    }

    println!("scores = {:?}", scores);
}

这里 score: &mut i32 指向 Vec 里的元素；词频统计里 count: &mut i32 指向 HashMap 里的 value。

6. HashMap 遍历顺序不固定

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    for (name, score) in &scores {
        println!("{name}: {score}");
    }
}

HashMap 不保证遍历顺序。

所以输出顺序可能是：

Alice: 95
Bob: 67
Carol: 88

也可能是其他顺序。

不要写依赖 HashMap 遍历顺序的逻辑。

如果需要排序，常见做法是先收集成 Vec 再排序：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    let mut items: Vec<_> = scores.iter().collect();
    items.sort_by_key(|(name, _score)| *name);

    for (name, score) in items {
        println!("{name}: {score}");
    }
}

7. HashMap<String, V> 中 key 的所有权

HashMap<K, V> 拥有它里面的 key 和 value。

例如：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    let name = String::from("Alice");

    scores.insert(name, 95);

    println!("scores = {:?}", scores);

    // 取消注释会报错：name 已经被 move 进 HashMap。
    // println!("name = {name}");
}

这一句：

#![allow(unused)]
fn main() {
scores.insert(name, 95);
}

把 name: String 移动进了 scores。

也就是：

name 的所有权从局部变量 name 转移给 HashMap。

这和 Day 2 学过的 move 一样：

#![allow(unused)]
fn main() {
let s1 = String::from("hello");
let s2 = s1;

// println!("{s1}"); // s1 已经被 move
}

insert 只是把 move 的目标换成了 HashMap。

7.1 如果插入后还想使用原 String

可以使用 clone()：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    let name = String::from("Alice");

    scores.insert(name.clone(), 95);

    println!("name is still usable: {name}");
    println!("scores = {:?}", scores);
}

这里：

#![allow(unused)]
fn main() {
name.clone()
}

创建了一个新的 String 放进 map，原来的 name 仍然可用。

代价是多复制一份字符串内容。

8. value 的所有权也一样

如果 value 也是 String，也会被 move 进 map：

use std::collections::HashMap;

fn main() {
    let mut users = HashMap::new();

    let name = String::from("Alice");
    let city = String::from("Beijing");

    users.insert(name, city);

    println!("users = {:?}", users);

    // 取消注释会报错：name 和 city 都已经被 move。
    // println!("name = {name}");
    // println!("city = {city}");
}

这里 users 的类型是：

#![allow(unused)]
fn main() {
HashMap<String, String>
}

key 和 value 都由 map 拥有。

9. 为什么 HashMap<String, i32> 可以用 get("Alice")

看这个例子：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    println!("{:?}", scores.get("Alice"));
}

scores 的 key 类型是：

#![allow(unused)]
fn main() {
String
}

但查询时使用的是：

#![allow(unused)]
fn main() {
"Alice"
}

它的类型是：

#![allow(unused)]
fn main() {
&str
}

这为什么可以？

直觉解释：

String 拥有字符串内容；
&str 是字符串切片，只是借用字符串内容；
String 可以按 str 来借用。

所以标准库允许：

#![allow(unused)]
fn main() {
HashMap<String, V>
}

用：

#![allow(unused)]
fn main() {
&str
}

查询。

这样就不需要临时构造一个新的 String：

#![allow(unused)]
fn main() {
scores.get(&String::from("Alice"));
}

这种写法会产生不必要的分配。

背后依赖标准库中的 trait，例如 Borrow。当前阶段不用深挖，只需要记住：

如果 HashMap 的 key 是 String，通常可以用 &str 查询。

例如：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    let query = String::from("Alice");

    println!("{:?}", scores.get("Alice"));
    println!("{:?}", scores.get(query.as_str()));
    println!("query is still usable: {query}");
}

query.as_str() 返回 &str，只是借用 query 的内容，不会 move query。

10. get_mut：拿到 value 的可变引用

如果要修改已有 value，可以使用 get_mut：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    if let Some(score) = scores.get_mut("Alice") {
        *score += 5;
    }

    println!("scores = {:?}", scores);
}

get_mut 返回：

#![allow(unused)]
fn main() {
Option<&mut V>
}

在这个例子里是：

#![allow(unused)]
fn main() {
Option<&mut i32>
}

所以：

#![allow(unused)]
fn main() {
if let Some(score) = scores.get_mut("Alice") {
    *score += 5;
}
}

里面的 score 是：

#![allow(unused)]
fn main() {
&mut i32
}

需要写：

#![allow(unused)]
fn main() {
*score += 5;
}

这和：

#![allow(unused)]
fn main() {
let count = word_counts.entry(word).or_insert(0);
*count += 1;
}

是同一类模式：拿到容器内部 value 的可变引用，然后原地修改。

11. HashMap<String, V> vs HashMap<&str, V>

这两个选择很常见。

11.1 HashMap<String, V>

#![allow(unused)]
fn main() {
HashMap<String, i32>
}

含义：

map 拥有 key。

优点：

数据独立存在，最稳妥。
可以从文件、网络、用户输入中读取字符串作为 key。
适合跨函数返回或长期保存。

缺点：

插入时可能需要 move 或 clone String。

真实工程中更常用。

11.2 HashMap<&str, V>

#![allow(unused)]
fn main() {
HashMap<&str, i32>
}

含义：

map 不拥有 key，只保存字符串引用。

优点：

不复制字符串。

缺点：

被引用的字符串必须活得比 map 久。

例如词频统计可以使用 HashMap<&str, i32>：

use std::collections::HashMap;

fn main() {
    let text = "rust rust ai";
    let mut counts = HashMap::new();

    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }

    println!("counts = {:?}", counts);
}

这里 word 都是从 text 借来的 &str，而 text 活得足够久。

但下面这种思路不行：

use std::collections::HashMap;

fn build_map() -> HashMap<&str, i32> {
    let name = String::from("Alice");
    let mut scores = HashMap::new();

    scores.insert(name.as_str(), 95);

    scores
}

因为 name 是函数里的局部 String。函数结束后 name 被释放，如果返回 HashMap<&str, i32>，map 里就会保存指向已释放字符串的引用。Rust 会阻止这种悬垂引用。

重要结论：

HashMap<String, V> 是拥有 key；
HashMap<&str, V> 是借用 key。

12. HashSet：只关心值是否出现过

HashSet<T> 可以理解为只有 key、没有 value 的 HashMap。

use std::collections::HashSet;

fn main() {
    let text = "rust rust ai infra rust ai";
    let mut seen_words = HashSet::new();

    for word in text.split_whitespace() {
        seen_words.insert(word);
    }

    println!("seen_words = {:?}", seen_words);
    println!("contains rust? {}", seen_words.contains("rust"));
    println!("contains python? {}", seen_words.contains("python"));
}

HashSet 关心：

某个值是否出现过。

不关心出现了几次。

例如：

rust rust ai infra rust ai

放进 HashSet 后只剩唯一值：

{"rust", "ai", "infra"}

同样，HashSet 也不保证打印顺序。

13. 用 HashSet 找重复项

use std::collections::HashSet;

fn main() {
    let names = vec!["Alice", "Bob", "Alice", "Carol", "Bob", "David"];
    let mut seen = HashSet::new();
    let mut duplicates = HashSet::new();

    for name in names {
        if !seen.insert(name) {
            duplicates.insert(name);
        }
    }

    println!("duplicates = {:?}", duplicates);
}

关键是：

#![allow(unused)]
fn main() {
seen.insert(name)
}

返回：

#![allow(unused)]
fn main() {
bool
}

含义：

true  -> 这个值原来不存在，这次成功插入
false -> 这个值原来已经存在，没有再次插入

所以：

#![allow(unused)]
fn main() {
if !seen.insert(name) {
    duplicates.insert(name);
}
}

意思是：

如果 name 之前已经出现过，就把它加入 duplicates。

14. 今日主实验代码

day10_hashmaps_sets/src/main.rs：

use std::collections::{HashMap, HashSet};

fn main() {
    println!("== 1. HashMap basics: insert and get ==");

    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    println!("scores = {:?}", scores);

    let name = "Alice";
    match scores.get(name) {
        Some(score) => println!("{name}'s score = {score}"),
        None => println!("{name} not found"),
    }

    match scores.get("David") {
        Some(score) => println!("David's score = {score}"),
        None => println!("David not found"),
    }

    println!("\n== 2. insert overwrites an old value ==");

    scores.insert(String::from("Bob"), 72);
    println!("scores after updating Bob = {:?}", scores);

    println!("\n== 3. entry(): insert only if missing ==");

    scores.entry(String::from("Alice")).or_insert(100);
    scores.entry(String::from("David")).or_insert(81);

    println!("scores after entry/or_insert = {:?}", scores);

    println!("\n== 4. Count word frequency with HashMap ==");

    let text = "rust rust ai infra rust ai";
    let mut word_counts = HashMap::new();

    for word in text.split_whitespace() {
        let count = word_counts.entry(word).or_insert(0);
        *count += 1;
    }

    println!("word_counts = {:?}", word_counts);

    println!("\n== 5. Iterate over HashMap ==");

    for (name, score) in &scores {
        println!("{name}: {score}");
    }

    println!("\n== 6. HashSet basics: unique values ==");

    let mut seen_words = HashSet::new();

    for word in text.split_whitespace() {
        seen_words.insert(word);
    }

    println!("seen_words = {:?}", seen_words);
    println!("contains rust? {}", seen_words.contains("rust"));
    println!("contains python? {}", seen_words.contains("python"));

    println!("\n== 7. Find duplicates with HashSet ==");

    let names = vec!["Alice", "Bob", "Alice", "Carol", "Bob", "David"];
    let mut seen = HashSet::new();
    let mut duplicates = HashSet::new();

    for name in names {
        if !seen.insert(name) {
            duplicates.insert(name);
        }
    }

    println!("duplicates = {:?}", duplicates);
}

运行输出示例：

Alice's score = 95
David not found

== 2. insert overwrites an old value ==

== 3. entry(): insert only if missing ==
scores after entry/or_insert = {"Carol": 88, "Alice": 95, "David": 81, "Bob": 72}

今日总结

Day 10 的核心地图：

概念关键点
HashMap<K, V>key-value 映射
HashSet<T>唯一值集合
HashMap::new()创建空 map
insert插入新值；key 已存在时覆盖旧值
get查询，返回 Option<&V>
get_mut查询并可变借用 value，返回 Option<&mut V>
entry获取 key 对应的 entry
or_insertkey 不存在时插入默认值，并返回 &mut V
HashMap<String, V>map 拥有 key
HashMap<&str, V>map 借用 key，有生命周期限制
String key插入时会 move；如还要用原变量，需要 clone()
get("Alice")HashMap<String, V> 通常可用 &str 查询
HashSet::insert返回 bool，表示是否新插入成功

一句话总结：

HashMap 用来按 key 查 value；HashSet 用来判断值是否出现过。

更 Rust 的总结：

HashMap 拥有自己的 key/value；get 借用 value；entry/or_insert 返回内部 value 的可变引用，因此可以原地更新。
