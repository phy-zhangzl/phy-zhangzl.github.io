Day 11 - Module、crate、use、pub 与测试

今日目标

Day 11 学习 Rust 的模块系统。目标不是背语法，而是理解 Rust 如何把一个逐渐变大的程序拆成多个文件、多个模块，并通过清晰的公开 API 组织工程结构。

今日重点：

  • mod：把文件或子模块挂到模块树上
  • pub：控制模块、函数、类型、字段的可见性
  • use：把路径引入当前作用域，减少重复长路径
  • crate::：从当前 crate 根部开始找路径
  • super::：从父模块开始找路径
  • 嵌套模块：用目录组织子模块
  • pub use：re-export，重新导出更干净的外部 API
  • #[cfg(test)] mod tests：模块内单元测试
  • src/lib.rs 与 src/main.rs：library crate 与 binary crate 的分工

1. 为什么需要模块系统

前面几天的代码大多写在一个 main.rs 里。随着程序变大，一个文件会逐渐混入很多职责：

数据结构定义
文本解析
统计逻辑
输出格式化
错误处理
main 流程
测试代码

模块系统的作用是把它们拆开：

student.rs  -> 数据结构
parser.rs   -> 解析文本
stats.rs    -> 统计逻辑
report.rs   -> 汇总输出
main.rs     -> 程序入口
lib.rs      -> library crate 根部，对外组织 API

一句话：

module 系统负责组织代码边界；pub 负责控制边界外能看见什么。

3. 第一层：多文件模块

最初可以从一个 binary 项目理解模块：

src/main.rs
src/student.rs
src/parser.rs
src/stats.rs

在 main.rs 里声明：

mod student;
mod parser;
mod stats;

这几行告诉 Rust：

当前 crate 里有 student/parser/stats 这些模块；
请去找 src/student.rs、src/parser.rs、src/stats.rs。

重要规则：

文件存在 != 模块已声明。
必须用 mod 把文件挂到模块树上。

如果删掉：

mod parser;

即使 src/parser.rs 文件存在，Rust 也不知道 crate::parser 是什么。

4. student.rs：pub struct、公开字段与私有字段

src/student.rs：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone)]
pub struct Student {
    pub name: String,
    score: i32,
}

impl Student {
    pub fn new(name: &str, score: i32) -> Self {
        Self {
            name: name.to_string(),
            score,
        }
    }

    pub fn score(&self) -> i32 {
        self.score
    }

    pub fn is_passing(&self) -> bool {
        self.score >= 60
    }
}

pub fn sample_students() -> Vec<Student> {
    vec![
        Student::new("Alice", 95),
        Student::new("Bob", 67),
        Student::new("Carol", 88),
        Student::new("David", 52),
    ]
}
}

4.1 pub struct Student

#![allow(unused)]
fn main() {
pub struct Student
}

表示 Student 这个类型可以被其他模块使用。

如果写成：

struct Student { ... }

那么 parser.rs、stats.rs、report.rs 这些兄弟模块就不能使用 Student。

Rust 默认是 private。想让模块外访问，必须显式写 pub。

4.2 struct 是 pub，字段不会自动 pub

#![allow(unused)]
fn main() {
pub struct Student {
    pub name: String,
    score: i32,
}
}

含义是：

Student 类型是 public。
name 字段是 public。
score 字段是 private。

所以其他模块可以写：

student.name

但不能直接写：

student.score

因为 score 字段没有 pub。

不过外部可以通过公开方法读取：

#![allow(unused)]
fn main() {
pub fn score(&self) -> i32 {
    self.score
}
}

这就是封装：

字段不直接公开；
通过公开方法控制访问。

5. parser.rs：模块间引用与 crate::

src/parser.rs：

#![allow(unused)]
fn main() {
use crate::student::Student;

pub fn parse_student(line: &str) -> Result<Student, String> {
    let (name, score_text) = line
        .split_once(',')
        .ok_or_else(|| format!("missing comma in line: {line:?}"))?;

    let name = name.trim();
    if name.is_empty() {
        return Err(format!("missing student name in line: {line:?}"));
    }

    let score = score_text
        .trim()
        .parse::<i32>()
        .map_err(|error| format!("invalid score in line {line:?}: {error}"))?;

    Ok(Student::new(name, score))
}

pub fn parse_students(text: &str) -> Result<Vec<Student>, String> {
    let mut students = Vec::new();

    for (index, line) in text.lines().enumerate() {
        let trimmed = line.trim();

        if trimmed.is_empty() {
            continue;
        }

        let student = parse_student(trimmed)
            .map_err(|error| format!("line {}: {error}", index + 1))?;

        students.push(student);
    }

    Ok(students)
}
}

这一句：

#![allow(unused)]
fn main() {
use crate::student::Student;
}

表示：

从当前 crate 的根开始找 student::Student。

如果不写 use，也可以在函数签名里写完整路径：

pub fn parse_student(line: &str) -> Result<crate::student::Student, String> {
    // ...
}

但这会很啰嗦。所以常用 use 把路径引入当前作用域。

6. stats.rs：模块内测试与 super::*

src/stats.rs：

#![allow(unused)]
fn main() {
use std::collections::HashMap;

use crate::student::Student;

pub fn average_score(students: &[Student]) -> Option<f64> {
    if students.is_empty() {
        return None;
    }

    let total: i32 = students.iter().map(|student| student.score()).sum();
    Some(total as f64 / students.len() as f64)
}

pub fn passing_names(students: &[Student]) -> Vec<String> {
    students
        .iter()
        .filter(|student| student.is_passing())
        .map(|student| student.name.clone())
        .collect()
}

pub fn score_map(students: &[Student]) -> HashMap<String, i32> {
    let mut scores = HashMap::new();

    for student in students {
        scores.insert(student.name.clone(), student.score());
    }

    scores
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn average_score_returns_none_for_empty_input() {
        let students = Vec::new();
        assert_eq!(average_score(&students), None);
    }

    #[test]
    fn average_score_computes_mean() {
        let students = vec![Student::new("Alice", 80), Student::new("Bob", 100)];
        assert_eq!(average_score(&students), Some(90.0));
    }

    #[test]
    fn passing_names_keeps_only_passing_students() {
        let students = vec![Student::new("Alice", 95), Student::new("David", 52)];
        assert_eq!(passing_names(&students), vec![String::from("Alice")]);
    }
}
}

6.1 #[cfg(test)] mod tests

#![allow(unused)]
fn main() {
#[cfg(test)]
mod tests {
    // ...
}
}

表示：

只有 cargo test 时才编译 tests 模块。

所以测试代码不会影响：

cargo run

6.2 use super::*

在 stats.rs 里，模块关系是：

stats
└── tests

tests 的父模块是 stats。所以：

#![allow(unused)]
fn main() {
use super::*;
}

表示：

从父模块 stats 引入可见项。

这样测试里可以直接调用：

#![allow(unused)]
fn main() {
average_score(...)
passing_names(...)
}

不用写：

super::average_score(...)

对比：

crate:: 从当前 crate 根部开始找。
super:: 从当前模块的父模块开始找。

7. report.rs：引入模块本身

src/report.rs：

#![allow(unused)]
fn main() {
use crate::stats;
use crate::student::Student;

pub fn print_summary(students: &[Student]) {
    println!("students = {:?}", students);

    match stats::average_score(students) {
        Some(avg) => println!("average score = {avg:.2}"),
        None => println!("average score = N/A"),
    }

    let passing_names = stats::passing_names(students);
    println!("passing students = {:?}", passing_names);

    let score_map = stats::score_map(students);
    println!("score map = {:?}", score_map);
}
}

这里：

#![allow(unused)]
fn main() {
use crate::stats;
}

引入整个 stats 模块。因此调用时写：

#![allow(unused)]
fn main() {
stats::average_score(students)
stats::passing_names(students)
stats::score_map(students)
}

也可以写成：

use crate::stats::{average_score, passing_names, score_map};

然后直接调用函数名。当前保留 stats::... 是为了让函数来源更清楚。

8. 嵌套模块：目录 + mod.rs

Day 11 第二层加入了嵌套模块：

src/formatters/
  mod.rs
  text.rs
  table.rs

在 src/lib.rs 中声明：

#![allow(unused)]
fn main() {
pub mod formatters;
}

Rust 会去找：

src/formatters.rs

或者：

src/formatters/mod.rs

本项目使用的是：

src/formatters/mod.rs

8.1 formatters/mod.rs

#![allow(unused)]
fn main() {
pub mod text;

mod table;

pub use table::print_score_table;
}

含义：

pub mod text;
    声明 text 子模块，并且让外部可以访问 formatters::text。

mod table;
    声明 table 子模块，但 table 模块本身不对外公开。

pub use table::print_score_table;
    把 table 模块里的 print_score_table 重新导出为 formatters::print_score_table。

9. pub use：re-export

pub use 叫重新导出。

#![allow(unused)]
fn main() {
pub use table::print_score_table;
}

让外部可以写：

formatters::print_score_table(&students);

而不是：

formatters::table::print_score_table(&students);

而且因为 table 是 private：

#![allow(unused)]
fn main() {
mod table;
}

外部本来就不能访问：

formatters::table

这是一种常见 API 设计：

内部文件如何拆，是实现细节；
外部只看到干净的公开接口。

10. formatters/text.rs

#![allow(unused)]
fn main() {
use crate::student::Student;

pub fn format_student_line(student: &Student) -> String {
    let status = if student.is_passing() { "PASS" } else { "FAIL" };
    format!("{}: {} ({})", student.name, student.score(), status)
}

pub fn print_student_lines(students: &[Student]) {
    for student in students {
        println!("{}", format_student_line(student));
    }
}
}

因为在 formatters/mod.rs 中写了：

#![allow(unused)]
fn main() {
pub mod text;
}

所以外部可以调用：

formatters::text::print_student_lines(&students);

11. formatters/table.rs 与 super::

#![allow(unused)]
fn main() {
use crate::student::Student;

use super::text::format_student_line;

pub fn print_score_table(students: &[Student]) {
    println!("Name   | Score | Status");
    println!("-------|-------|--------");

    for student in students {
        println!("{}", format_table_row(student));
    }
}

fn format_table_row(student: &Student) -> String {
    let status = if student.is_passing() { "PASS" } else { "FAIL" };
    format!("{:<6} | {:>5} | {}", student.name, student.score(), status)
}

#[allow(dead_code)]
fn debug_line_from_sibling_module(student: &Student) -> String {
    format_student_line(student)
}
}

当前模块是：

crate::formatters::table

父模块是：

crate::formatters

所以：

#![allow(unused)]
fn main() {
use super::text::format_student_line;
}

表示：

从父模块 formatters 出发，找到兄弟模块 text，再找到 format_student_line。

等价于：

use crate::formatters::text::format_student_line;

在同一组子模块内部，用 super:: 很常见。

12. src/lib.rs：library crate 根部

最终项目加入了 src/lib.rs：

#![allow(unused)]
fn main() {
pub mod formatters;
pub mod parser;
pub mod report;
pub mod stats;
pub mod student;

pub use parser::{parse_student, parse_students};
pub use student::{sample_students, Student};
}

这表示当前 package 现在同时有：

src/lib.rs  -> library crate
src/main.rs -> binary crate

lib.rs 承载可复用的业务逻辑和模块树。

main.rs 作为可执行程序入口，负责调用 library 逻辑。

真实 Rust 项目常见组织方式：

业务逻辑放 lib.rs 及其子模块；
main.rs 尽量薄，只负责启动、读参数、调用逻辑、打印结果。

12.1 pub mod in lib.rs

#![allow(unused)]
fn main() {
pub mod parser;
}

表示：

声明 parser 模块，对应 src/parser.rs；
并且让外部能访问 day11_modules::parser。

如果写成：

mod parser;

则 parser 只对 library 内部可见，外部不能写：

day11_modules::parser::parse_students

但如果仍然有：

pub use parser::parse_students;

外部仍然可以通过重新导出的路径访问：

day11_modules::parse_students

这说明可以隐藏内部模块结构，只暴露希望用户使用的 API。

12.2 pub use in lib.rs

#![allow(unused)]
fn main() {
pub use parser::{parse_student, parse_students};
pub use student::{sample_students, Student};
}

让外部除了写：

day11_modules::parser::parse_students
day11_modules::student::Student

还可以写：

day11_modules::parse_students
day11_modules::Student

这就是 re-export 的价值：

内部按模块组织；
外部暴露更顺手的入口。

13. src/main.rs：binary crate 入口

最终 src/main.rs：

use day11_modules::formatters;
use day11_modules::parser::parse_students;
use day11_modules::report;
use day11_modules::student::sample_students;

fn main() {
    println!("== 1. Use modules from separate files ==");

    let students = sample_students();
    report::print_summary(&students);

    println!("\n== 2. Parse students from text ==");

    let text = "Alice,95\nBob,67\nCarol,88\n\nDavid,52\n";

    match parse_students(text) {
        Ok(parsed_students) => report::print_summary(&parsed_students),
        Err(error) => println!("failed to parse students: {error}"),
    }

    println!("\n== 3. Parse bad input and show error ==");

    let bad_text = "Alice,95\nbad line\nCarol,88\n";

    match parse_students(bad_text) {
        Ok(parsed_students) => report::print_summary(&parsed_students),
        Err(error) => println!("failed to parse students: {error}"),
    }

    println!("\n== 4. Nested modules and re-export ==");
    formatters::text::print_student_lines(&students);

    println!("\n== 5. Private child module with public re-export ==");
    formatters::print_score_table(&students);
}

注意这里使用的是：

#![allow(unused)]
fn main() {
use day11_modules::parser::parse_students;
}

而不是：

use crate::parser::parse_students;

原因是：

main.rs 是 binary crate 的 crate root。
lib.rs 是 library crate 的 crate root。

它们虽然在同一个 package 里，但属于两个 crate。

main.rs 使用 lib.rs 暴露出的 library，就像使用一个外部 crate 一样，通过 package/crate 名字访问：

#![allow(unused)]
fn main() {
day11_modules::...
}

这个名字来自 Cargo.toml：

[package]
name = "day11_modules"

14. crate:: 在 lib.rs 模块里指向谁

在 parser.rs、stats.rs、report.rs 中仍然可以写：

#![allow(unused)]
fn main() {
use crate::student::Student;
}

因为这些文件现在是通过 lib.rs 挂进模块树的：

#![allow(unused)]
fn main() {
pub mod parser;
pub mod stats;
pub mod report;
pub mod student;
}

所以在这些模块里：

crate:: 指向 library crate 根部，也就是 src/lib.rs。

因此：

#![allow(unused)]
fn main() {
crate::student::Student
}

表示从 lib.rs 根部找到 student::Student。

15. 为什么 cargo test 会同时测试 lib.rs 和 main.rs

加入 src/lib.rs 后，运行：

cargo test

会看到类似：

Running unittests src/lib.rs
running 5 tests
...

Running unittests src/main.rs
running 0 tests
...

原因是当前 package 里有两个 crate：

library crate: src/lib.rs
binary crate:  src/main.rs

测试主要放在 parser.rs 和 stats.rs 中，而它们属于 library crate，所以测试出现在：

Running unittests src/lib.rs

main.rs 中没有测试，所以显示 0 tests。

18. 常见问题小结

18.1 删除 mod parser; 会怎样？

如果父模块不声明 mod parser;，Rust 就不会把 parser.rs 加入模块树。即使文件存在，crate::parser 也不存在。

18.2 删除 pub struct Student 会怎样？

Student 会变成只在 student 模块内部可见。兄弟模块无法使用 crate::student::Student。

18.3 为什么 score 字段不是 pub，但能通过 score() 读取？

因为字段 private，但方法 public。方法定义在同一模块内部，可以访问 private 字段；外部只能调用 public 方法。

18.4 crate::student::Student 和 super::* 区别是什么？

crate:: 从当前 crate 根部开始找。
super:: 从当前模块的父模块开始找。

use super::* 常用于测试子模块，把父模块里的可见项引入测试模块。

18.5 为什么 #[cfg(test)] mod tests 不影响 cargo run？

因为 #[cfg(test)] 表示这段代码只在 cargo test 时编译。

今日总结

Day 11 的核心地图：

概念关键点
mod声明模块，把文件挂到模块树上
pub控制外部可见性
use引入路径，减少长路径重复
crate::从当前 crate 根部找
super::从父模块找
pub mod模块本身对外公开
pub fn / pub structitem 对外公开
私有字段struct 即使 pub，字段也不会自动公开
pub use重新导出 API，隐藏内部路径
#[cfg(test)]只在测试时编译
lib.rslibrary crate 根部，组织可复用业务逻辑
main.rsbinary crate 入口，负责启动和调用逻辑

一句话总结：

mod 负责组织代码在哪里；pub 负责决定外部能看见什么；lib.rs 负责沉淀可复用逻辑；main.rs 负责把程序跑起来。
