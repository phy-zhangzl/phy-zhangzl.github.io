1. trait 是什么

trait 可以理解为“某种能力”或“某套接口约定”。

例如：

#![allow(unused)]
fn main() {
trait Summary {
    fn summarize(&self) -> String;

    fn label(&self) -> String {
        format!("[Summary] {}", self.summarize())
    }
}
}

这里定义了一个 Summary trait，表示实现者必须具备：

summarize() -> String

这个能力。

其中：

#![allow(unused)]
fn main() {
fn summarize(&self) -> String;
}

没有函数体，表示实现者必须自己提供实现。

而：

#![allow(unused)]
fn main() {
fn label(&self) -> String {
    format!("[Summary] {}", self.summarize())
}
}

有默认实现。只要类型实现了 summarize()，就自动得到 label()。

2. 为具体类型实现 trait

先定义两个具体类型：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone)]
struct Student {
    name: String,
    score: i32,
}

#[derive(Debug)]
struct Course {
    title: String,
    credits: u32,
}
}

然后分别实现 Summary：

#![allow(unused)]
fn main() {
impl Summary for Student {
    fn summarize(&self) -> String {
        format!("{} scored {}", self.name, self.score)
    }
}

impl Summary for Course {
    fn summarize(&self) -> String {
        format!("{} ({} credits)", self.title, self.credits)
    }
}
}

含义是：

Student 拥有 Summary 能力。
Course 也拥有 Summary 能力。

所以可以调用：

#[derive(Debug, Clone)]
struct Student { name: String, score: i32 }
#[derive(Debug)]
struct Course { title: String, credits: u32 }
trait Summary {
    fn summarize(&self) -> String;
    fn label(&self) -> String { format!("[Summary] {}", self.summarize()) }
}
impl Summary for Student {
    fn summarize(&self) -> String { format!("{} scored {}", self.name, self.score) }
}
impl Summary for Course {
    fn summarize(&self) -> String { format!("{} ({} credits)", self.title, self.credits) }
}
fn main() {
    let alice = Student {
        name: String::from("Alice"),
        score: 95,
    };

    let rust_course = Course {
        title: String::from("Rust 101"),
        credits: 3,
    };

    println!("{}", alice.summarize());
    println!("{}", rust_course.summarize());
    println!("{}", alice.label());
}

输出类似：

Alice scored 95
Rust 101 (3 credits)
[Summary] Alice scored 95

3. Rust 中几种常见的 impl

impl 在 Rust 里有几种语境。

3.1 固有实现：impl Student

impl Student {
    fn new(name: &str, score: i32) -> Self {
        Self {
            name: name.to_string(),
            score,
        }
    }
}

这是给 Student 本身定义方法，不涉及 trait。

3.2 trait 实现：impl Summary for Student

impl Summary for Student {
    fn summarize(&self) -> String {
        format!("{} scored {}", self.name, self.score)
    }
}

这是让 Student 实现 Summary 这套能力。

3.3 参数位置的 impl Trait

fn print_summary(item: &impl Summary) {
    println!("{}", item.summarize());
}

表示：

参数 item 可以是任何实现了 Summary 的类型。

它接近于：

fn print_summary<T: Summary>(item: &T) {
    println!("{}", item.summarize());
}

3.4 返回位置的 impl Trait

fn make_default_student() -> impl Summary {
    Student {
        name: String::from("Generated Student"),
        score: 76,
    }
}

表示：

这个函数返回某个实现了 Summary 的固定具体类型，但把具体类型名隐藏起来。

注意：返回 impl Trait 不是“可以随便返回任意实现该 trait 的类型”。所有返回路径必须返回同一个具体类型。

4. impl Trait 参数 vs 命名泛型 T

单参数时：

fn print_summary(item: &impl Summary)

和：

fn print_summary_generic<T: Summary>(item: &T)

非常接近。

但多个参数时有重要区别。

fn print_two_summaries_impl(left: &impl Summary, right: &impl Summary) {
    println!("left = {}", left.summarize());
    println!("right = {}", right.summarize());
}

这个函数的两个参数可以是不同具体类型，只要都实现了 Summary。

例如可以传：

print_two_summaries_impl(&alice, &rust_course);

而：

fn print_two_summaries_same_type<T: Summary>(left: &T, right: &T) {
    println!("left same-type = {}", left.summarize());
    println!("right same-type = {}", right.summarize());
}

这里两个参数共享同一个 T，所以必须是同一个具体类型。

可以：

print_two_summaries_same_type(&alice, &bob);

但不能：

print_two_summaries_same_type(&alice, &rust_course);

典型报错：

error[E0308]: mismatched types
expected `&Student`, found `&Course`

原因是编译器先从 &alice 推断：

T = Student

于是第二个参数也必须是 &Student。

5. 多个 trait bound 与 where

可以要求一个类型同时具备多种能力：

fn print_debug_summary<T: std::fmt::Debug + Summary>(item: &T) {
    println!("debug + summary = {:?} => {}", item, item.summarize());
}

这里：

T: std::fmt::Debug + Summary

表示：

T 必须同时实现 Debug 和 Summary。

当约束变长时，可以使用 where：

fn print_debug_summary_where<T>(item: &T)
where
    T: std::fmt::Debug + Summary,
{
    println!("where version = {:?} => {}", item, item.summarize());
}

这和上面的含义相同，只是更适合复杂签名。

6. 返回 impl Trait 与 Box<dyn Trait>

返回 impl Trait：

fn make_default_student() -> impl Summary {
    Student {
        name: String::from("Generated Student"),
        score: 76,
    }
}

特点：

静态分发；
具体类型固定；
只是隐藏具体类型名。

下面这种不能编译：

fn choose_summary_impl(use_student: bool) -> impl Summary {
    if use_student {
        Student {
            name: String::from("Generated Student"),
            score: 76,
        }
    } else {
        Course {
            title: String::from("Generated Course"),
            credits: 2,
        }
    }
}

因为 if 分支返回 Student，else 分支返回 Course。

编译器会提示：

if and else have incompatible types
expected `Student`, found `Course`

如果确实需要在不同分支返回不同具体类型，可以使用 trait object：

fn choose_summary(use_student: bool) -> Box<dyn Summary> {
    if use_student {
        Box::new(Student {
            name: String::from("Boxed Alice"),
            score: 91,
        })
    } else {
        Box::new(Course {
            title: String::from("Rust Systems"),
            credits: 4,
        })
    }
}

Box<dyn Summary> 的特点：

动态分发；
可以隐藏不同具体类型；
通过 Box 指针间接存放；
有少量运行时成本。

对比：

写法真实类型是否固定是否动态分发不同分支能否返回不同具体类型
-> Student固定为 Student否否
-> impl Summary固定，但名字隐藏否否
-> Box<dyn Summary>不固定是是

7. Self 与 trait 关联函数

定义一个“能构造示例值”的 trait：

trait BuildExample {
    fn example() -> Self;
}

这里 Self 表示：

当前实现这个 trait 的具体类型。

为 Student 实现：

impl BuildExample for Student {
    fn example() -> Self {
        Self {
            name: String::from("Example Student"),
            score: 89,
        }
    }
}

这里 Self 就是 Student。

为 Course 实现：

impl BuildExample for Course {
    fn example() -> Self {
        Self {
            title: String::from("Example Course"),
            credits: 2,
        }
    }
}

这里 Self 就是 Course。

可以写泛型构造函数：

fn make_example<T: BuildExample>() -> T {
    T::example()
}

使用：

let example_student: Student = make_example();
let example_course: Course = make_example();
let explicit_student = make_example::<Student>();

因为 make_example() 没有参数，所以编译器不能从参数推断 T。需要通过左侧类型标注或 turbofish 指定：

make_example::<Student>()

8. Self vs self

写法含义
Self当前类型
self当前值，拿走所有权
&self不可变借用当前值
&mut self可变借用当前值

例如：

fn example() -> Self

返回当前类型。

fn summarize(&self) -> String

不可变借用当前值。

9. 泛型 struct 上的 trait bound

可以定义一个只接收 Summary 元素的报告类型：

struct SummaryReport<T: Summary> {
    title: String,
    items: Vec<T>,
}

impl<T: Summary> SummaryReport<T> {
    fn new(title: &str, items: Vec<T>) -> Self {
        Self {
            title: title.to_string(),
            items,
        }
    }

    fn print(&self) {
        println!("-- {} --", self.title);
        for item in &self.items {
            println!("{}", item.summarize());
        }
    }
}

这里：

T: Summary

表示 SummaryReport<T> 里的 T 必须实现 Summary，因为 print() 里需要调用：

item.summarize()

使用：

let student_report = SummaryReport::new("Student report", vec![alice.clone(), bob.clone()]);
student_report.print();

此时：

T = Student

也可以：

let course_report = SummaryReport::new(
    "Course report",
    vec![Course {
        title: String::from("Traits Lab"),
        credits: 1,
    }],
);
course_report.print();

此时：

T = Course

注意：Vec<T> 是同质容器。同一个 SummaryReport<T> 里不能直接混放 Student 和 Course。如果需要混放，要使用类似 Vec<Box<dyn Summary>> 的形式。

10. 关联类型：I::Item

IntoIterator 是标准库中的 trait，表示：

某个类型可以被转换成 iterator。

它有一个关联类型 Item，表示迭代出来的元素类型。

例如：

fn print_debug_items<I>(items: I)
where
    I: IntoIterator,
    I::Item: std::fmt::Debug,
{
    for item in items {
        println!("item = {:?}", item);
    }
}

这里：

I::Item

表示：

I 被迭代时产生的元素类型。

所以：

I::Item: std::fmt::Debug

意思是：

迭代出来的每个元素都必须支持 Debug 打印。

可以调用：

print_debug_items(vec![10, 20, 30]);
print_debug_items(["rust", "trait", "generic"]);

11. dyn Trait 与 dyn compatibility

不是所有 trait 都适合做 dyn Trait。

可以做 trait object 的例子：

trait Named {
    fn name(&self) -> &str;

    fn display_name(&self) -> String {
        format!("name = {}", self.name())
    }
}

为 Student 和 Course 实现：

impl Named for Student {
    fn name(&self) -> &str {
        &self.name
    }
}

impl Named for Course {
    fn name(&self) -> &str {
        &self.title
    }
}

可以使用：

let named_items: Vec<&dyn Named> = vec![&alice, &rust_course];

因为 Named 的方法不要求调用者知道具体类型。

不适合 trait object 的例子：

trait DuplicateValue {
    fn duplicate_value(&self) -> Self;
}

这个方法返回 Self。如果只有 &dyn DuplicateValue，调用者不知道背后具体类型是 Student、Course 还是别的类型，所以这种 trait 不适合直接做 dyn Trait 调用。

直觉：

如果 dyn Trait 把具体类型藏起来，那么 trait 的方法就不能要求调用者知道这个具体类型。

因此返回 Self、泛型方法、无 self 的构造函数等，常常更适合泛型约束，而不是 trait object。

12. closure 与 Fn / FnMut / FnOnce

closure 能传给函数，是因为 closure 类型会自动实现 Fn / FnMut / FnOnce 这些 trait。

12.1 Fn

fn call_read_twice<F>(f: F)
where
    F: Fn() -> i32,
{
    println!("first read call = {}", f());
    println!("second read call = {}", f());
}

只读捕获可以满足 Fn：

let base = 100;
let read_base = || base + 1;
call_read_twice(read_base);

12.2 FnMut

fn call_mut_twice<F>(mut f: F)
where
    F: FnMut() -> i32,
{
    println!("first mutable call = {}", f());
    println!("second mutable call = {}", f());
}

修改捕获变量需要 FnMut：

let mut counter = 0;
let next_count = || {
    counter += 1;
    counter
};
call_mut_twice(next_count);

12.3 FnOnce

fn call_once<F>(f: F)
where
    F: FnOnce() -> String,
{
    println!("one-time call = {}", f());
}

消耗捕获变量需要 FnOnce：

let message = String::from("owned message moved into closure");
let consume_message = || message;
call_once(consume_message);

判断规则：

closure 行为通常实现
只读捕获，不修改，不消耗Fn
修改捕获变量FnMut
消耗捕获变量所有权FnOnce

关系：

Fn 可以当 FnMut / FnOnce 用。
FnMut 可以当 FnOnce 用。
FnOnce 不一定能当 FnMut / Fn 用。

注意：返回 String 不一定是 FnOnce。关键看是否 move 出捕获值。

let greeting = String::from("hello");
let clone_greeting = || greeting.clone();

这里每次 clone 一份新 String，没有消耗 greeting 本体，所以可以调用多次。

13. Display 与 Debug

Debug 用于开发者调试：

println!("{:?}", value);

Display 用于用户友好展示：

println!("{}", value);

为 Student 实现 Display：

impl std::fmt::Display for Student {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{} [{}]", self.name, self.score)
    }
}

为 Course 实现 Display：

impl std::fmt::Display for Course {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{} ({} credits)", self.title, self.credits)
    }
}

对比：

trait格式符目标是否常见 derive
Debug{:?}给开发者调试可以 derive
Display{}给用户阅读通常手写

14. From 与 Into

实现：

impl From<(&str, i32)> for Student {
    fn from(value: (&str, i32)) -> Self {
        let (name, score) = value;
        Self {
            name: name.to_string(),
            score,
        }
    }
}

使用：

let from_tuple = Student::from(("From Tuple", 88));
let into_student: Student = ("Into Tuple", 79).into();

通常优先实现 From<A> for B，因为标准库会自动提供对应的 Into<B> for A。

.into() 往往需要上下文告诉编译器目标类型：

let into_student: Student = ("Into Tuple", 79).into();

15. Default

实现默认值：

impl Default for Student {
    fn default() -> Self {
        Self {
            name: String::from("Unnamed"),
            score: 0,
        }
    }
}

泛型函数：

fn make_default_value<T: Default>() -> T {
    T::default()
}

使用：

let default_student: Student = make_default_value();

Default 常用于配置结构体：

let config = TrainConfig {
    lr: 1e-4,
    ..Default::default()
};

16. Iterator 与 IntoIterator

Iterator 表示“迭代器本体”，核心方法类似：

fn next(&mut self) -> Option<Self::Item>;

IntoIterator 表示“可以被转换成迭代器”。for 循环本质上依赖 IntoIterator。

更精确的关联类型约束：

fn total_numbers<I>(items: I) -> i32
where
    I: IntoIterator<Item = i32>,
{
    items.into_iter().sum()
}

这里：

I: IntoIterator<Item = i32>

表示：

I 必须可以被迭代，并且迭代出来的元素类型必须正好是 i32。

调用：

let total = total_numbers([1, 2, 3, 4]);
println!("total numbers = {total}");

今日总结

Day 12 的核心地图：

概念关键点
trait表达能力 / 行为 / 接口约束
impl Trait for Type为具体类型实现某种能力
默认方法trait 方法可以提供默认实现
T: Trait泛型类型必须满足 trait bound
impl Trait 参数接受某个实现 trait 的参数，常作为泛型简写
命名泛型 T可以表达多个参数必须同一类型
where更清晰地写复杂 trait bound
返回 impl Trait返回固定但隐藏名字的具体类型
dyn Trait运行时多态，隐藏具体类型并动态分发
Self当前实现类型
关联类型trait 中依赖实现者确定的类型，如 I::Item
Fn / FnMut / FnOnceclosure 的调用能力 trait
标准库 traitRust 生态中通用能力约定

一句话总结：

Rust 的泛型不是“什么都能传”，而是“任何满足 trait bound 的类型都能传”。
