当前练习代码核心

#![allow(unused)]
fn main() {
fn max_number(nums: &[i32]) -> i32 {
    let mut max = nums[0];

    for &x in nums {
        if x > max {
            max = x;
        }
    }

    max
}
}

含义：

  • nums: &[i32]：参数名是 nums，类型是 &[i32]，即“借用一段 i32 序列”。
  • -> i32：函数返回一个 i32。
  • let mut max：max 是可变变量，因为后续要更新最大值。
  • 函数最后的 max 没有分号，表示作为返回值。

let 和 mut

Rust 变量默认不可变：

#![allow(unused)]
fn main() {
let ans = 8;
ans = 100; // 编译错误
}

如果需要修改，需要写：

#![allow(unused)]
fn main() {
let mut ans = 8;
ans = 100;
}

判断原则：

  • 如果一个变量代表“会逐步变化的状态”，用 mut。
  • 如果只是值转换，优先考虑 shadowing。

Shadowing

Rust 允许重新绑定同名变量：

#![allow(unused)]
fn main() {
let input = "42";
let input: i32 = input.parse().unwrap();
}

这不是修改原变量，而是创建一个新的同名变量，遮住旧变量。

合理使用场景：

  • 原始字符串转换成数字
  • 原始配置转换成结构体
  • trim 后再 parse

不合理例子：

#![allow(unused)]
fn main() {
let ans = max_number(&nums);
let ans = 100;
}

如果第一个 ans 没被使用，编译器会 warning：

warning: unused variable: `ans`

Rust 类型含义
i3232 位有符号整数，整数默认常见推断类型

#![allow(unused)]

let b = 3.14;            // f64

}

Vec<i32> 和 vec![]

  • Vec<i32> 是类型，表示“装 i32 的动态数组”。
  • vec![1, 2, 3] 是创建 Vec 的宏。

! 表示宏 macro，例如：

#![allow(unused)]
fn main() {
println!("hello");
vec![1, 2, 3];
dbg!(x);
format!("x = {}", x);
}

宏可以理解为“编译期展开代码的工具”。

&[i32] 和 &nums

函数参数：

#![allow(unused)]
fn main() {
fn max_number(nums: &[i32]) -> i32
}

表示函数只借用一段整数序列，不拿走所有权。

调用时：

#![allow(unused)]
fn main() {
let nums = vec![3, 1, 8, 2, 5];
let ans = max_number(&nums);
}

&nums 表示“借用 nums”。

粗略类比 C++：

int max_number(const std::vector<int>& nums)

更底层类比：

int max_number(const int* nums, size_t len)

区别是 Rust 的切片引用 &[i32] 自带长度，并受借用规则保护。

println! 的 {} 和 {:?}

讲解片段：

#![allow(unused)]
fn main() {
println!("name = {}", name);
println!("numbers = {:?}", nums);
}

这里假设前面已经定义了：

#![allow(unused)]
fn main() {
let name = "rust";
let nums = vec![1, 2, 3];
}

可运行示例：

fn main() {
    let name = "rust";
    let nums = vec![1, 2, 3];

    println!("name = {}", name);
    println!("numbers = {:?}", nums);
}
  • {} 使用 Display，适合普通展示。
  • {:?} 使用 Debug，适合调试输出。

基础类型如 i32、f64、bool、char、&str 通常可以用 {}。

Vec<i32> 通常不能用 {}，要用 {:?}：

#![allow(unused)]
fn main() {
println!("numbers = {:?}", nums);
}

如果要测试 Vec<i32> 不能用 {} 打印，应该使用完整实验代码：

fn main() {
    let nums = vec![1, 2, 3];

    println!("numbers = {}", nums);
}

这时会看到类似错误：

`Vec<{integer}>` doesn't implement `std::fmt::Display`

如果只运行下面这一行：

#![allow(unused)]
fn main() {
println!("numbers = {}", nums);
}

但没有定义 nums，则会先看到另一个错误：

error[E0425]: cannot find value `nums` in this scope

这个错误的原因是变量不存在，而不是 {} / {:?} 的问题。

实验 1：{} vs {:?}

把：

}

改成：

fn main() {

  • Vec<i32> 通常没有 Display。
  • Vec<i32> 实现了 Debug，所以调试打印用 {:?}。

实验 2：&nums vs nums

函数签名：

#![allow(unused)]
fn main() {
fn max_number(nums: &[i32]) -> i32
}

调用应该是：

#![allow(unused)]
fn main() {
let ans = max_number(&nums);
}

如果写成：

#![allow(unused)]
fn main() {
let ans = max_number(nums);
}

会触发类型不匹配。核心原因：

  • 函数需要 &[i32]，即借用一段 i32 序列。
  • nums 本身是 Vec<i32>。
  • &nums 可以借用 Vec<i32>，并转换成切片引用 &[i32]。

这类报错重点看三块：

expected ...  # 编译器期望的类型
found ...     # 实际传入的类型
help ...      # 编译器建议的修复方式

1. i32：赋值时 Copy

可运行示例：

fn main() {
    let x = 10;
    let y = x;

    println!("x = {}", x);
    println!("y = {}", y);
}

输出：

x = 10
y = 10

这里 let y = x; 会把 x 的值复制一份给 y。

原因是 i32 实现了 Copy。对于 i32、bool、char、浮点数等简单类型，复制成本低，Rust 允许自动复制。

关键点：

let y = x;

不是修改 x，而是用 x 初始化一个新变量 y。

2. String：赋值时 Move

错误实验：

fn main() {
    let s = String::from("hello");
    let t = s;

    println!("s = {}", s);
    println!("t = {}", t);
}

编译错误核心：

error[E0382]: borrow of moved value: `s`

move occurs because `s` has type `String`, which does not implement the `Copy` trait
value moved here
value borrowed here after move

解释：

#![allow(unused)]
fn main() {
let t = s;
}

这句会把 s 的所有权移动给 t。之后：

t 有效
s 失效

所以后面再打印 s 会报错。

可以运行的 move 版本：

fn main() {
    let s = String::from("hello");
    let t = s;

    println!("t = {}", t);
}

这里没有再使用 s，所以没有问题。

3. 为什么 String 不默认 Copy？

String 管理堆内存。可以粗略理解成：

String {
    ptr,
    len,
    capacity,
}

如果 Rust 默认复制这三个字段，就可能出现两个 String 指向同一块堆内存。离开作用域时，两者都想释放同一块内存，可能造成 double free。

Rust 的选择是：

默认 move 所有权，不默认深拷贝堆数据。

这也是 Rust 的性能哲学：

便宜的复制可以自动发生。
昂贵的复制必须显式写出来。

4. clone()：显式深拷贝

如果确实希望 s 和 t 都拥有一份字符串内容，可以使用 clone()。

可运行示例：

fn main() {
    let s = String::from("hello");
    let t = s.clone();

    println!("s = {}", s);
    println!("t = {}", t);
}

含义：

s 保留原字符串
t 得到一份新的字符串拷贝

代价：

额外分配内存
复制字符串内容

看到 .clone() 时，要逐渐养成一个习惯：

这里真的需要复制吗？能不能改成借用？

初学阶段不必害怕 clone()，但要知道它不是免费的。

5. 函数传参也可能 Move

错误实验：

fn take_ownership(s: String) {
    println!("inside function: {}", s);
}

fn main() {
    let s = String::from("hello");

    take_ownership(s);

    println!("after function: {}", s);
}

这里：

#![allow(unused)]
fn main() {
take_ownership(s);
}

会把 main 里的 s 移动到函数参数 s。

可以理解成：

main::s -> take_ownership::s

函数结束时，函数参数 s 离开作用域，字符串被释放。回到 main 后，原来的 s 已经失效。

6. 只读借用：&str

如果函数只是读字符串，不需要拿走所有权，应该使用借用。

可运行示例：

fn read_string(s: &str) {
    println!("inside function: {}", s);
}

fn main() {
    let s = String::from("hello");

    read_string(&s);

    println!("after function: {}", s);
}

输出：

inside function: hello
after function: hello

这里 read_string(&s) 只是借用 s，不拿走所有权，所以函数调用后 s 仍然可用。

为什么用 &str 而不是 &String？

&String 可以用，但 &str 更通用。

#![allow(unused)]
fn main() {
fn read_string(s: &str)
}

既可以接收：

#![allow(unused)]
fn main() {
let s = String::from("hello");
read_string(&s);
}

也可以接收：

#![allow(unused)]
fn main() {
read_string("hello");
}

所以只读字符串时，优先考虑 &str。

7. 可变借用：&mut String

如果函数要修改原字符串，需要可变借用。

可运行示例：

fn add_suffix(s: &mut String) {
    s.push_str(" world");
}

fn main() {
    let mut s = String::from("hello");

    add_suffix(&mut s);

    println!("s = {}", s);
}

输出：

s = hello world

这里有三处要对应：

#![allow(unused)]
fn main() {
let mut s = String::from("hello"); // 变量本身允许被修改
fn add_suffix(s: &mut String)       // 函数接收可变引用
add_suffix(&mut s);                 // 调用时传可变借用
}

如果变量没有声明为 mut：

#![allow(unused)]
fn main() {
let s = String::from("hello");
add_suffix(&mut s);
}

会报错，核心意思是：

cannot borrow `s` as mutable, as it is not declared as mutable

8. 可变借用是独占的

错误实验：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    println!("s = {}", s);
    println!("r = {}", r);
}

这里不允许，因为 r 是对 s 的可变借用，而且后面还要继续使用 r。

核心规则：

可变借用存在期间，不能同时通过原变量或其他引用访问同一份数据。

更口语化：

借给 r 改的时候，就别同时从 s 这边插手。
等 r 用完了，再回到 s。

可运行修复版本：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;
    r.push_str(" world");
    println!("r = {}", r);

    println!("s = {}", s);
}

这里 r 最后一次使用在：

#![allow(unused)]
fn main() {
println!("r = {}", r);
}

之后借用结束，所以可以继续使用 s。

也可以用作用域明确结束借用：

fn main() {
    let mut s = String::from("hello");

    {
        let r = &mut s;
        r.push_str(" world");
        println!("r = {}", r);
    }

    println!("s = {}", s);
}

9. 所有权地图：传值、借用、可变借用

Rust 里函数参数设计可以先用这张地图理解：

函数想做什么参数类型调用方式数据归属
拿走整数等 Copy 值i32f(x)复制一份，原值还可用
拿走堆数据Stringf(s)move 所有权，原变量失效
只读字符串&strf(&s) 或 f("hi")借用，不拿走
修改原字符串&mut Stringf(&mut s)可变借用，独占修改
只读数组/Vec 内容&[T]f(&nums)借用一段连续数据

今天先记住三个最核心的：

传 String：把所有权交出去。
传 &str：借给函数看一下。
传 &mut String：借给函数改一下。

参数选择的初步原则

如果你在写一个函数，可以先问：

1. 函数是否需要拥有这个值？
   - 需要：传 `T`，例如 `String`。
   - 不需要：传引用。

2. 函数是否需要修改调用者的数据？
   - 需要：传 `&mut T`。
   - 不需要：传 `&T`、`&str` 或 `&[T]`。

3. 这个参数是不是字符串？
   - 只读字符串优先用 `&str`。

4. 这个参数是不是数组/Vec？
   - 只读一段连续数据优先用 `&[T]`。

这不是最终完整规则，但足够支撑第一轮 Rust 学习。

10. Copy、Move、Clone、Borrow 的关系

可以把今天学的四个词放在一起：

词含义典型例子
Copy便宜复制，赋值后原变量还能用i32, bool, char, f64
Move所有权转移，原变量失效String, Vec<T>
Clone显式深拷贝或自定义复制s.clone()
Borrow借用，不拿走所有权&s, &mut s

它们解决的是同一个问题：

数据到底怎么在程序中流动？

Rust 不希望昂贵复制偷偷发生，所以：

小值可以 Copy。
堆数据默认 Move。
真的要复制就 Clone。
只是用一下就 Borrow。

11. 和 C++ 的关键区别

C++ 中：

void f(std::string s);

调用：

std::string name = "hello";
f(name);

通常是拷贝一份，name 还能用。

Rust 中：

#![allow(unused)]
fn main() {
fn f(s: String) {}

let name = String::from("hello");
f(name);
}

默认是 move，name 之后不能再用。

如果 Rust 想复制，要显式写：

#![allow(unused)]
fn main() {
f(name.clone());
}

如果只是读，要写：

#![allow(unused)]
fn main() {
f(&name);
}

1. 借用规则的核心模型

Day 2 已经学过：

#![allow(unused)]
fn main() {
let r = &mut s;
}

可以理解为：

r 是指向 s 的可变引用。
s 仍然拥有数据。
r 临时、独占地借用 s，并可以通过 r 修改 s。

Rust 的借用规则可以先记成一句话：

同一份数据：可以有多个只读引用，或者有一个可变引用，但二者不能重叠。

也就是常说的：

many readers OR one writer
多个读者，或者一个写者

2. 多个只读引用可以共存

完整示例：

fn main() {
    let s = String::from("hello");

    let r1 = &s;
    let r2 = &s;

    println!("r1 = {}", r1);
    println!("r2 = {}", r2);
    println!("s = {}", s);
}

这段代码可以正常通过。

原因是：

r1 和 r2 都只是读，不会修改数据。
多个只读引用同时存在是安全的。

可以类比成：

很多人同时看同一本书：可以。

3. 可变引用可以修改原数据

完整示例：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    r.push_str(" world");

    println!("r = {}", r);
}

这里有两处要区分：

#![allow(unused)]
fn main() {
let mut s = String::from("hello");
}

表示变量 s 绑定的值允许被修改。

#![allow(unused)]
fn main() {
let r = &mut s;
}

表示创建一个对 s 的可变引用。

r 不是 owner，s 才是 owner；但是在借用期间，r 可以修改 s 拥有的那份字符串。

4. 可变引用存在时不能同时使用原变量

错误示例：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;

    println!("s = {}", s);
    println!("r = {}", r);
}

典型错误信息类似：

cannot borrow `s` as immutable because it is also borrowed as mutable
mutable borrow occurs here
immutable borrow occurs here
mutable borrow later used here

原因是：

r 还要继续使用，所以 r 对 s 的可变借用还没有结束。
在这段时间里，不能再通过 s 访问同一份数据。

可以类比成：

书已经被一个人拿去修改批注了，在他还没还之前，别人不能同时拿这本书读。

5. 引用通常活到最后一次使用

下面这个版本可以通过：

fn main() {
    let mut s = String::from("hello");

    let r = &mut s;
    r.push_str(" world");
    println!("r = {}", r);

    println!("s = {}", s);
}

原因是：

#![allow(unused)]
fn main() {
println!("r = {}", r);
}

是 r 的最后一次使用。之后可变借用结束，所以可以重新使用 s。

现代 Rust 的引用作用域通常不是简单地持续到代码块结尾，而是到最后一次使用为止。这叫：

NLL: Non-Lexical Lifetimes
非词法生命周期

初学阶段不需要深入生命周期语法，只需要记住：

引用通常活到最后一次使用。
最后一次使用之后，原变量可以重新被使用。

6. 只读引用和可变引用不能重叠

可以先只读，再可变，只要只读引用后面不再使用：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    println!("r1 = {}", r1);

    let r2 = &mut s;
    r2.push_str(" world");

    println!("r2 = {}", r2);
}

但如果只读引用和可变引用重叠，就会失败：

fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &mut s;

    println!("r1 = {}", r1);
    println!("r2 = {}", r2);
}

因为 r1 在创建 r2 之后还要继续使用，所以只读借用和可变借用的作用范围重叠了。

7. &[T]：借用一段数组或 Vec

如果函数只是读一段连续元素，参数优先写成 &[T]。

完整示例：

fn print_slice(nums: &[i32]) {
    println!("slice = {:?}", nums);
    println!("len = {}", nums.len());

    if !nums.is_empty() {
        println!("first = {}", nums[0]);
    }
}

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    print_slice(&nums);
    print_slice(&nums[1..4]);
    print_slice(&nums[..2]);
    print_slice(&nums[2..]);
    print_slice(&nums[..]);
}

这里：

#![allow(unused)]
fn main() {
nums: &[i32]
}

表示：

借用一段连续的 i32。

它既可以接收整个 Vec，也可以接收 Vec 的一部分。

8. slice 范围语法

对于：

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    println!("{:?}", &nums[1..4]);
    println!("{:?}", &nums[..2]);
    println!("{:?}", &nums[2..]);
    println!("{:?}", &nums[..]);
}

含义是：

&nums[1..4]  -> [20, 30, 40]
&nums[..2]   -> [10, 20]
&nums[2..]   -> [30, 40, 50]
&nums[..]    -> [10, 20, 30, 40, 50]

Rust 的范围通常是左闭右开：

[start, end)

所以 1..4 包含索引 1、2、3，不包含索引 4。

9. 为什么优先用 &[T] 而不是 &Vec<T>

求和函数可以写成：

fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for &x in nums {
        total += x;
    }

    total
}

fn main() {
    let nums = vec![10, 20, 30, 40, 50];

    let total = sum_slice(&nums[1..4]);

    println!("sum = {}", total);
    println!("nums after borrowing = {:?}", nums);
}

&[i32] 比 &Vec<i32> 更通用：

&Vec<i32>  = 我必须借一个 Vec
&[i32]     = 我只需要借一段 i32

所以函数只读 Vec 内容时，优先使用：

#![allow(unused)]
fn main() {
fn f(xs: &[T])
}

而不是：

#![allow(unused)]
fn main() {
fn f(xs: &Vec<T>)
}

10. for &x in nums 的含义

在这个函数里：

#![allow(unused)]
fn main() {
fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for &x in nums {
        total += x;
    }

    total
}
}

nums 的类型是：

#![allow(unused)]
fn main() {
&[i32]
}

遍历 nums 时，每个元素的类型是：

#![allow(unused)]
fn main() {
&i32
}

所以：

#![allow(unused)]
fn main() {
for &x in nums
}

表示把 &i32 解开，得到 i32。

等价写法是：

#![allow(unused)]
fn main() {
fn sum_slice(nums: &[i32]) -> i32 {
    let mut total = 0;

    for x in nums {
        total += *x;
    }

    total
}
}

因为 i32 是 Copy，所以复制一个整数很便宜。

11. &str：字符串 slice

&str 表示一段 UTF-8 字符串的只读视图。

完整示例：

fn print_text(text: &str) {
    println!("text = {}", text);
    println!("len in bytes = {}", text.len());
}

fn main() {
    let s = String::from("hello rust");

    let first = &s[..5];
    let second = &s[6..];

    print_text(&s);
    print_text(first);
    print_text(second);
    print_text("literal string");
}

这里 print_text 可以接收：

#![allow(unused)]
fn main() {
print_text(&s);               // String 的全部内容
print_text(&s[..5]);          // String 的一部分
print_text("literal string"); // 字符串字面量
}

所以只读字符串时，优先使用：

#![allow(unused)]
fn main() {
fn f(s: &str)
}

而不是：

#![allow(unused)]
fn main() {
fn f(s: &String)
}

12. String、&String、&str 的关系

可以先这样理解：

类型含义
String拥有字符串数据
&String借用整个 String 对象
&str借用字符串内容的一段

一般函数只读文本时，优先写：

#![allow(unused)]
fn main() {
fn print_text(text: &str)
}

因为 &str 能接收更多来源。

13. 字符串长度是字节数，不是字符数

Rust 字符串是 UTF-8 编码。str.len() 返回的是字节数，不是字符数。

完整示例：

fn main() {
    let en = String::from("hello");
    let zh = String::from("你好");

    println!("en len = {}", en.len());
    println!("zh len = {}", zh.len());
}

输出中，zh.len() 是 6，不是 2，因为中文字符通常每个占 3 个字节。

字符串 slice 必须切在合法 UTF-8 边界上。下面这个程序会在运行时 panic：

fn main() {
    let s = String::from("你好");
    let part = &s[..1];

    println!("{}", part);
}

典型错误信息：

byte index 1 is not a char boundary

说明 Rust 允许用字节范围切 &str，但运行时会检查这个范围是不是合法字符边界。

14. 函数返回 &str

函数可以接收一个引用，并返回这个引用里面的一部分。

完整示例：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let sentence = String::from("hello rust world");

    let word = first_word(&sentence);

    println!("first word = {}", word);
}

这个函数的意思是：

给我一段字符串 text。
我不拥有它，只借来看。
我返回其中第一个单词那一段。

word 不是新的字符串，不拥有数据，它只是指向 sentence 内部一段内容的视图。

15. char_indices() 的作用

在函数中：

#![allow(unused)]
fn main() {
for (index, ch) in text.char_indices() {
    if ch == ' ' {
        return &text[..index];
    }
}
}

char_indices() 会遍历字符串里的字符，同时给出每个字符的字节位置。

对于：

hello rust

可以粗略理解为：

index = 0, ch = 'h'
index = 1, ch = 'e'
index = 2, ch = 'l'
index = 3, ch = 'l'
index = 4, ch = 'o'
index = 5, ch = ' '

遇到空格时：

#![allow(unused)]
fn main() {
return &text[..index];
}

就返回开头到空格之前的字符串 slice。

16. 返回引用时，不能比原数据活得更久

下面这段可以通过：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let mut sentence = String::from("hello rust world");

    let word = first_word(&sentence);
    println!("first word = {}", word);

    sentence.clear();
    sentence.push_str("borrow checker");
    println!("sentence = {}", sentence);
}

因为：

#![allow(unused)]
fn main() {
println!("first word = {}", word);
}

是 word 的最后一次使用。之后 word 不再使用，对 sentence 的只读借用结束，所以可以修改 sentence。

但下面这段会失败：

fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}

fn main() {
    let mut sentence = String::from("hello rust world");

    let word = first_word(&sentence);

    sentence.clear();

    println!("word after clear = {}", word);
}

典型错误信息类似：

cannot borrow `sentence` as mutable because it is also borrowed as immutable

原因是：

word 借用了 sentence 里面的一段。
如果后面还要使用 word，那么这段借用必须继续有效。
sentence.clear() 会可变修改原字符串，所以 Rust 禁止它和 word 的后续使用重叠。

17. 函数返回 &[T]

同样的逻辑也适用于数组或 Vec slice。

完整示例：

fn first_two(nums: &[i32]) -> &[i32] {
    if nums.len() >= 2 {
        &nums[..2]
    } else {
        nums
    }
}

fn main() {
    let nums = vec![10, 20, 30, 40];

    let head = first_two(&nums);

    println!("first two = {:?}", head);
    println!("nums still usable = {:?}", nums);
}

这里：

nums 拥有 Vec。
head 是借用 nums 前两个元素的 &[i32]。

如果在 head 后续还要使用时修改 nums，就会失败：

fn first_two(nums: &[i32]) -> &[i32] {
    if nums.len() >= 2 {
        &nums[..2]
    } else {
        nums
    }
}

fn main() {
    let mut nums = vec![10, 20, 30, 40];

    let head = first_two(&nums);

    nums.push(50);

    println!("first two = {:?}", head);
}

原因是：

head 借用了 nums 的内部元素。
nums.push(50) 可能导致 Vec 重新分配内存。
如果允许 push 之后继续使用 head，head 可能指向旧内存。

Rust 在编译期禁止这种情况。

18. 返回 String 还是返回 &str

如果返回值来自输入数据的一部分，可以返回 &str：

#![allow(unused)]
fn main() {
fn first_word(text: &str) -> &str {
    for (index, ch) in text.char_indices() {
        if ch == ' ' {
            return &text[..index];
        }
    }

    text
}
}

这不会分配新内存，只是返回原字符串的一段视图。

如果函数内部创建了新的字符串，就返回 String：

fn make_greeting(name: &str) -> String {
    format!("hello, {}", name)
}

fn main() {
    let msg = make_greeting("rust");
    println!("{}", msg);
}

这里不能返回 &str，因为 format! 创建的是函数内部的新字符串。函数结束后，必须把这个新字符串的所有权交给调用者，所以返回 String。

19. 函数参数选择决策表

想做什么参数类型例子含义
函数要拿走这个值Tfn consume(s: String)所有权 move 进函数
函数只读一个普通对象&Tfn print_user(user: &User)借来看，不修改
函数要修改调用者的数据&mut Tfn normalize(v: &mut Vec<f64>)借来改，独占
函数只读一段数组或 Vec&[T]fn sum(xs: &[i32])借用一段连续元素
函数只读字符串&strfn count_words(s: &str)借用一段文本
函数需要返回新字符串Stringfn join_name(...) -> String创建并返回拥有所有权的新数据
函数需要返回新 VecVec<T>fn filter(...) -> Vec<T>创建并返回新集合

可以用这个流程判断参数类型：

1. 函数是否需要拥有这个值？
   - 是：用 T，例如 String、Vec<T>
   - 否：继续

2. 函数是否需要修改调用者的数据？
   - 是：用 &mut T
   - 否：继续

3. 参数是不是字符串？
   - 是：优先用 &str
   - 否：继续

4. 参数是不是 Vec 或数组内容？
   - 是：优先用 &[T]
   - 否：用 &T

返回值可以这样判断：

1. 返回值是不是函数新创建的数据？
   - 是：返回 String、Vec<T>、T

2. 返回值是不是输入数据的一部分？
   - 是：返回 &str、&[T]、&T

形式含义
&T只读借用

Rust 不是不让你共享数据，而是要求你明确：谁拥有，谁只读借用，谁独占修改，借用能活多久。

1. 函数返回值：最后一个表达式

在 Rust 里，函数体最后一个没有分号的表达式就是返回值。

#![allow(unused)]
fn main() {
fn add(a: i32, b: i32) -> i32 {
    a + b
}
}

等价于：

#![allow(unused)]
fn main() {
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}
}

但 Rust 更常写前一种风格。

如果加了分号：

fn add(a: i32, b: i32) -> i32 {
    a + b;
}

编译器会报错：

expected `i32`, found `()`
help: remove this semicolon

2. 语句 vs 表达式

这个区别在 Rust 中非常重要：

语句 statement表达式 expression
做什么执行动作计算并产生值
有没有值没有可用的值（返回 ()）有值
例子let x = 3;a + b，if ... else ...

函数体最后用表达式作为返回值，是 Rust 常见的风格。

3. if 也是表达式

#![allow(unused)]
fn main() {
fn describe_number(x: i32) -> &'static str {
    if x < 0 {
        "negative"
    } else if x == 0 {
        "zero"
    } else if x % 2 == 0 {
        "positive even"
    } else {
        "positive odd"
    }
}
}

这里整个 if ... else ... 是函数最后一个表达式，它的结果就是函数返回值。

if 作为表达式时，所有分支必须返回同一种类型。比如这个不行：

let value = if x > 0 {
    1
} else {
    "negative"
};

因为 Rust 需要在编译时确定 value 的类型，但两个分支类型不一样。

4. match：强大的分支表达式

#![allow(unused)]
fn main() {
fn grade(score: i32) -> &'static str {
    match score {
        90..=100 => "A",
        80..=89 => "B",
        70..=79 => "C",
        60..=69 => "D",
        0..=59 => "F",
        _ => "invalid",
    }
}
}

关键语法点：

90..=100    包含两端的范围，等价于 [90, 100]
_           兜底，匹配其他所有情况
match 必须穷尽所有可能性，所以 _ 很常用

用 | 匹配多个值

#![allow(unused)]
fn main() {
match x {
    1 | 2 => println!("one or two"),
    3 | 4 => println!("three or four"),
    5..=10 => println!("five to ten"),
    _ => println!("something else"),
}
}

| 表示“或“，..= 表示包含两端的范围。

5. 三种循环

for

#![allow(unused)]

for score in [95, 82, 61, 40, 120] {

#![allow(unused)]

6. Option<T>

Option<T> 是 Rust 标准库里非常常用的枚举，表示“可能有值，也可能没有值“：

#![allow(unused)]
fn main() {
fn find_first_even(nums: &[i32]) -> Option<i32> {
    for &x in nums {
        if x % 2 == 0 {
            return Some(x);
        }
    }

    None
}
}

两种可能：

Some(value)   -> 有值，value 是具体内容
None          -> 没有值

用 match 处理：

#![allow(unused)]
fn main() {
match first_even {
    Some(value) => println!("first even = {}", value),
    None => println!("no even number"),
}
}

7. if let：简化单模式匹配

如果只关心其中一种模式：

#![allow(unused)]
fn main() {
if let Some(value) = find_first_even(&[1, 3, 8, 9]) {
    println!("found even = {}", value);
}
}

等价于：

#![allow(unused)]
fn main() {
match find_first_even(&[1, 3, 8, 9]) {
    Some(value) => println!("found even = {}", value),
    _ => {}
}
}

带 else 的版本：

#![allow(unused)]
fn main() {
if let Some(value) = find_first_even(&[1, 3, 7]) {
    println!("found even = {}", value);
} else {
    println!("no even number");
}
}

为什么必须写 let？

#![allow(unused)]
fn main() {
if let Some(value) = expr { ... }
}

不能省略 let，写成：

if Some(value) = expr { ... }

因为普通 if 期望条件是 bool，而 Some(value) = expr 是模式匹配赋值，不是 bool。let 关键字告诉编译器“这一行是模式匹配，不是 bool 判断“。

8. while let：持续匹配直到失败

#![allow(unused)]
fn main() {
let mut nums = vec![1, 2, 3, 4, 5];

while let Some(top) = nums.pop() {
    println!("popped = {}", top);
}
}

逻辑：

nums.pop() 返回 Some(5)，匹配成功，执行循环体
nums.pop() 返回 Some(4)，匹配成功
...
nums.pop() 返回 None，匹配失败，退出循环

9. let else：简化 Option 的提前返回

#![allow(unused)]
fn main() {
fn try_parse(s: &str) -> Option<i32> {
    let result: i32 = s.parse().ok()?;
    Some(result)
}

fn process(s: &str) {
    let Some(value) = try_parse(s) else {
        println!("parse failed: {}", s);
        return;
    };

    println!("parsed value = {}", value);
    println!("value + 10 = {}", value + 10);
}
}

含义：

如果 try_parse(s) 返回 Some(value)，取出 value。
否则执行 else 块，然后 return。

let else 的 else 块必须以 return、break、continue 或 panic! 结尾。

10. 元组解构

let 可以直接解构元组：

#![allow(unused)]
fn main() {
let pair = (100, 200);
let (a, b) = pair;
// a = 100, b = 200

let (first, _, third) = (1, 2, 3);
// _ 表示忽略这个位置的值
}

match 也可以解构元组，并根据内容做不同分支：

#![allow(unused)]
fn main() {
let point = (3, 0);

match point {
    (0, 0) => println!("origin"),
    (0, y) => println!("on y-axis, y = {}", y),
    (x, 0) => println!("on x-axis, x = {}", x),
    (x, y) => println!("x = {}, y = {}", x, y),
}
}

Rust 从上往下匹配，第一个匹配到的分支会被执行。

11. match guard

match 分支可以附加条件：

#![allow(unused)]
fn main() {
let pair = (10, 20);

match pair {
    (x, y) if x > y => println!("(larger, smaller)"),
    (x, y) if x < y => println!("(smaller, larger)"),
    (x, _) => println!("(equal, value = {})", x),
}
}

if x > y 就是 match guard：模式匹配成功后再额外检查条件。

12. enumerate()

遍历集合时同时获取索引：

#![allow(unused)]
fn main() {
let colors = vec!["red", "green", "blue"];

for (index, color) in colors.iter().enumerate() {
    println!("color[{}] = {}", index, color);
}
}

输出：

color[0] = red
color[1] = green
color[2] = blue

13. 循环标签 'label

嵌套循环时，可以用标签指定 break 和 continue 的作用范围。

#![allow(unused)]
fn main() {
'outer: for i in 0..3 {
    for j in 0..3 {
        if i == 1 && j == 1 {
            break 'outer;           // 跳出两层循环
        }
        if j == 1 {
            continue 'outer;        // 跳到外层下一次迭代
        }
    }
}
}

语法：标签以单引号 ' 开头，放在循环关键字之前。

没有标签时，break 和 continue 只影响最内层循环。

Rust 对 panic! 的哲学

panic! 用于"程序无法继续运行"的情况。
不用于"预期可能出错"的情况。

用户输入非法 -> 不用 panic，用 Result
文件不存在 -> 不用 panic，用 Result

12. .filter()

filter 用来保留满足条件的元素。

filter 的 closure 返回 bool：

true  -> 保留

为什么这里是 *x？

所以 x 是 &i32，需要 *x 得到 i32。

13. .filter() 中的引用层级

如果写：

    .iter()
    .filter(|x| **x % 2 == 0)
    .copied()
    .collect();
}

类型流动是：

nums.iter()                Item = &i32
filter 的参数 x             &&i32
filter 后保留的 Item 仍然是  &i32
copied()                   &i32 -> i32
collect()                  Vec<i32>

关键点：

filter 没有把 &&i32 变成 &i32。
filter 只是用 &&i32 判断是否保留元素。
保留下来的元素仍然是原 iterator 的 item，也就是 &i32。
copied() 才把 &i32 变成 i32。

15. .filter_map()

filter_map() 可以理解成：

转换 + 丢弃失败项

示例：

fn main() {
    let text = "10 20 abc 30 -5 xx";

    let numbers: Vec<i32> = text
        .split_whitespace()
        .filter_map(|word| word.parse::<i32>().ok())
        .collect();

    println!("numbers = {:?}", numbers);
}

流程：

"10"  -> Ok(10)  -> Some(10)  -> 保留
"20"  -> Ok(20)  -> Some(20)  -> 保留
"abc" -> Err     -> None      -> 丢弃
"30"  -> Ok(30)  -> Some(30)  -> 保留
"-5"  -> Ok(-5)  -> Some(-5)  -> 保留
"xx"  -> Err     -> None      -> 丢弃

结果：

[10, 20, 30, -5]

手写循环版本：

#![allow(unused)]
fn main() {
let text = "10 20 bad 30 xx -5";
let mut numbers = Vec::new();

for word in text.split_whitespace() {
    match word.parse::<i32>() {
        Ok(value) => numbers.push(value),
        Err(_) => println!("skip invalid word = {:?}", word),
    }
}
}

1. Rust 程序的最小单位

最小 Rust 程序：

fn main() {
    println!("hello rust");
}

main 是程序入口。

当运行一个二进制 Rust 程序时，Rust 会从：

fn main()

开始执行。

main 默认返回：

#![allow(unused)]
fn main() {
()
}

也就是 unit，可以理解成“没有有意义的返回值”。

所以这个写法是正常的：

fn main() {
    println!("hello rust");
}

也可以显式写成：

fn main() -> () {
    println!("hello rust");
}

但通常不写 -> ()。

2. Cargo 默认运行 src/main.rs

一个最小 Cargo 项目通常长这样：

my_project/
  Cargo.toml
  src/
    main.rs

进入项目目录：

cd my_project

运行：

cargo run

Cargo 默认会运行：

src/main.rs

所以如果你写的是：

src/main.rs

那么命令就是：

cargo run

检查是否能编译但不真正运行：

cargo check

常用习惯：

cargo check  用来快速看有没有编译错误
cargo run    用来编译并运行程序

3. 为什么 src/case1.rs 不会被 cargo run 运行？

假设目录是：

my_project/
  Cargo.toml
  src/
    main.rs
    case1.rs

你运行：

cargo run

Cargo 只会运行：

src/main.rs

不会自动运行：

src/case1.rs

因为 src/case1.rs 在 Cargo 看来只是一个普通源码文件。

如果你想让它成为模块，需要在 main.rs 里写：

#![allow(unused)]
fn main() {
mod case1;
}

但模块文件通常不写自己的 fn main()。

所以初学阶段不推荐这样放可运行小程序：

src/case1.rs

更推荐使用：

src/bin/case1.rs

4. 多个可运行 .rs 文件：推荐用 src/bin/

如果你想在一个项目里写多个可运行练习，推荐目录结构：

my_project/
  Cargo.toml
  src/
    main.rs
    bin/
      case1.rs
      case2.rs
      parse_words.rs

每个 src/bin/*.rs 都可以有自己的：

fn main() {
    ...
}

运行方式：

cargo run --bin case1
cargo run --bin case2
cargo run --bin parse_words

注意：命令里不写 .rs 后缀。

例如文件是：

src/bin/parse_words.rs

运行：

cargo run --bin parse_words

检查：

cargo check --bin parse_words

5. examples/ 目录

另一种组织方式是：

my_project/
  examples/
    demo.rs

运行：

cargo run --example demo

examples/ 常用于库项目的 API 示例。

当前学习阶段，更推荐：

因为它更适合放多个独立小练习。

6. rustc 单文件运行

如果只是一个非常小的单文件实验，也可以不用 Cargo，直接用 rustc。

例如文件：

src/case1.rs

运行：

rustc src/case1.rs -o case1
./case1

含义：

rustc src/case1.rs -o case1   编译成可执行文件 case1
./case1                       运行这个可执行文件

缺点：

会生成一个二进制文件 case1，需要自己清理。

清理：

rm case1

如果你输出到了 src/case1，就清理：

rm src/case1

初学时，如果已经在 Cargo 项目里，通常更推荐用 src/bin/。

9. 从零手写一个 Rust 小程序的流程

不要一开始就写复杂链式调用。推荐流程：

1. 写 fn main()
2. 定义一个输入
3. println! 打印输入
4. 用 for 循环拆开
5. 逐步加 parse / match / push
6. 最后再改写成 iterator 链

例如目标：

给定字符串 "10 20 bad -5"，逐个尝试解析成 i32。

第一步：只打印输入。

fn main() {
    let text = "10 20 bad -5";
    println!("text = {}", text);
}

第二步：拆分单词。

fn main() {
    let text = "10 20 bad -5";

    for word in text.split_whitespace() {
        println!("word = {:?}", word);
    }
}

第三步：尝试解析。

fn main() {
    let text = "10 20 bad -5";

    for word in text.split_whitespace() {
        let parsed = word.parse::<i32>();
        println!("word = {:?}, parsed = {:?}", word, parsed);
    }
}

第四步：只收集成功结果。

fn main() {
    let text = "10 20 bad -5";
    let mut numbers = Vec::new();

    for word in text.split_whitespace() {
        match word.parse::<i32>() {
            Ok(value) => numbers.push(value),
            Err(_) => println!("skip invalid word = {:?}", word),
        }
    }

    println!("numbers = {:?}", numbers);
}

第五步：再改写成 iterator 链。

fn main() {
    let text = "10 20 bad -5";

    let numbers: Vec<i32> = text
        .split_whitespace()
        .filter_map(|word| word.parse::<i32>().ok())
        .collect();

    println!("numbers = {:?}", numbers);
}

10. 函数可以写在 main 前，也可以写在 main 后

Rust 不要求函数必须先定义再使用。

这个可以：

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", add(2, 3));
}

这个也可以：

fn main() {
    println!("{}", add(2, 3));
}

fn add(a: i32, b: i32) -> i32 {
    a + b
}

初学阶段推荐：

辅助函数写在前面，main 写在最后。

这样读起来比较顺。

文件：

2. 修改字段需要 mut

如果要修改字段，变量绑定本身必须是 mut：

fn main() {
    let mut user1 = User {
        name: String::from("Alice"),
        age: 20,
        active: true,
    };

    user1.age += 1;
    user1.active = false;

    println!("name = {}", user1.name);
    println!("age = {}", user1.age);
    println!("active = {}", user1.active);
}

struct User {
    name: String,
    age: u32,
    active: bool,
}

注意 Rust 不是给单个字段加 mut，而是：

#![allow(unused)]
fn main() {
let mut user1 = ...;
}

表示 user1 这个绑定可变，于是可以修改它的字段。

3. Debug 与 #[derive(Debug)]

单独打印字段可以用 {}：

#![allow(unused)]
fn main() {
println!("name = {}", user1.name);
}

但如果想直接打印整个结构体：

println!("user1 = {:?}", user1);

如果没有实现 Debug，编译器会报错：

`User` cannot be formatted using `{:?}` because it doesn't implement `Debug`
help: consider annotating `User` with `#[derive(Debug)]`

修复方式是在 struct 上方添加：

#![allow(unused)]
fn main() {
#[derive(Debug)]
}

完整示例：

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

fn main() {
    let mut user1 = User {
        name: String::from("Alice"),
        age: 20,
        active: true,
    };

    user1.age += 1;
    user1.active = false;

    println!("user1 = {:?}", user1);
}

输出类似：

user1 = User { name: "Alice", age: 21, active: false }

更漂亮的多行调试输出使用 {:#?}：

#![allow(unused)]
fn main() {
println!("user1 = {:#?}", user1);
}

输出类似：

user1 = User {
    name: "Alice",
    age: 21,
    active: false,
}

格式化规则：

写法含义
{}Display，面向用户的普通显示
{:?}Debug，面向开发者的调试显示
{:#?}pretty Debug，多行调试显示

4. impl：给类型定义方法

impl User 表示给 User 类型实现函数或方法。

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn greet(&self) {
        println!("Hello, my name is {}.", self.name);
    }

    fn is_adult(&self) -> bool {
        self.age >= 18
    }
}

fn main() {
    let user1 = User {
        name: String::from("Alice"),
        age: 21,
        active: true,
    };

    user1.greet();
    println!("is adult? {}", user1.is_adult());
    println!("user1 = {:#?}", user1);
}

这里：

#![allow(unused)]
fn main() {
fn greet(&self)
}

表示只读借用当前对象。

可以把：

#![allow(unused)]
fn main() {
user1.greet();
}

大致理解成：

User::greet(&user1);

is_adult 返回 bool：

#![allow(unused)]
fn main() {
fn is_adult(&self) -> bool {
    self.age >= 18
}
}

最后一行没有分号，因此是表达式，作为返回值。

如果写成：

fn is_adult(&self) -> bool {
    self.age >= 18;
}

会得到类似错误：

expected `bool`, found `()`

这复习了 Day 4 的规则：

没有分号的表达式产生值；
带分号的语句通常产生 ()。

5. &mut self：方法修改结构体

如果方法要修改结构体字段，就使用 &mut self：

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn greet(&self) {
        println!("Hello, my name is {}.", self.name);
    }

    fn is_adult(&self) -> bool {
        self.age >= 18
    }

    fn birthday(&mut self) {
        self.age += 1;
        println!("Happy birthday, {}!", self.name);
    }

    fn deactivate(&mut self) {
        self.active = false;
    }
}

fn main() {
    let mut user1 = User {
        name: String::from("Alice"),
        age: 17,
        active: true,
    };

    println!("before = {:#?}", user1);

    user1.greet();
    println!("is adult? {}", user1.is_adult());

    user1.birthday();
    println!("after birthday = {:#?}", user1);
    println!("is adult now? {}", user1.is_adult());

    user1.deactivate();
    println!("after deactivate = {:#?}", user1);
}

因为 birthday 和 deactivate 需要可变借用，变量必须声明为：

#![allow(unused)]
fn main() {
let mut user1 = ...;
}

如果写成：

let user1 = User { ... };
user1.birthday();

编译器会提示类似：

cannot borrow `user1` as mutable, as it is not declared as mutable
help: consider changing this to be mutable

6. self：消耗结构体

第三种方法接收者是：

#![allow(unused)]
fn main() {
self
}

它表示直接拿走整个对象的所有权。

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn greet(&self) {
        println!("Hello, my name is {}.", self.name);
    }

    fn birthday(&mut self) {
        self.age += 1;
    }

    fn into_name(self) -> String {
        self.name
    }
}

fn main() {
    let mut user1 = User {
        name: String::from("Alice"),
        age: 17,
        active: true,
    };

    user1.greet();

    user1.birthday();
    println!("after birthday = {:#?}", user1);

    let name = user1.into_name();
    println!("name = {}", name);

    // user1 已经被 into_name() 消耗，不能再使用
    // println!("user1 = {:#?}", user1);
}

into_name 的签名是：

#![allow(unused)]
fn main() {
fn into_name(self) -> String
}

调用：

#![allow(unused)]
fn main() {
let name = user1.into_name();
}

大致等价于：

let name = User::into_name(user1);

也就是 user1 被 move 进方法。方法内部把 self.name 移出并返回。

常见命名习惯：

into_xxx

通常表示：

消耗旧值，把它转换成新值。

例如标准库中的：

#![allow(unused)]
fn main() {
let s = String::from("abc");
let bytes = s.into_bytes();

// s 之后不能再用
}

7. &self、&mut self、self 对比

写法等价理解含义调用后原对象还能用吗
&selfself: &User只读借用能
&mut selfself: &mut User可变借用能
selfself: User拿走所有权通常不能

判断方法：

这个方法调用后，原对象还应该继续使用吗？

如果只是读取：用 &self。

如果要原地修改：用 &mut self。

如果要转换、拆包、终结对象生命周期：用 self。

8. 借用名字、克隆名字、消耗名字

同样是“得到名字”，可以有三种不同设计：

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn name(&self) -> &str {
        &self.name
    }

    fn cloned_name(&self) -> String {
        self.name.clone()
    }

    fn into_name(self) -> String {
        self.name
    }
}

fn main() {
    let user1 = User {
        name: String::from("Alice"),
        age: 21,
        active: true,
    };

    let borrowed_name = user1.name();
    println!("borrowed_name = {}", borrowed_name);
    println!("user1 after name() = {:#?}", user1);

    let copied_name = user1.cloned_name();
    println!("copied_name = {}", copied_name);
    println!("user1 after cloned_name() = {:#?}", user1);

    let owned_name = user1.into_name();
    println!("owned_name = {}", owned_name);

    // user1 已经被消耗
    // println!("user1 after into_name() = {:#?}", user1);
}

对比：

方法返回是否复制是否消耗 user1
name(&self)&str不复制不消耗
cloned_name(&self)String复制不消耗
into_name(self)String不额外复制消耗

9. 关联函数与构造函数模式

在 impl 中，如果函数没有 self 参数，它就是关联函数。

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn new(name: &str, age: u32) -> User {
        User {
            name: name.to_string(),
            age,
            active: true,
        }
    }
}

fn main() {
    let user1 = User::new("Alice", 21);
    println!("user1 = {:#?}", user1);
}

调用方式是：

#![allow(unused)]
fn main() {
User::new("Alice", 21)
}

不是：

user1.new(...)

Rust 没有固定的构造函数语法，但社区常用：

#![allow(unused)]
fn main() {
TypeName::new(...)
}

作为构造函数模式。

10. Self：当前类型

在：

#![allow(unused)]
fn main() {
impl User {
    ...
}
}

内部，Self 表示当前类型，也就是 User。

因此常见写法是：

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn new(name: &str, age: u32) -> Self {
        Self {
            name: name.to_string(),
            age,
            active: true,
        }
    }

    fn guest() -> Self {
        Self {
            name: String::from("guest"),
            age: 0,
            active: false,
        }
    }
}

fn main() {
    let user1 = User::new("Alice", 21);
    let guest = User::guest();

    println!("user1 = {:#?}", user1);
    println!("guest = {:#?}", guest);
}

这里：

#![allow(unused)]
fn main() {
fn new(...) -> Self
}

等价于：

#![allow(unused)]
fn main() {
fn new(...) -> User
}
#![allow(unused)]
fn main() {
Self { ... }
}

等价于：

#![allow(unused)]
fn main() {
User { ... }
}

12. struct update syntax：..user1

Rust 可以基于旧结构体创建新结构体：

#[derive(Debug)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    fn new(name: &str, age: u32) -> Self {
        Self {
            name: name.to_string(),
            age,
            active: true,
        }
    }
}

fn main() {
    let user1 = User::new("Alice", 21);

    let user2 = User {
        name: String::from("Bob"),
        ..user1
    };

    println!("user2 = {:#?}", user2);
}

这里：

#![allow(unused)]
fn main() {
..user1
}

表示剩余字段从 user1 补齐。

在上面的例子中，age: u32 和 active: bool 都是 Copy 类型，因此复制即可。

如果没有被覆盖的字段里包含 String，就会发生 move：

#[derive(Debug)]
struct User {
    name: String,
    email: String,
    age: u32,
    active: bool,
}

impl User {
    fn new(name: &str, email: &str, age: u32) -> Self {
        Self {
            name: name.to_string(),
            email: email.to_string(),
            age,
            active: true,
        }
    }
}

fn main() {
    let user1 = User::new("Alice", "alice@example.com", 21);

    let user2 = User {
        name: String::from("Bob"),
        ..user1
    };

    println!("user2 = {:#?}", user2);

    // user1.email 已经被 move 到 user2，user1 不能再整体使用
    println!("user1 = {:#?}", user1);
}

核心规则：

struct update syntax 会从旧对象补齐字段；
Copy 字段会复制；
非 Copy 字段会 move。

13. Builder 风格：消耗并返回 Self

self 的一个常见用途是 builder 模式。

#[derive(Debug)]
struct Config {
    batch_size: usize,
    learning_rate: f64,
    device: String,
}

impl Config {
    fn new() -> Self {
        Self {
            batch_size: 1,
            learning_rate: 0.01,
            device: String::from("cpu"),
        }
    }

    fn with_batch_size(mut self, batch_size: usize) -> Self {
        self.batch_size = batch_size;
        self
    }

    fn with_learning_rate(mut self, learning_rate: f64) -> Self {
        self.learning_rate = learning_rate;
        self
    }

    fn with_device(mut self, device: &str) -> Self {
        self.device = device.to_string();
        self
    }
}

fn main() {
    let config = Config::new()
        .with_batch_size(32)
        .with_learning_rate(0.001)
        .with_device("cuda");

    println!("config = {:#?}", config);
}

每个 with_xxx 都消耗旧的 Config，修改后返回新的 Config，因此可以链式调用。

14. 科学计算风格示例：Particle

下面的例子把今天的内容组合起来：

struct 表示状态
impl 表示状态上的操作
&self 读取状态
&mut self 更新状态
self 消耗并转换状态

#[derive(Debug)]
struct Particle {
    position: f64,
    velocity: f64,
    mass: f64,
}

impl Particle {
    fn new(position: f64, velocity: f64, mass: f64) -> Self {
        Self {
            position,
            velocity,
            mass,
        }
    }

    fn kinetic_energy(&self) -> f64 {
        0.5 * self.mass * self.velocity * self.velocity
    }

    fn momentum(&self) -> f64 {
        self.mass * self.velocity
    }

    fn is_moving(&self) -> bool {
        self.velocity != 0.0
    }

    fn apply_force(&mut self, force: f64, dt: f64) {
        let acceleration = force / self.mass;
        self.velocity += acceleration * dt;
    }

    fn step(&mut self, dt: f64) {
        self.position += self.velocity * dt;
    }

    fn stop(&mut self) {
        self.velocity = 0.0;
    }

    fn into_tuple(self) -> (f64, f64, f64) {
        (self.position, self.velocity, self.mass)
    }
}

fn main() {
    let mut p = Particle::new(0.0, 2.0, 1.5);

    println!("initial particle = {:#?}", p);
    println!("kinetic energy = {}", p.kinetic_energy());
    println!("momentum = {}", p.momentum());
    println!("is moving? {}", p.is_moving());

    p.apply_force(3.0, 0.1);
    p.step(0.1);

    println!("after update = {:#?}", p);
    println!("kinetic energy = {}", p.kinetic_energy());
    println!("momentum = {}", p.momentum());

    p.stop();
    println!("after stop = {:#?}", p);
    println!("is moving? {}", p.is_moving());

    let raw = p.into_tuple();
    println!("raw tuple = {:?}", raw);

    // p 已经被 into_tuple() 消耗，不能再使用
    // println!("p after into_tuple = {:#?}", p);
}

这个例子和科学计算、模拟代码的思路相似：

状态数据：position, velocity, mass
只读计算：kinetic_energy, momentum, is_moving
原地更新：apply_force, step, stop
转换输出：into_tuple

1. 为什么需要 enum

Day 6 的 struct 适合表达：

一个东西同时拥有多个字段。

例如：

#![allow(unused)]
fn main() {
struct User {
    name: String,
    age: u32,
    active: bool,
}
}

这表示一个 User 同时拥有 name、age、active。

而 enum 适合表达：

一个值只能是多种可能形态之一。

例如任务状态：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone, Copy)]
enum TaskStatus {
    Todo,
    InProgress,
    Done,
}
}

这表示一个 TaskStatus 只能是：

#![allow(unused)]
fn main() {
TaskStatus::Todo
TaskStatus::InProgress
TaskStatus::Done
}

三者之一。

如果用字符串表示状态：

#![allow(unused)]
fn main() {
let status = String::from("todo");
}

容易出现拼写问题：

"todo"
"Todo"
"TODO"
"tood"

编译器无法帮你检查。

用 enum：

#![allow(unused)]
fn main() {
let status = TaskStatus::Todo;
}

如果写错：

let status = TaskStatus::Tood;

编译器会直接报错。

这就是 enum 的价值：

把非法状态挡在编译期。

2. 最简单的 enum

完整示例：

#[derive(Debug)]
enum TaskStatus {
    Todo,
    InProgress,
    Done,
}

fn describe_status(status: TaskStatus) {
    match status {
        TaskStatus::Todo => println!("task is not started"),
        TaskStatus::InProgress => println!("task is in progress"),
        TaskStatus::Done => println!("task is done"),
    }
}

fn main() {
    let s1 = TaskStatus::Todo;
    let s2 = TaskStatus::InProgress;
    let s3 = TaskStatus::Done;

    println!("s1 = {:?}", s1);
    println!("s2 = {:?}", s2);
    println!("s3 = {:?}", s3);

    describe_status(s1);
    describe_status(s2);
    describe_status(s3);
}

输出：

s1 = Todo
s2 = InProgress
s3 = Done
task is not started
task is in progress
task is done

这里：

#![allow(unused)]
fn main() {
TaskStatus
}

是类型。

#![allow(unused)]
fn main() {
Todo
InProgress
Done
}

不是独立类型，而是 TaskStatus 的 variant。

也就是说：

#![allow(unused)]
fn main() {
let s: TaskStatus = TaskStatus::Todo;
}

TaskStatus::Todo 的类型是：

#![allow(unused)]
fn main() {
TaskStatus
}

可以类比：

bool = true | false
TaskStatus = Todo | InProgress | Done

true 和 false 不是两个类型，它们都是 bool 的值。同理，Todo、InProgress、Done 都是 TaskStatus 的不同值。

3. match 与穷尽匹配

match 用来根据 enum 的不同 variant 执行不同逻辑：

#![allow(unused)]
fn main() {
match status {
    TaskStatus::Todo => println!("task is not started"),
    TaskStatus::InProgress => println!("task is in progress"),
    TaskStatus::Done => println!("task is done"),
}
}

每一行叫一个 match arm：

#![allow(unused)]
fn main() {
pattern => expression,
}

例如：

#![allow(unused)]
fn main() {
TaskStatus::Todo => println!("task is not started"),
}

其中：

TaskStatus::Todo                  pattern
=>                                匹配后执行右边
println!("task is not started")   expression
,                                 结束这个 match arm

match 的分支之间用逗号分隔。类似数组或 vec! 中的元素用逗号分隔：

#![allow(unused)]
fn main() {
let nums = vec![
    1,
    2,
    3,
];
}

如果 arm 右边是代码块，初学阶段也建议保留逗号：

#![allow(unused)]
fn main() {
match status {
    TaskStatus::Todo => {
        println!("task is not started");
    },
    TaskStatus::InProgress => {
        println!("task is in progress");
    },
    TaskStatus::Done => {
        println!("task is done");
    },
}
}

Rust 的 match 要求穷尽匹配。也就是说，必须处理所有可能情况。

如果少写一个分支，例如漏掉：

TaskStatus::Done => println!("task is done"),

编译器会报类似错误：

non-exhaustive patterns: `TaskStatus::Done` not covered

这意味着：

你没有处理 Done 这种情况。

这是 Rust 帮你防止逻辑遗漏的重要机制。

4. derive(Debug, Clone, Copy)

对于简单 enum，可以写：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone, Copy)]
enum TaskStatus {
    Todo,
    InProgress,
    Done,
}
}

derive 的意思是：

请编译器自动帮这个类型实现某些 trait。

当前阶段可以把 trait 理解成“某种能力”。

trait能力
Debug可以用 {:?} 打印
Clone可以显式 .clone()
Copy赋值、传参时可以隐式复制，不 move

例如：

#[derive(Debug, Clone, Copy)]
enum TaskStatus {
    Todo,
    InProgress,
    Done,
}

fn describe_status(status: TaskStatus) {
    println!("status = {:?}", status);
}

fn main() {
    let s1 = TaskStatus::Todo;

    describe_status(s1);
    println!("s1 after describe = {:?}", s1);
}

因为 TaskStatus 实现了 Copy，所以传入函数时复制一份，原来的 s1 还能继续使用。

一个 enum 能不能 Copy，取决于它所有 variant 携带的数据是否都能 Copy。

下面这个可以 Copy，因为没有携带任何数据：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone, Copy)]
enum Direction {
    Up,
    Down,
    Left,
    Right,
}
}

下面这个不能 Copy，因为 String 不是 Copy：

#[derive(Debug, Clone, Copy)]
enum Message {
    Text(String),
    Quit,
}

编译器会报类似错误：

the trait `Copy` cannot be implemented for this type
this field does not implement `Copy`

原因是 String 拥有堆内存，不能隐式复制；但它可以显式 .clone()。

因此可以写：

#![allow(unused)]
fn main() {
#[derive(Debug, Clone)]
enum Message {
    Text(String),
    Quit,
}
}

5. 带数据的 enum variant

Rust 的 enum 不只是标签。每个 variant 可以携带不同形状的数据。

#![allow(unused)]
fn main() {
#[derive(Debug)]
enum Message {
    Text(String),
    Move { x: i32, y: i32 },
    Resize(u32, u32),
    Quit,
}
}

四种 variant：

variant形状例子
Text(String)tuple-like，携带一个 StringMessage::Text(String::from("hello"))
Move { x, y }struct-like，命名字段Message::Move { x: 10, y: 20 }
Resize(u32, u32)tuple-like，携带两个值Message::Resize(800, 600)
Quitunit-like，不携带数据Message::Quit

完整示例：

#[derive(Debug)]
enum Message {
    Text(String),
    Move { x: i32, y: i32 },
    Resize(u32, u32),
    Quit,
}

fn handle_message(message: Message) {
    match message {
        Message::Text(content) => {
            println!("text message: {}", content);
        }
        Message::Move { x, y } => {
            println!("move to x = {}, y = {}", x, y);
        }
        Message::Resize(width, height) => {
            println!("resize to {} x {}", width, height);
        }
        Message::Quit => {
            println!("quit");
        }
    }
}

fn main() {
    let m1 = Message::Text(String::from("hello rust"));
    let m2 = Message::Move { x: 10, y: 20 };
    let m3 = Message::Resize(800, 600);
    let m4 = Message::Quit;

    println!("m1 = {:?}", m1);
    println!("m2 = {:?}", m2);
    println!("m3 = {:?}", m3);
    println!("m4 = {:?}", m4);

    handle_message(m1);
    handle_message(m2);
    handle_message(m3);
    handle_message(m4);
}

match 不只是判断 variant，还可以解构其中的数据：

#![allow(unused)]
fn main() {
Message::Text(content) => {
    println!("text message: {}", content);
}
}

如果 message 是：

#![allow(unused)]
fn main() {
Message::Text(String::from("hello"))
}

那么 content 就绑定到内部的 String。

#![allow(unused)]
fn main() {
Message::Move { x, y } => {
    println!("x = {}, y = {}", x, y);
}
}

会把内部字段解构到 x 和 y。

6. enum 比“kind + 很多 Option 字段”更安全

如果不用 enum 表达消息，可能会写成：

#![allow(unused)]
fn main() {
struct Message {
    kind: String,
    text: Option<String>,
    x: Option<i32>,
    y: Option<i32>,
    width: Option<u32>,

}

这会产生很多非法状态：

kind = "Move" 但 x/y 缺一个
kind = "Quit" 但 width/height 有值
kind 拼写错误

用 enum：

非法状态在类型层面被排除了。

7. Option<T> 的本质

Option<T> 是 Rust 标准库里最常用的 enum 之一。

它大概定义为：

#![allow(unused)]
fn main() {
enum Option<T> {
    Some(T),
    None,
}
}

含义：

Some(value)  有值
None         没有值

Rust 没有普通意义上的 null。如果一个值可能不存在，类型通常写成：

#![allow(unused)]
fn main() {
Option<T>
}

例如：

fn describe_number(value: Option<i32>) {
    match value {
        Some(n) => println!("number = {}", n),
        None => println!("no number"),
    }
}

fn main() {
    let a = Some(10);
    let b: Option<i32> = None;

    describe_number(a);
    describe_number(b);
}

输出：

number = 10
no number

这里：

#![allow(unused)]
fn main() {
let b: Option<i32> = None;
}

需要标注类型，因为 None 本身没有携带值。编译器不知道你想表达的是：

#![allow(unused)]
fn main() {
Option<i32>
Option<String>
Option<Vec<i32>>
}

所以需要告诉它。

而：

#![allow(unused)]
fn main() {
let a = Some(10);
}

不需要标注，因为 10 默认可推断为 i32，所以 a 是：

#![allow(unused)]
fn main() {
Option<i32>
}

8. 返回 Option<T>：查找偶数

如果一个函数“可能找得到，也可能找不到”，就适合返回 Option<T>。

fn describe_number(value: Option<i32>) {
    match value {
        Some(n) => println!("number = {}", n),
        None => println!("no number"),
    }
}

fn find_even(nums: &[i32]) -> Option<i32> {
    for n in nums {
        if *n % 2 == 0 {
            return Some(*n);
        }
    }

    None
}

fn main() {
    let nums1 = vec![1, 3, 5, 8, 9];
    let nums2 = vec![1, 3, 5];

    let result1 = find_even(&nums1);
    let result2 = find_even(&nums2);

    describe_number(result1);
    describe_number(result2);
}

输出：

number = 8
no number

find_even 的签名：

#![allow(unused)]
fn main() {
fn find_even(nums: &[i32]) -> Option<i32>
}

表示：

尝试找一个偶数。
找到了：Some(value)
没找到：None

这比用特殊值更安全。

例如有些语言可能返回：

-1

表示没找到。但如果 -1 本身也是合法值呢？

Option<i32> 更明确：

Some(-1)  真的找到了 -1
None      没找到

9. if let：只关心一种情况的 match 简写

普通 if 的条件必须是 bool：

#![allow(unused)]
fn main() {
let x = 10;

if x > 5 {
    println!("large");
}
}

if let 不是普通赋值，而是：

模式匹配 + 解构绑定

例如：

#![allow(unused)]
fn main() {
if let Some(n) = value {
    println!("number = {}", n);
}
}

意思是：

如果 value 能匹配 Some(n)，就进入 if 块，并把 Some 内部的值绑定到 n。

它大致等价于：

#![allow(unused)]
fn main() {
match value {
    Some(n) => {
        println!("number = {}", n);
    }
    None => {}
}
}

完整示例：

fn print_if_some(value: Option<i32>) {
    if let Some(n) = value {
        println!("got number = {}", n);
    }
}

fn print_with_else(value: Option<i32>) {
    if let Some(n) = value {
        println!("got number = {}", n);
    } else {
        println!("got nothing");
    }
}

fn label(value: Option<i32>) -> String {
    if let Some(n) = value {
        format!("number: {}", n)
    } else {
        String::from("none")
    }
}

fn main() {
    let a = Some(42);
    let b: Option<i32> = None;

    print_if_some(a);
    print_if_some(b);

    print_with_else(a);
    print_with_else(b);

    println!("label a = {}", label(a));
    println!("label b = {}", label(b));
}

这里能多次使用 a 和 b，因为 Option<i32> 是 Copy。

如果是 Option<String>，就不是 Copy，传参可能 move。

如果不想消耗原值，可以借用：

fn print_if_some_string(value: &Option<String>) {
    if let Some(name) = value {
        println!("name = {}", name);
    }
}

fn main() {
    let name = Some(String::from("Alice"));

    print_if_some_string(&name);
    println!("name after call = {:?}", name);
}

10. 真实一点的案例：下载任务状态

为了避免过于抽象，可以看一个“下载任务”的例子。

一个下载任务可能处于这些状态：

等待中
下载中，已经下载多少字节
下载完成，保存路径是什么
下载失败，原因是什么
已取消

如果用多个 bool 和 Option 字段表示，可能会很乱：

struct DownloadJob {
    url: String,
    is_started: bool,
    is_done: bool,
    is_failed: bool,
    is_cancelled: bool,
    downloaded_bytes: Option<u64>,
    output_path: Option<String>,
    error_message: Option<String>,
}

这个设计会产生很多非法组合：

is_done = true 但 output_path = None
is_done = true 且 is_failed = true
is_cancelled = true 但还在 downloaded_bytes 增长
is_started = false 但 downloaded_bytes = Some(100)

用 enum 会更自然：

#[derive(Debug)]
enum DownloadState {
    Pending,
    Downloading { downloaded_bytes: u64 },
    Finished { output_path: String },
    Failed { reason: String },
    Cancelled,
}

#[derive(Debug)]
struct DownloadJob {
    url: String,
    state: DownloadState,
}

impl DownloadJob {
    fn new(url: &str) -> Self {
        Self {
            url: url.to_string(),
            state: DownloadState::Pending,
        }
    }

    fn start(&mut self) {
        match &self.state {
            DownloadState::Pending => {
                self.state = DownloadState::Downloading {
                    downloaded_bytes: 0,
                };
            }
            DownloadState::Downloading { .. } => {
                println!("download already started");
            }
            DownloadState::Finished { .. } => {
                println!("download already finished");
            }
            DownloadState::Failed { reason } => {
                println!("cannot start failed download: {}", reason);
            }
            DownloadState::Cancelled => {
                println!("cannot start cancelled download");
            }
        }
    }

    fn progress(&mut self, bytes: u64) {
        match &mut self.state {
            DownloadState::Downloading { downloaded_bytes } => {
                *downloaded_bytes += bytes;
            }
            _ => {
                println!("cannot update progress unless downloading");
            }
        }
    }

    fn finish(&mut self, output_path: &str) {
        match &self.state {
            DownloadState::Downloading { .. } => {
                self.state = DownloadState::Finished {
                    output_path: output_path.to_string(),
                };
            }
            _ => {
                println!("only downloading job can finish");
            }
        }
    }

    fn fail(&mut self, reason: &str) {
        match &self.state {
            DownloadState::Finished { .. } => {
                println!("cannot fail a finished download");
            }
            DownloadState::Cancelled => {
                println!("cannot fail a cancelled download");
            }
            _ => {
                self.state = DownloadState::Failed {
                    reason: reason.to_string(),
                };
            }
        }
    }

    fn describe(&self) {
        match &self.state {
            DownloadState::Pending => {
                println!("{}: pending", self.url);
            }
            DownloadState::Downloading { downloaded_bytes } => {
                println!("{}: downloading {} bytes", self.url, downloaded_bytes);
            }
            DownloadState::Finished { output_path } => {
                println!("{}: finished -> {}", self.url, output_path);
            }
            DownloadState::Failed { reason } => {
                println!("{}: failed ({})", self.url, reason);
            }
            DownloadState::Cancelled => {
                println!("{}: cancelled", self.url);
            }
        }
    }
}

fn main() {
    let mut job = DownloadJob::new("https://example.com/model.bin");

    job.describe();

    job.start();
    job.progress(1024);
    job.progress(2048);
    job.describe();

    job.finish("/tmp/model.bin");
    job.describe();

    job.fail("network disconnected");
    job.describe();
}

这个例子中：

fn main() {

Finished { output_path: String }
Failed { reason: String }
}

不同状态携带不同数据。

这比一堆 bool 更准确，因为类型系统表达了：

只有 Finished 状态才有 output_path。
只有 Failed 状态才有 reason。
只有 Downloading 状态才有 downloaded_bytes。

11. 今日主实验：任务状态机

今天最后的代码把 enum + struct + impl 组合起来。

#[derive(Debug)]
enum TaskState {
    Todo,
    InProgress,
    Done,
    Failed(String),
    Cancelled,
}

#[derive(Debug)]
struct Task {
    title: String,
    state: TaskState,
}

impl Task {
    fn new(title: &str) -> Self {
        Self {
            title: title.to_string(),
            state: TaskState::Todo,
        }
    }

    fn start(&mut self) {
        match &self.state {
            TaskState::Todo => {
                self.state = TaskState::InProgress;
            }
            TaskState::InProgress => {
                println!("task is already in progress");
            }
            TaskState::Done => {
                println!("cannot start a done task");
            }
            TaskState::Failed(_) => {
                println!("cannot start a failed task");
            }
            TaskState::Cancelled => {
                println!("cannot start a cancelled task");
            }
        }
    }

    fn complete(&mut self) {
        match &self.state {
            TaskState::InProgress => {
                self.state = TaskState::Done;
            }
            TaskState::Todo => {
                println!("cannot complete a todo task");
            }
            TaskState::Done => {
                println!("task is already done");
            }
            TaskState::Failed(_) => {
                println!("cannot complete a failed task");
            }
            TaskState::Cancelled => {
                println!("cannot complete a cancelled task");
            }
        }
    }

    fn fail(&mut self, reason: &str) {
        self.state = TaskState::Failed(reason.to_string());
    }

    fn cancel(&mut self) {
        match &self.state {
            TaskState::Done => {
                println!("cannot cancel a done task");
            }
            TaskState::Failed(_) => {
                println!("cannot cancel a failed task");
            }
            TaskState::Cancelled => {
                println!("task is already cancelled");
            }
            TaskState::Todo | TaskState::InProgress => {
                self.state = TaskState::Cancelled;
            }
        }
    }

    fn describe(&self) {
        match &self.state {
            TaskState::Todo => {
                println!("{}: todo", self.title);
            }
            TaskState::InProgress => {
                println!("{}: in progress", self.title);
            }
            TaskState::Done => {
                println!("{}: done", self.title);
            }
            TaskState::Failed(reason) => {
                println!("{}: failed ({})", self.title, reason);
            }
            TaskState::Cancelled => {
                println!("{}: cancelled", self.title);
            }
        }
    }
}

fn main() {
    let mut task = Task::new("learn Rust enum");

    println!("initial = {:#?}", task);
    task.describe();

    task.complete();

    task.start();
    task.describe();

    task.cancel();
    task.describe();

    task.complete();
    task.fail("network error");
    task.describe();

    println!("final = {:#?}", task);
}

这里：

#![allow(unused)]
fn main() {
TaskState::Todo | TaskState::InProgress => {
    self.state = TaskState::Cancelled;
}
}

表示：

Todo 或 InProgress 两种情况共用同一段逻辑。

describe 中使用：

#![allow(unused)]
fn main() {
match &self.state
}

是因为 describe(&self) 只读借用任务，不应该把 state 从任务中 move 出来。

对于：

#![allow(unused)]
fn main() {
TaskState::Failed(reason)
}

由于匹配的是引用，reason 大致是 &String，可以直接打印。

12. _ 通配符

#![allow(unused)]

_ 表示：

其他所有情况。

1. 从 Option<T> 到 Result<T, E>

Day 7 学过：

#![allow(unused)]
fn main() {
enum Option<T> {
    Some(T),
    None,
}
}

Option<T> 表达：

有值 / 没有值

例如：

#![allow(unused)]
fn main() {
fn find_even(nums: &[i32]) -> Option<i32> {
    for n in nums {
        if *n % 2 == 0 {
            return Some(*n);
        }
    }

    None
}
}

但是 Option<T> 只能表达“没有”，不能表达“为什么没有”。

Result<T, E> 用来表达：

成功 / 失败，并且失败时带有原因

它大致可以理解为：

#![allow(unused)]
fn main() {
enum Result<T, E> {
    Ok(T),
    Err(E),
}
}

含义：

形式含义
Ok(T)成功，并携带成功结果
Err(E)失败，并携带错误原因

例如：

#![allow(unused)]
fn main() {
Result<i32, String>
}

可以读作：

要么成功得到 i32，要么失败得到 String 错误信息。

2. 最简单的 Result：安全除法

完整示例：

fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("cannot divide by zero"))
    } else {
        Ok(a / b)
    }
}

fn main() {
    for (a, b) in [(10, 2), (10, 0)] {
        match divide(a, b) {
            Ok(value) => println!("{a} / {b} = {value}"),
            Err(message) => println!("failed to divide {a} by {b}: {message}"),
        }
    }
}

输出：

10 / 2 = 5
failed to divide 10 by 0: cannot divide by zero

这里：

#![allow(unused)]
fn main() {
fn divide(a: i32, b: i32) -> Result<i32, String>
}

表示：

如果除法合法，返回 Ok(i32)。
如果 b == 0，返回 Err(String)。

调用处用 match 分别处理成功和失败：

#![allow(unused)]
fn main() {
match divide(a, b) {
    Ok(value) => println!("{a} / {b} = {value}"),
    Err(message) => println!("failed to divide {a} by {b}: {message}"),
}
}

这和 Option<T> 的模式很像：

match value {
    Some(x) => ...,
    None => ...,
}

只不过 Result<T, E> 的失败分支会携带错误信息。

3. 文件读取天然返回 Result

Rust 标准库中的文件读取函数：

#![allow(unused)]
fn main() {
std::fs::read_to_string(path)
}

返回类型是：

#![allow(unused)]
fn main() {
Result<String, std::io::Error>
}

因为文件读取可能失败，例如：

  • 文件不存在
  • 路径是目录
  • 没有读取权限
  • 文件系统出错

所以 Rust 不会让你假装文件读取一定成功，而是把“可能失败”写进类型。

手动处理文件读取错误：

use std::fs;
use std::io;

fn read_username_manual(path: &str) -> Result<String, io::Error> {
    let content_result = fs::read_to_string(path);

    match content_result {
        Ok(content) => Ok(content.trim().to_string()),
        Err(error) => Err(error),
    }
}

fn main() {
    match read_username_manual("username.txt") {
        Ok(name) => println!("username = {name}"),
        Err(error) => println!("failed to read username: {error}"),
    }
}

这里：

#![allow(unused)]
fn main() {
fs::read_to_string(path)
}

得到的是：

#![allow(unused)]
fn main() {
Result<String, io::Error>
}

如果成功，content 是文件内容；如果失败，error 是具体的 I/O 错误。

4. ? 运算符：传播错误

手动 match 很常见，所以 Rust 提供了 ? 简化错误传播。

下面两个函数语义相同。

手动版本：

#![allow(unused)]
fn main() {
use std::fs;
use std::io;

fn read_username_manual(path: &str) -> Result<String, io::Error> {
    let content_result = fs::read_to_string(path);

    match content_result {
        Ok(content) => Ok(content.trim().to_string()),
        Err(error) => Err(error),
    }
}
}

? 版本：

#![allow(unused)]
fn main() {
use std::fs;
use std::io;

fn read_username_question_mark(path: &str) -> Result<String, io::Error> {
    let content = fs::read_to_string(path)?;
    Ok(content.trim().to_string())
}
}

这一行：

#![allow(unused)]
fn main() {
let content = fs::read_to_string(path)?;
}

可以理解为：

let content = match fs::read_to_string(path) {
    Ok(value) => value,
    Err(error) => return Err(error),
};

也就是说：

如果是 Ok(value)，? 取出 value，程序继续执行。
如果是 Err(error)，? 立刻从当前函数返回 Err(error)。

? 不是忽略错误，而是把错误向上传播。

5. ? 对函数签名的要求

如果在函数内部写：

#![allow(unused)]
fn main() {
fs::read_to_string(path)?
}

那么当前函数也必须能返回相应的错误。

例如下面是合法的：

#![allow(unused)]
fn main() {
use std::fs;
use std::io;

fn read_username(path: &str) -> Result<String, io::Error> {
    let content = fs::read_to_string(path)?;
    Ok(content.trim().to_string())
}
}

因为当前函数返回：

#![allow(unused)]
fn main() {
Result<String, io::Error>
}

如果文件读取失败，? 可以直接返回：

#![allow(unused)]
fn main() {
Err(io::Error)
}

但如果函数写成：

fn read_username(path: &str) -> String {
    let content = fs::read_to_string(path)?;
    content.trim().to_string()
}

就不合理，因为失败时不知道应该返回什么 String。

当前阶段可以先记住：

想用 ? 传播 Result 错误，函数自己通常也要返回 Result。

6. .trim()：清理字符串两端空白

读取文本文件时经常会看到：

#![allow(unused)]
fn main() {
content.trim()
}

.trim() 会去掉字符串开头和结尾的空白字符，包括：

  • 空格
  • 换行 \n
  • 制表符 \t
  • Windows 换行里的 \r\n

例如：

fn main() {
    let text = "  42\n";
    let cleaned = text.trim();

    println!("before = {:?}", text);
    println!("after  = {:?}", cleaned);
}

输出：

before = "  42\n"
after  = "42"

它不会删除字符串中间的空格：

fn main() {
    let text = "  hello rust  ";
    println!("{:?}", text.trim());
}

输出：

"hello rust"

中间的空格仍然存在。

.trim() 不会原地修改原字符串，而是返回一个 &str 视图：

fn main() {
    let text = String::from("  hello  ");
    let cleaned = text.trim();

    println!("text = {:?}", text);
    println!("cleaned = {:?}", cleaned);
}

输出：

text = "  hello  "
cleaned = "hello"

所以在下面这个函数里：

#![allow(unused)]
fn main() {
use std::fs;
use std::io;

fn read_username(path: &str) -> Result<String, io::Error> {
    let content = fs::read_to_string(path)?;
    Ok(content.trim().to_string())
}
}

流程是：

String -> trim 得到 &str -> to_string 得到新的 String

因为函数返回类型要求是：

#![allow(unused)]
fn main() {
Result<String, io::Error>
}

所以最后需要 .to_string()。

10. match、?、unwrap()、expect() 的区别

假设有：

#![allow(unused)]
fn main() {
let result = std::fs::read_to_string("number.txt");
}

它的类型是：

#![allow(unused)]
fn main() {
Result<String, std::io::Error>
}

常见处理方式有四种。

10.1 match：显式处理

#![allow(unused)]
fn main() {
match std::fs::read_to_string("number.txt") {
    Ok(content) => println!("content = {}", content),
    Err(error) => println!("failed to read file: {}", error),
}
}

特点：

成功怎么处理，失败怎么处理，都写清楚。

适合在程序边界层处理错误，例如 main、CLI、用户界面。

10.2 ?：向上传播

let content = std::fs::read_to_string("number.txt")?;

特点：

当前函数不处理错误，而是交给调用者。

适合中间函数。

10.3 unwrap()：失败就 panic

#![allow(unused)]
fn main() {
let content = std::fs::read_to_string("number.txt").unwrap();
}

含义：

如果是 Ok(value)，取出 value。
如果是 Err(error)，程序 panic。

适合快速实验或测试代码，不适合正式处理用户输入、文件、网络等外部失败。

10.4 expect()：失败就 panic，但带说明

#![allow(unused)]
fn main() {
let content = std::fs::read_to_string("number.txt")
    .expect("number.txt should exist for this demo");
}

expect() 和 unwrap() 类似，也会在失败时 panic，但它可以提供更清晰的上下文信息。

正式代码中如果确实要 panic，通常 expect() 比裸 unwrap() 更好。

11. Err 不是 panic

这是一个重要区别。

#![allow(unused)]
fn main() {
Err(error)
}

只是一个普通值，表示操作失败了，但程序还可以继续运行。

例如：

fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("cannot divide by zero"))
    } else {
        Ok(a / b)
    }
}

fn main() {
    match divide(10, 0) {
        Ok(n) => println!("result = {n}"),
        Err(error) => println!("error: {error}"),
    }

    println!("program is still running");
}

输出：

error: cannot divide by zero
program is still running

而：

divide(10, 0).unwrap();

会把 Err 变成 panic。

所以：

Result 是可恢复错误。
panic 是不可恢复崩溃。

12. 多行文件解析：lines()、enumerate() 与 map_err

今天的主实验读取一个多行数字文件，解析成 Vec<i32>，并在错误中报告行号。

完整示例：

use std::fs;

fn parse_numbers_from_text(text: &str) -> Result<Vec<i32>, String> {
    let mut numbers = Vec::new();

    for (index, line) in text.lines().enumerate() {
        let trimmed = line.trim();

        if trimmed.is_empty() {
            continue;
        }

        let number = trimmed.parse::<i32>().map_err(|error| {
            format!(
                "line {}: cannot parse {:?}: {}",
                index + 1,
                trimmed,
                error
            )
        })?;

        numbers.push(number);
    }

    Ok(numbers)
}

fn read_numbers(path: &str) -> Result<Vec<i32>, Box<dyn std::error::Error>> {
    let content = fs::read_to_string(path)?;
    let numbers = parse_numbers_from_text(&content)?;
    Ok(numbers)
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    fs::write("numbers.txt", "10\n20\n\n30\n")?;
    fs::write("bad_numbers.txt", "10\nabc\n30\n")?;

    match read_numbers("numbers.txt") {
        Ok(numbers) => {
            let total: i32 = numbers.iter().sum();
            println!("numbers = {:?}", numbers);
            println!("total = {total}");
        }
        Err(error) => println!("failed to read numbers: {error}"),
    }

    match read_numbers("bad_numbers.txt") {
        Ok(numbers) => println!("numbers = {:?}", numbers),
        Err(error) => println!("failed to read numbers: {error}"),
    }

    Ok(())
}

输出：

numbers = [10, 20, 30]
total = 60
failed to read numbers: line 2: cannot parse "abc": invalid digit found in string

例如：

12.4 map_err

这一行是错误上下文的关键：

#![allow(unused)]
fn main() {
let number = trimmed.parse::<i32>().map_err(|error| {
    format!(
        "line {}: cannot parse {:?}: {}",
        index + 1,
        trimmed,
        error
    )
})?;
}

trimmed.parse::<i32>() 的类型是：

#![allow(unused)]
fn main() {
Result<i32, ParseIntError>
}

但 parse_numbers_from_text 返回：

#![allow(unused)]
fn main() {
Result<Vec<i32>, String>
}

所以需要把错误类型从 ParseIntError 转成 String。

map_err 的作用是：

如果是 Ok(value)，保持 Ok(value) 不变。
如果是 Err(error)，把 error 转换成另一个错误。

也就是：

Result<i32, ParseIntError>
    -> map_err(...)
Result<i32, String>

然后最后的 ?：

Ok(number)  -> 取出 number，继续执行
Err(String) -> 立刻返回 Err(String)

这样错误信息就能从：

invalid digit found in string

增强为：

line 2: cannot parse "abc": invalid digit found in string

这在真实工程里非常重要，因为好的错误信息应该回答：

哪里错了？哪个输入错了？为什么错了？

13. 什么时候用 Result，什么时候用 panic

Rust 通常把错误分为两类。

13.1 可恢复错误：用 Result

如果失败是正常可能发生的，程序应该有机会处理，就用 Result。

例如：

  • 用户输入了非法数字
  • 文件不存在
  • 网络请求失败
  • 配置文件格式不对
  • 权限不足
  • 某一行文本解析失败

这些不是程序员写错代码，而是外部世界本来就可能这样。

例如：

#![allow(unused)]
fn main() {
fn read_number(path: &str) -> Result<i32, Box<dyn std::error::Error>> {
    let content = std::fs::read_to_string(path)?;
    let number = content.trim().parse::<i32>()?;
    Ok(number)
}
}

13.2 不可恢复错误：可以 panic

如果某个错误发生时说明程序内部逻辑已经坏了，继续运行没有意义，可以用 panic。

例如：

  • 数组越界访问
  • 违反程序内部不变量
  • 某个理论上绝不应该发生的分支真的发生了
  • 测试中发现结果不符合预期

“不变量”指的是：

程序在某个位置必须始终满足的条件。

例如下面这个函数假设输入切片非空：

#![allow(unused)]
fn main() {
fn average(nums: &[i32]) -> f64 {
    if nums.is_empty() {
        panic!("nums should not be empty");
    }

    let sum: i32 = nums.iter().sum();
    sum as f64 / nums.len() as f64
}
}

如果调用者传入空切片，就违反了函数约定。

不过更安全的 API 往往会用 Option 或 Result 表达这种可能性：

#![allow(unused)]
fn main() {
fn average(nums: &[i32]) -> Option<f64> {
    if nums.is_empty() {
        return None;
    }

    let sum: i32 = nums.iter().sum();
    Some(sum as f64 / nums.len() as f64)
}
}

这里用 Option<f64> 很合适，因为失败原因只有一种：没有数字，无法计算平均值。

14. Result、Option、panic 的选择

可以用下面的表判断：

场景推荐
可能没有值，但没有复杂错误原因Option<T>
可能失败，而且需要说明失败原因Result<T, E>
外部输入、文件、网络、解析Result<T, E>
程序内部逻辑不变量被破坏panic!
快速实验可以临时用 unwrap()
测试代码unwrap() / expect() 常见
正式代码中确信不会失败优先 expect("说明为什么不该失败")，少用裸 unwrap()

实用原则：

能恢复，用 Result。
可能没有，用 Option。
程序员 bug，用 panic。
实验代码可以 unwrap。
正式代码少 unwrap，多用 ?、match、expect。

更工程化一点：

在函数内部用 ? 传播错误；
在边界层用 match 展示错误；
在错误发生处用 map_err / 自定义错误增加上下文；
只有不可恢复的逻辑错误才 panic。

15. Library 和 Application 的区别

如果你在写库代码，也就是别人会调用你的函数，通常应该少 panic，多返回 Result。

库代码更推荐：

fn load_config(path: &str) -> Result<Config, ConfigError> {
    // ...
}

而不是：

fn load_config(path: &str) -> Config {
    // ...
    panic!("failed to load config");
}

因为库不应该随便替调用者决定：

程序必须崩溃。

应用程序的最外层可以决定如何展示错误、是否退出程序：

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = load_config("config.toml")?;
    run(config)?;
    Ok(())
}

或者：

fn main() {
    match run() {
        Ok(()) => {}
        Err(error) => {
            eprintln!("error: {}", error);
            std::process::exit(1);
        }
    }
}

常见风格是：

底层函数返回 Result。
顶层函数决定如何展示错误、是否退出程序。

17.1 Ok(scores) 的作用

这个函数签名是：

#![allow(unused)]
fn main() {
fn parse_scores_from_text(text: &str) -> Result<Vec<f64>, String>
}

它不是返回：

#![allow(unused)]
fn main() {
Vec<f64>
}

而是返回：

#![allow(unused)]
fn main() {
Result<Vec<f64>, String>
}

所以函数最后不能直接写：

scores

因为 scores 的类型只是：

#![allow(unused)]
fn main() {
Vec<f64>
}

必须写：

#![allow(unused)]
fn main() {
Ok(scores)
}

这表示：

成功解析出了 Vec<f64>，现在把它包装成 Result 的成功分支返回。

类型关系是：

scores: Vec<f64>
Ok(scores): Result<Vec<f64>, String>

同理，如果失败，则返回：

#![allow(unused)]
fn main() {
Err(message)
}

其中：

message: String
Err(message): Result<Vec<f64>, String>

17.2 Ok 的两个位置：构造与匹配

同样写作 Ok(scores)，在不同位置含义不同。

在函数返回处：

#![allow(unused)]
fn main() {
Ok(scores)
}

表示“构造一个成功的 Result 值”。

在 match 中：

#![allow(unused)]
fn main() {
match read_scores("scores.txt") {
    Ok(scores) => println!("{:?}", scores),
    Err(error) => println!("{error}"),
}
}

这里的 Ok(scores) 表示“匹配成功分支，并把里面的值取出来命名为 scores”。

位置含义
函数最后 Ok(scores)构造成功结果
match 里的 Ok(scores) => ...匹配成功结果并拆包

Some(value) 也有同样的两种用法。

17.3 ?：从 Result 里取值，或提前返回错误

这一行：

#![allow(unused)]
fn main() {
let score = trimmed.parse::<f64>().map_err(|error| {
    format!(
        "line {}: cannot parse {:?}: {}",
        index + 1,
        trimmed,
        error
    )
})?;
}

类型流动如下：

trimmed: &str
trimmed.parse::<f64>(): Result<f64, ParseFloatError>
map_err(...): Result<f64, String>
?: 成功时取出 f64，失败时提前返回 Err(String)
score: f64

也就是说，? 的作用是：

如果是 Ok(value)，取出 value，赋给 score。
如果是 Err(error)，立刻从 parse_scores_from_text 返回 Err(error)。

所以 ? 不是忽略错误，而是把错误沿着函数返回类型传播出去。

17.4 写变量类型时的判断方法

Rust 有类型推断，不是所有变量都需要手动标类型。但初学阶段可以主动标出关键类型，帮助自己建立类型感。

例如：

#![allow(unused)]
fn main() {
let mut scores: Vec<f64> = Vec::new();
}

表示 scores 是一个装 f64 的动态数组。

#![allow(unused)]

    format!("line {}: cannot parse {:?}: {}", index + 1, trimmed, error)

表示这一行最终成功时得到的是一个 f64。

}

这里建议标注 f64，因为 sum() 是泛型方法，类型提示能让代码更清楚。

一个实用原则：

能从右边明显看出来的，可以省略类型。
Vec::new()、parse、sum 这类容易让人迷糊的地方，初学时可以多写类型。

17.6 返回值小抄

如果函数签名是：

#![allow(unused)]
fn main() {
fn f() -> Result<T, E>
}

成功返回：

#![allow(unused)]
fn main() {
Ok(value_of_type_T)
}

失败返回：

#![allow(unused)]
fn main() {
Err(error_of_type_E)
}

如果函数签名是：

#![allow(unused)]
fn main() {
fn f() -> Option<T>
}

有值返回：

#![allow(unused)]
fn main() {
Some(value_of_type_T)
}

没值返回：

#![allow(unused)]
fn main() {
None
}

所以：

#![allow(unused)]
fn main() {
fn average(scores: &[f64]) -> Option<f64> {
    if scores.is_empty() {
        return None;
    }

    let total: f64 = scores.iter().sum();
    Some(total / scores.len() as f64)
}
}

这里：

None: Option<f64>
Some(...): Option<f64>

它们都和函数签名一致。

17.7 本次练习暴露出的核心问题

这次练习中，最容易卡住的不是算法，而是 Rust 的“类型包装”意识：

Vec<f64> 要用 Ok(...) 包成 Result<Vec<f64>, String>。
f64 要从 Result<f64, String> 里用 ? 取出来。
平均值 f64 要用 Some(...) 包成 Option<f64>。
没有平均值时返回 None。

以后写 Rust 函数时，可以先问自己四个问题：

1. 函数签名说最终返回什么类型？
2. 成功值是什么类型？
3. 失败值是什么类型？
4. 当前这一步拿到的是普通值，还是 Result / Option 包装值？

这比一开始就直接敲代码更稳。

.trim()去掉字符串两端空白，常用于清理换行
.parse::<i32>()字符串解析数字，返回 Result<i32, ParseIntError>
Box<dyn Error>当前阶段可理解为通用错误盒子
unwrap()成功取值，失败 panic
expect()成功取值，失败 panic，但带自定义说明
map_err转换错误类型，常用于增加上下文
panic!表示不可恢复错误或程序内部不变量被破坏

一句话总结：

Rust 不把普通失败藏起来，而是用 Result 把失败写进类型，让调用者必须面对。

1. Iterator 的三条主线

Rust iterator 学习可以抓住三条主线：

1. 所有权：iter / iter_mut / into_iter
2. 惰性执行：map/filter 本身不运行，collect/sum/count 才触发
3. 类型流动：&T、&mut T、T、Option、Result 如何在链式调用中变化

如果这三条线清楚，Rust iterator 的大部分常见用法就能理解。

2. iter() / iter_mut() / into_iter()

核心口诀：

iter()      -> 借来看，产生 &T
iter_mut()  -> 借来改，产生 &mut T
into_iter() -> 拿走元素，产生 T

2.1 iter()：只读借用

fn main() {
    let nums = vec![1, 2, 3];

    for n in nums.iter() {
        println!("n = {n}");
    }

    println!("nums can still be used: {:?}", nums);
}

nums.iter() 不拿走 nums，而是产生一串 &i32。因此循环结束后，nums 仍然可以使用。

2.2 iter_mut()：可变借用

fn main() {
    let mut scores = vec![58, 76, 90];

    for score in scores.iter_mut() {
        *score += 5;
    }

    println!("curved scores = {:?}", scores);
}

iter_mut() 产生的是 &mut i32，所以需要用 *score 解引用后修改里面的值。

2.3 into_iter()：消费集合

fn main() {
    let words = vec![String::from("rust"), String::from("ai")];

    let upper: Vec<String> = words
        .into_iter()
        .map(|word| word.to_uppercase())
        .collect();

    println!("upper = {:?}", upper);

    // 取消注释会报错：words 已经被 into_iter() 消费。
    // println!("words = {:?}", words);
}

对于 Vec<String>，into_iter() 会把每个 String move 出来，因此原来的 words 不能再使用。

这和 Day 2 的所有权一致：String 不是 Copy，默认移动所有权。

3. Iterator 是 lazy 的

下面这段代码不会打印任何东西：

fn main() {
    let nums = vec![1, 2, 3];

    nums.iter().map(|x| {
        println!("{x}");
        x * 2
    });
}

原因是：

map 只是创建一个新的 iterator，不会立刻执行。

必须有 consumer 消费 iterator，代码才真正运行：

fn main() {
    let nums = vec![1, 2, 3];

    let doubled: Vec<i32> = nums
        .iter()
        .map(|x| {
            println!("mapping {x}");
            x * 2
        })
        .collect();

    println!("doubled = {:?}", doubled);
}

常见 adaptor：

map()
filter()
filter_map()
enumerate()
take()
skip()
zip()
chain()

常见 consumer：

collect()
sum()
count()
for_each()
any()
all()
find()
fold()

简单说：

adaptor 改造 iterator，consumer 真正消费 iterator。

4. Closure 语法

Closure 可以理解为匿名小函数：

#![allow(unused)]
fn main() {
|x| x + 1
}

类似 Python 中的：

lambda x: x + 1

Rust 中常见写法：

fn main() {
    let nums = vec![1, 2, 3];

    let doubled: Vec<i32> = nums.iter().map(|x| x * 2).collect();

    println!("doubled = {:?}", doubled);
}

这里：

#![allow(unused)]
fn main() {
|x| x * 2
}

表示对每个元素执行 x * 2。

Rust 的格式化宏还支持直接捕获变量名：

fn main() {
    let name = "Rust";
    let score = 95;

    println!("name = {name}");
    println!("score = {score}");
}

这和下面写法含义类似：

fn main() {
    let name = "Rust";
    let score = 95;

    println!("name = {}", name);
    println!("score = {}", score);
}

5. map / filter / collect

三个最常见的方法：

方法作用
map一对一转换
filter保留满足条件的元素
collect把 iterator 收集成集合

示例：

fn main() {
    let nums = vec![1, 2, 3, 4, 5];

    let doubled: Vec<i32> = nums.iter().map(|x| x * 2).collect();

    let evens: Vec<i32> = nums
        .iter()
        .filter(|x| **x % 2 == 0)
        .copied()
        .collect();

    println!("doubled = {:?}", doubled);
    println!("evens = {:?}", evens);
}

这里：

#![allow(unused)]
fn main() {
let doubled: Vec<i32> = ...collect();
}

需要写出 Vec<i32>，因为 collect() 可以收集成多种集合，Rust 需要知道目标类型。

也可以写成 turbofish 形式：

fn main() {
let nums = vec![1, 2, 3];

}

6. filter 中的引用层级

这是 Day 9 的重点之一。

fn main() {
    let nums = vec![1, 2, 3, 4];

    let evens: Vec<i32> = nums
        .iter()
        .filter(|x| **x % 2 == 0)
        .copied()
        .collect();

    println!("evens = {:?}", evens);
}

类型流动：

nums.iter()             -> Iterator<Item = &i32>
filter(|x| ...)         -> x 的类型是 &&i32
**x                     -> i32
filter 之后仍然是 &i32
copied()                -> &i32 变 i32
collect::<Vec<i32>>()   -> Vec<i32>

为什么 filter 里是 &&i32？

因为 filter 的 closure 收到的是“对 iterator item 的引用”。

而 nums.iter() 的 item 已经是：

&i32

所以 filter 里拿到：

&&i32

可以这样理解：

x   : &&i32
*x  : &i32
**x : i32

7. copied() 与 cloned()

copied() 用来把 &T 变成 T，前提是 T: Copy。

例如 i32 是 Copy：

fn main() {
    let nums = vec![1, 2, 3];

    let copied_nums: Vec<i32> = nums.iter().copied().collect();

    println!("copied_nums = {:?}", copied_nums);
    println!("nums = {:?}", nums);
}

String 不是 Copy，但它是 Clone，所以要用 cloned()：

fn main() {
    let words = vec![String::from("rust"), String::from("ai")];

    let cloned_words: Vec<String> = words.iter().cloned().collect();

    println!("cloned_words = {:?}", cloned_words);
    println!("words = {:?}", words);
}

区别：

copied() 用于 Copy 类型，例如 i32、f64、bool、char
cloned() 用于 Clone 类型，例如 String、Vec<T>

String 可以 clone，但不能 copy，因为它拥有堆内存，隐式按位复制会导致所有权问题。

8. filter_map：过滤 + 转换

filter_map 常用于“能转换就保留，不能转换就丢掉”的场景。

fn main() {
    let text = "10 20 bad 30";

    let nums: Vec<i32> = text
        .split_whitespace()
        .filter_map(|word| word.parse::<i32>().ok())
        .collect();

    println!("nums = {:?}", nums);
}

输出：

nums = [10, 20, 30]

流程：

"10"  -> Ok(10)  -> Some(10) -> 保留
"20"  -> Ok(20)  -> Some(20) -> 保留
"bad" -> Err(_)  -> None     -> 丢掉
"30"  -> Ok(30)  -> Some(30) -> 保留

其中：

#![allow(unused)]
fn main() {
.ok()
}

把：

Result<T, E> -> Option<T>

也就是：

Ok(value) -> Some(value)
Err(_)    -> None

所以：

#![allow(unused)]
fn main() {
filter_map(|word| word.parse::<i32>().ok())
}

表示：

能解析的数字留下，不能解析的跳过。

9. collect::<Result<Vec<_>, _>>()

如果不想跳过坏数据，而是遇到错误就返回 Err，可以使用：

fn parse_numbers(text: &str) -> Result<Vec<i32>, std::num::ParseIntError> {
    text.lines()
        .map(|line| line.trim())
        .filter(|line| !line.is_empty())
        .map(|line| line.parse::<i32>())
        .collect::<Result<Vec<_>, _>>()
}

fn main() {
    match parse_numbers("10\n20\n30\n") {
        Ok(nums) => println!("nums = {:?}", nums),
        Err(error) => println!("parse error: {error}"),
    }

    match parse_numbers("10\nbad\n30\n") {
        Ok(nums) => println!("nums = {:?}", nums),
        Err(error) => println!("parse error: {error}"),
    }
}

collect() 在这里可以把：

Iterator<Item = Result<i32, E>>

收集成：

Result<Vec<i32>, E>

含义：

全部成功 -> Ok(Vec<i32>)
有一个失败 -> Err(E)

所以：

#![allow(unused)]
fn main() {
.map(|line| line.parse::<i32>())
.collect::<Result<Vec<_>, _>>()
}

可以读作：

把每一行都解析成 i32；
如果全部成功，得到 Ok(Vec<i32>)；
如果某一行失败，整体返回 Err。

10. collect::<Result<Vec<_>, _>>()?

在返回 Result 的函数里，经常会看到：

#![allow(unused)]
fn main() {
fn parse_numbers(text: &str) -> Result<Vec<i32>, std::num::ParseIntError> {
    let nums: Vec<i32> = text
        .lines()
        .map(|line| line.trim())
        .filter(|line| !line.is_empty())
        .map(|line| line.parse::<i32>())
        .collect::<Result<Vec<_>, _>>()?;

    Ok(nums)
}
}

这句：

#![allow(unused)]
fn main() {
.collect::<Result<Vec<_>, _>>()?
}

分两步：

collect::<Result<Vec<_>, _>>()
    把 Iterator<Item = Result<T, E>> 变成 Result<Vec<T>, E>

?
    如果是 Ok(Vec<T>)，取出 Vec<T>
    如果是 Err(E)，从当前函数提前返回 Err(E)

所以它可以读作：

全部成功就拿到 Vec；遇到错误就提前返回。

和 filter_map(...ok()) 的区别：

写法错误处理方式返回类型
`filter_map(xx.parse().ok())`
`.map(xx.parse()).collect::<Result<Vec<_>, _>>()`

工程判断：

日志提取、弱清洗：坏 token 可以跳过 -> filter_map
配置文件、实验输入：坏一行就应该报错 -> collect Result

11. Closure 捕获外部变量

Closure 可以使用定义它时周围作用域里的变量。

fn main() {
    let threshold = 80;
    let scores = vec![95, 67, 88];

    let good: Vec<i32> = scores
        .iter()
        .copied()
        .filter(|score| *score >= threshold)
        .collect();

    println!("good = {:?}", good);
}

这里：

#![allow(unused)]
fn main() {
|score| *score >= threshold
}

使用了外部变量 threshold。

可以把 closure 想象成编译器生成的“带环境的小函数对象”。它不是单纯的函数指针，而是可以携带自己捕获的变量。

12. Fn / FnMut / FnOnce

Fn / FnMut / FnOnce 描述 closure 如何使用捕获的变量。

粗略对应：

Trait类比能调用几次典型行为
Fn&self多次只读使用外部变量
FnMut&mut self多次修改外部状态
FnOnceself至少一次可能拿走捕获的值

注意：

不是手动选择 Fn / FnMut / FnOnce，
而是编译器根据 closure 内部如何使用捕获变量自动判断。

12.1 Fn：只读捕获

fn call_fn<F>(f: F)
where
    F: Fn(),
{
    f();
    f();
}

fn main() {
    let threshold = 80;

    let show_threshold = || {
        println!("threshold = {threshold}");
    };

    call_fn(show_threshold);
    println!("threshold is still usable: {threshold}");
}

这个 closure 只是读取 threshold，可以调用多次。

12.2 FnMut：修改捕获变量

fn call_fn_mut<F>(mut f: F)
where
    F: FnMut(),
{
    f();
    f();
}

fn main() {
    let mut count = 0;

    let add_one = || {
        count += 1;
        println!("count = {count}");
    };

    call_fn_mut(add_one);
    println!("count after closure = {count}");
}

这个 closure 修改了外部变量 count，因此属于 FnMut。

12.3 FnOnce：消耗捕获变量

fn call_fn_once<F>(f: F)
where
    F: FnOnce(),
{
    f();
}

fn main() {
    let name = String::from("Rust");

    let consume_name = || {
        println!("dropping name = {name}");
        drop(name);
    };

    call_fn_once(consume_name);

    // 不能再次调用，因为 name 已经被消耗。
    // call_fn_once(consume_name);
}

这里 drop(name) 消耗了 name。String 不是 Copy，被 move 后不能再使用，所以这个 closure 只能调用一次。

13. move closure 不一定是 FnOnce

看到 move 不要立刻认为 closure 一定是 FnOnce。

fn call_fn<F>(f: F)
where
    F: Fn(),
{
    f();
    f();
}

fn main() {
    let language = String::from("Rust");

    let say_language = move || {
        println!("language = {language}");
    };

    call_fn(say_language);
}

这里使用了 move，表示 language 被移动进 closure 内部。

但是 closure 内部只是打印：

#![allow(unused)]
fn main() {
println!("language = {language}");
}

并没有消耗 language。因此这个 closure 仍然可以调用多次。

真正让 closure 变成只能调用一次的是：

fn main() {
let language = String::from("Rust");

let consume_language = move || {
    drop(language);
};

consume_language();
// consume_language(); // 不能再次调用
}

关键不是有没有 move，而是：

closure 内部是否消耗了捕获变量。

1. HashMap 和 HashSet 在 Rust 全貌中的位置

前面已经学过：

今天的两个容器是：

HashSet<T>   -> 只关心某个值是否出现过

Python 类比：

Rust HashSet<T>    ≈ Python set

C++ 类比：

Rust HashMap<K, V> ≈ C++ unordered_map
Rust HashSet<T>    ≈ C++ unordered_set

使用前需要导入：

#![allow(unused)]
fn main() {

HashMap 和 HashSet 不在 Rust prelude 中，因此不像 Vec、String、Option 那样默认可用。

2. HashMap 基础：insert 与 get

完整示例：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    println!("scores = {:?}", scores);

    match scores.get("Alice") {
        Some(score) => println!("Alice's score = {score}"),
        None => println!("Alice not found"),
    }

    match scores.get("David") {
        Some(score) => println!("David's score = {score}"),
        None => println!("David not found"),
    }
}

scores 的类型由插入的数据推断出来：

#![allow(unused)]
fn main() {
HashMap<String, i32>
}

含义：

key 是 String
value 是 i32

get 返回：

#![allow(unused)]
fn main() {
Option<&i32>
}

原因有两个：

1. key 可能不存在，所以外层是 Option。
2. value 归 HashMap 所有，所以 get 只借用，返回 &i32。

所以：

#![allow(unused)]
fn main() {
scores.get("Alice")
}

可能是：

#![allow(unused)]
fn main() {
Some(&95)
}

也可能是：

#![allow(unused)]
fn main() {
None
}

这和 Day 7 的 Option 直接连接起来。

3. insert 会覆盖旧值

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Bob"), 72);

    println!("scores = {:?}", scores);
}

结果中 Bob 的分数是 72。

insert 的语义：

如果 key 不存在，插入新 key-value。
如果 key 已存在，覆盖旧 value。

HashMap 中每个 key 只能对应一个 value。

4. entry(...).or_insert(...)

有时我们不想覆盖已有值，而是希望：

如果 key 存在，就保留原值。
如果 key 不存在，就插入默认值。

可以使用：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    scores.entry(String::from("Alice")).or_insert(100);
    scores.entry(String::from("David")).or_insert(81);

    println!("scores = {:?}", scores);
}

结果：

Alice 仍然是 95
David 被插入为 81

含义：

#![allow(unused)]
fn main() {
scores.entry(key).or_insert(default_value)
}

可以读作：

找到 key 对应的 entry。
如果 key 不存在，就插入 default_value。
无论原来存在还是刚插入，都返回这个 value 的可变引用。

最后一点非常重要：

#![allow(unused)]
fn main() {
or_insert(...)
}

返回的是：

#![allow(unused)]
fn main() {
&mut V
}

不是 V 本身。

5. 词频统计：entry 的经典用法

use std::collections::HashMap;

fn main() {
    let text = "rust rust ai infra rust ai";
    let mut word_counts = HashMap::new();

    for word in text.split_whitespace() {
        let count = word_counts.entry(word).or_insert(0);
        *count += 1;
    }

    println!("word_counts = {:?}", word_counts);
}

这里 word_counts 的类型是：

#![allow(unused)]
fn main() {
HashMap<&str, i32>
}

因为：

#![allow(unused)]
fn main() {
text.split_whitespace()
}

产生的是 &str。

这一句：

#![allow(unused)]
fn main() {
let count = word_counts.entry(word).or_insert(0);
}

中，count 的类型是：

#![allow(unused)]
fn main() {
&mut i32
}

也就是说，count 不是一个独立的 i32 副本，而是指向 word_counts 内部某个 value 的可变引用。

因此：

#![allow(unused)]
fn main() {
*count += 1;
}

修改的是 HashMap 里面的 value 本身。

5.1 为什么不需要把 count 放回 word_counts

这是今天很关键的理解点。

假设第一次遇到 "rust"：

word_counts = {}

执行：

#![allow(unused)]
fn main() {
let count = word_counts.entry("rust").or_insert(0);
}

因为 "rust" 不存在，所以 map 变成：

word_counts = { "rust": 0 }

然后 or_insert(0) 返回 map 内部这个 0 的可变引用：

count ---> word_counts["rust"]

执行：

#![allow(unused)]
fn main() {
*count += 1;
}

就会把 map 内部的值改成：

word_counts = { "rust": 1 }

第二次遇到 "rust" 时，entry("rust") 找到已有 value，or_insert(0) 不会插入新值，而是返回已有计数的可变引用。再次执行 *count += 1，就变成 2。

所以这里不是：

取出 count -> 修改 count -> 忘了放回 map

而是：

借到 map 内部 value 的可变引用 -> 直接修改 map 内部 value

这和 Day 9 的 iter_mut() 本质一样：

fn main() {
    let mut scores = vec![58, 76, 90];

    for score in scores.iter_mut() {
        *score += 5;
    }

    println!("scores = {:?}", scores);
}

这里 score: &mut i32 指向 Vec 里的元素；词频统计里 count: &mut i32 指向 HashMap 里的 value。

6. HashMap 遍历顺序不固定

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    for (name, score) in &scores {
        println!("{name}: {score}");
    }
}

HashMap 不保证遍历顺序。

所以输出顺序可能是：

Alice: 95
Bob: 67
Carol: 88

也可能是其他顺序。

不要写依赖 HashMap 遍历顺序的逻辑。

如果需要排序，常见做法是先收集成 Vec 再排序：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);
    scores.insert(String::from("Bob"), 67);
    scores.insert(String::from("Carol"), 88);

    let mut items: Vec<_> = scores.iter().collect();
    items.sort_by_key(|(name, _score)| *name);

    for (name, score) in items {
        println!("{name}: {score}");
    }
}

例如：

这一句：

#![allow(unused)]

把 name: String 移动进了 scores。

也就是：

name 的所有权从局部变量 name 转移给 HashMap。

7.1 如果插入后还想使用原 String

这里：

9. 为什么 HashMap<String, i32> 可以用 get("Alice")

看这个例子：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    println!("{:?}", scores.get("Alice"));
}

scores 的 key 类型是：

#![allow(unused)]
fn main() {
String
}

但查询时使用的是：

#![allow(unused)]
fn main() {
"Alice"
}

它的类型是：

#![allow(unused)]
fn main() {
&str
}

这为什么可以？

直觉解释：

String 拥有字符串内容；
&str 是字符串切片，只是借用字符串内容；
String 可以按 str 来借用。

所以标准库允许：

#![allow(unused)]
fn main() {
HashMap<String, V>
}

用：

#![allow(unused)]
fn main() {
&str
}

查询。

这样就不需要临时构造一个新的 String：

#![allow(unused)]
fn main() {
scores.get(&String::from("Alice"));
}

这种写法会产生不必要的分配。

背后依赖标准库中的 trait，例如 Borrow。当前阶段不用深挖，只需要记住：

如果 HashMap 的 key 是 String，通常可以用 &str 查询。

例如：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    let query = String::from("Alice");

    println!("{:?}", scores.get("Alice"));
    println!("{:?}", scores.get(query.as_str()));
    println!("query is still usable: {query}");
}

query.as_str() 返回 &str，只是借用 query 的内容，不会 move query。

10. get_mut：拿到 value 的可变引用

如果要修改已有 value，可以使用 get_mut：

use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();

    scores.insert(String::from("Alice"), 95);

    if let Some(score) = scores.get_mut("Alice") {
        *score += 5;
    }

    println!("scores = {:?}", scores);
}

get_mut 返回：

#![allow(unused)]
fn main() {
Option<&mut V>
}

在这个例子里是：

#![allow(unused)]
fn main() {
Option<&mut i32>
}

所以：

#![allow(unused)]
fn main() {
if let Some(score) = scores.get_mut("Alice") {
    *score += 5;
}
}

里面的 score 是：

#![allow(unused)]
fn main() {
&mut i32
}

需要写：

#![allow(unused)]
fn main() {
*score += 5;
}

这和：

#![allow(unused)]
fn main() {
let count = word_counts.entry(word).or_insert(0);
*count += 1;
}

是同一类模式：拿到容器内部 value 的可变引用，然后原地修改。

11. HashMap<String, V> vs HashMap<&str, V>

这两个选择很常见。

11.1 HashMap<String, V>

#![allow(unused)]
fn main() {
HashMap<String, i32>
}

含义：

map 拥有 key。

优点：

数据独立存在，最稳妥。
可以从文件、网络、用户输入中读取字符串作为 key。
适合跨函数返回或长期保存。

缺点：

插入时可能需要 move 或 clone String。

真实工程中更常用。

11.2 HashMap<&str, V>

#![allow(unused)]
fn main() {
HashMap<&str, i32>
}

含义：

map 不拥有 key，只保存字符串引用。

优点：

不复制字符串。

缺点：

被引用的字符串必须活得比 map 久。

例如词频统计可以使用 HashMap<&str, i32>：

use std::collections::HashMap;

fn main() {
    let text = "rust rust ai";
    let mut counts = HashMap::new();

    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }

    println!("counts = {:?}", counts);
}

这里 word 都是从 text 借来的 &str，而 text 活得足够久。

但下面这种思路不行：

use std::collections::HashMap;

fn build_map() -> HashMap<&str, i32> {
    let name = String::from("Alice");
    let mut scores = HashMap::new();

    scores.insert(name.as_str(), 95);

    scores
}

因为 name 是函数里的局部 String。函数结束后 name 被释放，如果返回 HashMap<&str, i32>，map 里就会保存指向已释放字符串的引用。Rust 会阻止这种悬垂引用。

重要结论：

HashMap<String, V> 是拥有 key；
HashMap<&str, V> 是借用 key。

12. HashSet：只关心值是否出现过

HashSet<T> 可以理解为只有 key、没有 value 的 HashMap。

use std::collections::HashSet;

fn main() {
    let text = "rust rust ai infra rust ai";
    let mut seen_words = HashSet::new();

    for word in text.split_whitespace() {
        seen_words.insert(word);
    }

    println!("seen_words = {:?}", seen_words);
    println!("contains rust? {}", seen_words.contains("rust"));
    println!("contains python? {}", seen_words.contains("python"));
}

HashSet 关心：

某个值是否出现过。

不关心出现了几次。

例如：

rust rust ai infra rust ai

放进 HashSet 后只剩唯一值：

{"rust", "ai", "infra"}

同样，HashSet 也不保证打印顺序。

13. 用 HashSet 找重复项

use std::collections::HashSet;

fn main() {
    let names = vec!["Alice", "Bob", "Alice", "Carol", "Bob", "David"];
    let mut seen = HashSet::new();
    let mut duplicates = HashSet::new();

    for name in names {
        if !seen.insert(name) {
            duplicates.insert(name);
        }
    }

    println!("duplicates = {:?}", duplicates);
}

关键是：

#![allow(unused)]
fn main() {
seen.insert(name)
}

返回：

#![allow(unused)]
fn main() {
bool
}

含义：

true  -> 这个值原来不存在，这次成功插入
false -> 这个值原来已经存在，没有再次插入

所以：

#![allow(unused)]
fn main() {
if !seen.insert(name) {
    duplicates.insert(name);
}
}

意思是：

如果 name 之前已经出现过，就把它加入 duplicates。

Day 10 的核心地图：

概念关键点
HashMap<K, V>key-value 映射
HashSet<T>唯一值集合
HashMap::new()创建空 map
insert插入新值；key 已存在时覆盖旧值

get_mut查询并可变借用 value，返回 Option<&mut V>

HashMap<String, V>map 拥有 key

get("Alice")HashMap<String, V> 通常可用 &str 查询

更 Rust 的总结：

HashMap 拥有自己的 key/value；get 借用 value；entry/or_insert 返回内部 value 的可变引用，因此可以原地更新。

        }

        self.score

    }

4.1 pub struct Student

#![allow(unused)]
fn main() {
pub struct Student
}

表示 Student 这个类型可以被其他模块使用。

如果写成：

struct Student { ... }

那么 parser.rs、stats.rs、report.rs 这些兄弟模块就不能使用 Student。

Rust 默认是 private。想让模块外访问，必须显式写 pub。

4.2 struct 是 pub，字段不会自动 pub

#![allow(unused)]
fn main() {
pub struct Student {
    pub name: String,
    score: i32,
}
}

含义是：

Student 类型是 public。
name 字段是 public。
score 字段是 private。

所以其他模块可以写：

student.name

但不能直接写：

student.score

因为 score 字段没有 pub。

不过外部可以通过公开方法读取：

#![allow(unused)]
fn main() {
pub fn score(&self) -> i32 {
    self.score
}
}

这就是封装：

字段不直接公开；
通过公开方法控制访问。

5. parser.rs：模块间引用与 crate::

src/parser.rs：

#![allow(unused)]
fn main() {
use crate::student::Student;

pub fn parse_student(line: &str) -> Result<Student, String> {
    let (name, score_text) = line
        .split_once(',')
        .ok_or_else(|| format!("missing comma in line: {line:?}"))?;

    let name = name.trim();
    if name.is_empty() {
        return Err(format!("missing student name in line: {line:?}"));
    }

    let score = score_text
        .trim()
        .parse::<i32>()
        .map_err(|error| format!("invalid score in line {line:?}: {error}"))?;

    Ok(Student::new(name, score))
}

pub fn parse_students(text: &str) -> Result<Vec<Student>, String> {
    let mut students = Vec::new();

    for (index, line) in text.lines().enumerate() {
        let trimmed = line.trim();

        if trimmed.is_empty() {
            continue;
        }

        let student = parse_student(trimmed)
            .map_err(|error| format!("line {}: {error}", index + 1))?;

        students.push(student);
    }

    Ok(students)
}
}

这一句：

#![allow(unused)]
fn main() {
use crate::student::Student;
}

表示：

从当前 crate 的根开始找 student::Student。

如果不写 use，也可以在函数签名里写完整路径：

pub fn parse_student(line: &str) -> Result<crate::student::Student, String> {
    // ...
}

但这会很啰嗦。所以常用 use 把路径引入当前作用域。

#![allow(unused)]
fn main() {
use std::collections::HashMap;

use crate::student::Student;

pub fn average_score(students: &[Student]) -> Option<f64> {
    if students.is_empty() {
        return None;
    }

    let total: i32 = students.iter().map(|student| student.score()).sum();
    Some(total as f64 / students.len() as f64)
}

pub fn passing_names(students: &[Student]) -> Vec<String> {
    students
        .iter()
        .filter(|student| student.is_passing())
        .map(|student| student.name.clone())
        .collect()
}

pub fn score_map(students: &[Student]) -> HashMap<String, i32> {
    let mut scores = HashMap::new();

    for student in students {
        scores.insert(student.name.clone(), student.score());
    }

    scores
}

        assert_eq!(average_score(&students), None);

    #[test]

        let students = vec![Student::new("Alice", 80), Student::new("Bob", 100)];

        let students = vec![Student::new("Alice", 95), Student::new("David", 52)];

}
}

└── tests

18. 常见问题小结

18.1 删除 mod parser; 会怎样？

如果父模块不声明 mod parser;，Rust 就不会把 parser.rs 加入模块树。即使文件存在，crate::parser 也不存在。

18.2 删除 pub struct Student 会怎样？

Student 会变成只在 student 模块内部可见。兄弟模块无法使用 crate::student::Student。

18.3 为什么 score 字段不是 pub，但能通过 score() 读取？

因为字段 private，但方法 public。方法定义在同一模块内部，可以访问 private 字段；外部只能调用 public 方法。

18.4 crate::student::Student 和 super::* 区别是什么？

crate:: 从当前 crate 根部开始找。
super:: 从当前模块的父模块开始找。

use super::* 常用于测试子模块，把父模块里的可见项引入测试模块。

18.5 为什么 #[cfg(test)] mod tests 不影响 cargo run？

因为 #[cfg(test)] 表示这段代码只在 cargo test 时编译。

概念关键点
mod声明模块，把文件挂到模块树上
pub控制外部可见性
