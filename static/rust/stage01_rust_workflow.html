阶段复盘 01 - Rust 最小写作与运行流程

日期：2026-05-14

目标

学完 Day 1 到 Day 5 后，已经接触了不少 Rust 语言概念：

  • 变量、类型、String、Vec
  • 所有权、借用、slice
  • 函数、控制流、match、Option
  • iterator、map、filter、collect

但“看懂代码”和“自己写并运行代码”是两种能力。

本阶段笔记专门解决一个问题：

如何写一个最小 Rust 程序，并在终端里正确运行它。

重点包括：

  • fn main() 是什么
  • Cargo 默认运行哪个文件
  • 多个 .rs 文件怎么组织
  • cargo run、cargo check、cargo run --bin xxx、rustc 怎么用
  • 初学阶段推荐的练习目录结构

1. Rust 程序的最小单位

最小 Rust 程序：

fn main() {
    println!("hello rust");
}

main 是程序入口。

当运行一个二进制 Rust 程序时，Rust 会从：

fn main()

开始执行。

main 默认返回：

#![allow(unused)]
fn main() {
()
}

也就是 unit，可以理解成“没有有意义的返回值”。

所以这个写法是正常的：

fn main() {
    println!("hello rust");
}

也可以显式写成：

fn main() -> () {
    println!("hello rust");
}

但通常不写 -> ()。

2. Cargo 默认运行 src/main.rs

一个最小 Cargo 项目通常长这样：

my_project/
  Cargo.toml
  src/
    main.rs

进入项目目录：

cd my_project

运行：

cargo run

Cargo 默认会运行：

src/main.rs

所以如果你写的是：

src/main.rs

那么命令就是：

cargo run

检查是否能编译但不真正运行：

cargo check

常用习惯：

cargo check  用来快速看有没有编译错误
cargo run    用来编译并运行程序

3. 为什么 src/case1.rs 不会被 cargo run 运行？

假设目录是：

my_project/
  Cargo.toml
  src/
    main.rs
    case1.rs

你运行：

cargo run

Cargo 只会运行：

src/main.rs

不会自动运行：

src/case1.rs

因为 src/case1.rs 在 Cargo 看来只是一个普通源码文件。

如果你想让它成为模块，需要在 main.rs 里写：

#![allow(unused)]
fn main() {
mod case1;
}

但模块文件通常不写自己的 fn main()。

所以初学阶段不推荐这样放可运行小程序：

src/case1.rs

更推荐使用：

src/bin/case1.rs

4. 多个可运行 .rs 文件：推荐用 src/bin/

如果你想在一个项目里写多个可运行练习，推荐目录结构：

my_project/
  Cargo.toml
  src/
    main.rs
    bin/
      case1.rs
      case2.rs
      parse_words.rs

每个 src/bin/*.rs 都可以有自己的：

fn main() {
    ...
}

运行方式：

cargo run --bin case1
cargo run --bin case2
cargo run --bin parse_words

注意：命令里不写 .rs 后缀。

例如文件是：

src/bin/parse_words.rs

运行：

cargo run --bin parse_words

检查：

cargo check --bin parse_words

5. examples/ 目录

另一种组织方式是：

my_project/
  examples/
    demo.rs

运行：

cargo run --example demo

examples/ 常用于库项目的 API 示例。

当前学习阶段，更推荐：

src/bin/

因为它更适合放多个独立小练习。

6. rustc 单文件运行

如果只是一个非常小的单文件实验，也可以不用 Cargo，直接用 rustc。

例如文件：

src/case1.rs

运行：

rustc src/case1.rs -o case1
./case1

含义：

rustc src/case1.rs -o case1   编译成可执行文件 case1
./case1                       运行这个可执行文件

缺点：

会生成一个二进制文件 case1，需要自己清理。

清理：

rm case1

如果你输出到了 src/case1，就清理：

rm src/case1

初学时，如果已经在 Cargo 项目里，通常更推荐用 src/bin/。

8. 推荐的每日练习结构

从后续 Day 开始，建议每一天的项目使用这种结构：

dayXX_topic/
  Cargo.toml
  src/
    main.rs
    bin/
      case1_basic.rs

      case3_practice.rs

其中：

src/main.rs        当天主实验
src/bin/*.rs       当天手写练习、小作业、错误实验

运行主实验：

cargo run

运行小练习：

cargo run --bin case1_basic
cargo run --bin case2_error
cargo run --bin case3_practice

9. 从零手写一个 Rust 小程序的流程

不要一开始就写复杂链式调用。推荐流程：

1. 写 fn main()
2. 定义一个输入
3. println! 打印输入
4. 用 for 循环拆开
5. 逐步加 parse / match / push
6. 最后再改写成 iterator 链

例如目标：

给定字符串 "10 20 bad -5"，逐个尝试解析成 i32。

第一步：只打印输入。

fn main() {
    let text = "10 20 bad -5";
    println!("text = {}", text);
}

第二步：拆分单词。

fn main() {
    let text = "10 20 bad -5";

    for word in text.split_whitespace() {
        println!("word = {:?}", word);
    }
}

第三步：尝试解析。

fn main() {
    let text = "10 20 bad -5";

    for word in text.split_whitespace() {
        let parsed = word.parse::<i32>();
        println!("word = {:?}, parsed = {:?}", word, parsed);
    }
}

第四步：只收集成功结果。

fn main() {
    let text = "10 20 bad -5";
    let mut numbers = Vec::new();

    for word in text.split_whitespace() {
        match word.parse::<i32>() {
            Ok(value) => numbers.push(value),
            Err(_) => println!("skip invalid word = {:?}", word),
        }
    }

    println!("numbers = {:?}", numbers);
}

第五步：再改写成 iterator 链。

fn main() {
    let text = "10 20 bad -5";

    let numbers: Vec<i32> = text
        .split_whitespace()
        .filter_map(|word| word.parse::<i32>().ok())
        .collect();

    println!("numbers = {:?}", numbers);
}

10. 函数可以写在 main 前，也可以写在 main 后

Rust 不要求函数必须先定义再使用。

这个可以：

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", add(2, 3));
}

这个也可以：

fn main() {
    println!("{}", add(2, 3));
}

fn add(a: i32, b: i32) -> i32 {
    a + b
}

初学阶段推荐：

辅助函数写在前面，main 写在最后。

这样读起来比较顺。

11. 多个文件时，先区分“模块”和“可运行程序”

这是初学者最容易混的地方。

可运行程序

文件：

src/bin/case1.rs

里面可以有：

fn main() {
    println!("case1");
}

运行：

cargo run --bin case1

模块

文件：

src/case1.rs

通常写函数，不写 main：

#![allow(unused)]
fn main() {
pub fn hello() {
    println!("hello from case1 module");
}
}

在 main.rs 中引用：

mod case1;

fn main() {
    case1::hello();
}

运行：

cargo run

当前阶段如果你只是想做多个独立练习，优先用：

src/bin/*.rs

不要先引入模块系统。

12. 建议后续学习节奏

后续 Day 正常学习新内容，但每隔几天补一次“写代码训练”：

概念学习：Day 6、Day 7、Day 8 ...
阶段训练：如何写小程序、如何读报错、如何拆任务、如何组织文件

每个阶段训练都遵循：

小目标 -> 你手写 -> 你运行 -> 贴报错 -> 修正 -> 总结命令和模式

阶段总结

当前最重要的运行规则：

cargo run                     运行 src/main.rs
cargo run --bin case1          运行 src/bin/case1.rs
cargo run --example demo       运行 examples/demo.rs
rustc file.rs -o demo && ./demo 单文件临时运行

当前最推荐的练习结构：

src/main.rs          当天主实验
src/bin/case1.rs     第一个手写练习
src/bin/case2.rs     第二个手写练习

一句话总结：

先学会写一个最小 fn main()，再学会把多个 main 放进 src/bin/，最后再学模块系统。
